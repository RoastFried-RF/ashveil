# ASHVEIL character motion

캐릭터/생물 원화, 걷기 속도, 무기 부착 또는 행동 전환을 바꿀 때 사용한다. 저장소에서 관리하는 제작 스킬이며 외부 공식 스킬이나 이미지 생성 모델 자체가 아니다. 사용자의 범위와 검사 우선순위가 이 절차보다 우선한다. 기존 [게임 개발 스킬](../ashveil-game-development/SKILL.md)과 함께 적용한다.

1. `CLAUDE.md`, `docs/CANON.md`, `docs/motion-v323.md`, 수정 대상 renderer/Def/원본의 provenance를 읽는다. 머리 수·사지·복장·방향·손·무기 크기와 실제 행동/지속 활동을 조사한다. 과거 프레임 수를 완성된 동작 수로 간주하지 않는다.
2. `node --import tsx tools/art/motion-workbench.ts --output test-results/새이름`으로 실제 활성 물품/캐릭터의 동작·손잡이·보행 등록을 조사한다. 각 모델의4방향과 모든 무기 스타일을 포함한다. 사람, 네발짐승, 기계, 기어가는 몸의 주기를 구분한다.
3. 시간과 거리를 먼저 정한다. `walk-motion.ts`의 한 칸, `gait`의 두 발 한 주기, 키 반복/자동 이동, backlog 따라잡기 상한을 함께 확인한다. 프레임 수만 늘리고 전체 주기를 짧게 두지 않는다. 한 걸음·두 걸음·긴 직선·대각선·급회전·정지·웅크림·부상·0/.5/1/2배를 고려하고 게임 TU와 표현 시간을 구분한다.
4. 무기는 실제 `meleeWield/wield`가 선택한 물품·팔·공격 방식을 따른다. 칼의 베기/찌르기, 도끼·망치의 무게, 장병기의 찌르기/보조 손, 양손검, 방패·받아넘김, 활의 시위, 석궁과 총의 실제 발사/장전, 투척·맨손·횃불·등불까지 매핑한다. 손잡이의 앵커와 그림의 원래 방향, 크기, 앞/뒤 가림을 먼저 맞춘다. 준비→접촉의 짧은 유지→후속 동작→회복을 만들고 피격·이동·장비 교체·중단·사망을 처리한다. 같은 입력이라도 빈 무기/불발을 발사로 꾸미지 않는다.
5. 새 픽셀이 필요할 때는 제공된 이미지 생성 도구를 사용한다. 자체 원화만 일관성 입력으로 주고 타 게임 픽셀을 복사/트레이싱하지 않는다. 먼저 해당 원화를 직접 본다. 한 작업에 하나의 명확한 행/열 배치를 쓰고, 가능한 한 한 행에 한 방향만 둔다. 투명한 간격·고정 머리 크기·빈 손/실제 장비 레이어 분리를 지정한다. 겹침·방향 혼합·잘림·추가 사지·실제 무기와 모순되는 원화는 다시 만든다.
6. 생성 PNG는 원본 바이트로 보존하고 SHA-256·입력·정확한 프롬프트·실패/대체 이유를 기록한다. Python/Pillow는 알파·영역·기준점·유사도 등 읽기 전용 분석에만 쓴다. 픽셀 수정·리샘플링 결과를 원본이라고 기록하지 않는다. 모델·프레임키·고유 원본 영역·반전 공유·역순 재사용을 구분한다. 배율로 잘림이나 잘못된 방향을 숨기지 않는다.
7. 기존 v322 원화를 재등록했다면 `python3 tools/art/direction-v323/apply-rigs.py`로 현재 cadence도 적용한다. `node --import tsx tools/art/export-public-artbook.ts`와 `node --import tsx tools/art/export-motion-comparison.ts`로 도감을 내보낸다. 비교 페이지는 게임과 같은 `equipment-motion.ts`를 사용하고, 이전 주기와 현재 주기를 별도로 재생한다. 원화 표·선택 프레임·동영상/연속 캡처를 실제로 열어 손에 잡힌 무기와 발의 교대를 본다.
8. `node --import tsx tools/validate-sprites.ts`, 타입/대상 린트와 변경에 필요한 짧은 검사를 실행한다. 빌드 뒤 `tools/inspect-movement-v316.ts` 및 해당 revision의 무기 실제 입력 도구를 고유 출력 경로로 실행한다. 유한 초기 각인은 허용하되 불러온 뒤 세계/난수/장비를 API로 조작해서 성공처럼 만들지 않는다. 공개 player 관찰 정보와 실제 PNG를 대조한다. 머리·손·발의 위치나 검사 실패를 발견하면 먼저 수정한다.
9. 사용자가 전체 회귀를 후속으로 지시했다면 Full/World/1,000판을 시작하지 않는다. 실행한 것과 보지 않은 것, 고유 원화 수와 공유 포즈, 미완성 장비/몸 변형을 기록한다. 큰 묶음을 동결하고 그 바이트를 게시하며 배포 후 버전/선택 공개 파일 해시를 확인한다. 게시 기록만을 위한 작은 추가 push는 하지 않는다.

반복 가능한 부분은 조사·등록·카탈로그·도구로 자동화한다. 생성된 이미지의 의미적 방향, 정확한 손 위치와 움직임의 자연스러움은 사람이 화면을 보고 판단해야 한다. 알파 분리나 테스트 통과를 시각 품질 보증으로 취급하지 않는다.

## 사족 동물·공격 변형에서 얻은 절차

- 12칸을 생성했다는 사실로 12프레임 보행을 수락하지 않는다. LF/RF/LH/RH의 실제 소유, 회복→접지와 나머지 지지발을 프레임마다 기록한다. 행 중간에 반대 방향이 되거나 두 뒷발이 함께 들리는 후보는 별도로 보류한다. 고유한 4자세와 실패한12후보를 더해 밀도 완료로 세지 않는다.
- 몸이 연결되지 않아도 두 실루엣의 직사각형 영역이 겹칠 수 있다. 여백0에서도 이웃 그림이 들어오면 그 방향의 clip 전체를 보류한다. 배율·마스크·리샘플링으로 감추지 않는다. 실패 원인을 직접 본 뒤 필요한 방향만 적은 칸/넓은 간격의 별도 묶음으로 보완하며, 원문과 실패를 유지하고 요청 횟수를 기록한다.
- 실제 공격 event의 mode를 저장해 자연 공격 `attackVariants` 원문을 선택한다. 이벤트를 소비할 때 나중의 공격 선택을 추측하지 않는다. 원본 선택 로더·검증기·도감에도 변형 clip을 포함한다. 앞발/턱의 실제 기능과 손 소유를 구분하고, 기상 중 피격이 정지 자세로 갑자기 바뀌지 않는지 실제 입력에서 본다.
- 설치 기록은 역사적 staging의 `active:false`를 바꿔 수락한 것처럼 만들지 않는다. 선택한 원문 SHA/사각형/기부·런타임 배율·고유 영역 수와 Native 검토를 부모 설치 기록에 별도로 남긴다. [등록 예](../../../tools/art/install-bear-v348.py), [실제 입력 예](../../../tools/inspect-bear-v348.ts).

## 분리 원화로 만드는 기계 관절

- 전체 보행 후보가 같은 발을 반복하면 실패 원문을 유지하고, 한 방향의 분리 차체/고정 길이 upper/lower/foot로 효율을 검토할 수 있다. 보이는 금속 안쪽 핀과 추정/가려진 힙을 분리하고, 기울어진 source축 두 끝을 실제 투영 관절에 맞춘다. 원화4부품을4다리에 공유해도 authored 보행16프레임이 되지 않는다.
- 거리 기반 회복과 지지발 world anchor를 사용한다. 이동 전후의 contact발 좌표, 정지 후 회복 완료/재출발, 급한 방향 전환, 링크 도달 오류를 실제 DOM과 읽기 전용 관찰로 확인한다. 긴 프레임은 분할하며 지도 변경/순간 이동에는 새 소유자를 만든다.
- 지지점의 각도 정렬은 내부 점 때문에 오목 다각형이 될 수 있다. 실제 convex hull의 여유를 보고하고, 지지 중에 몸을 먼저 이동한 다음 발을 든다. 가정한 무게중심의 투영 지지 여유가 양수인 것과 실제 동역학/사람 품질 승인을 구분한다.
- 원화의 하이라이트는 파츠 회전과 함께 돈다. 미제작 밑면/반대 면이나 고정 lower를 늘린 것을 새 원화·진짜 피스톤 stroke라고 기록하지 않는다. 먼저 격리 시제품에서 source4영역과한계를 보인 뒤 실제 Core행동/전 방향/손상 모델과 연결한다. 예: `tools/art/export-sower-rig-v356.ts`, `tools/inspect-sower-rig-v356.ts`.


## 여러 체절·많은 다리의 원화 비용 제어

- 각 원문의 머리와 몸판/꼬리판을 분리해 번호를 관찰하고, 원래 Body 부위 수와 비교한다. 같은4포즈에서 몸판8/9가 바뀌거나 턱보조지/보행 다리 소유가 불명확하면 생성 요청의 숫자로 수락하지 않는다. 넓은 여백·크롭 무손실은 모델의 해부 일치나 교대 지지를 증명하지 않는다.
- 같은 문제의 whole-walk 후보를 계속 늘리기 전에 분리된 머리·단일 몸판·다리·꼬리 원화와 런타임 연결 방식을 검토한다. 실제로 제작/관찰하지 않은 부품은 제안으로만 남기며 원본을 임의 잘라 새 고유 부품이라고 세지 않는다. 고정 길이/겹침/가림/손상 몸의 소유와 방향별 원문 면을 먼저 해결한다.
- 군체의 느슨함·밀집·이동·흩어짐은 상태 영역이며4보행 프레임이나 실제 개체수/체력으로 환산하지 않는다. 원본 alpha1 잔상·alpha16 몸·경계/이웃 침범을 나누어 보고하고 배경을 자체 편집해 원본으로 바꾸지 않는다.
- 격리 후보의 출시 수락과 실제 Core/지도/저장/선택 로딩/공개 도감의 등록을 분리한다. 부모가 실제 활성과 입력을 확인하기 전 staging 제작 완료를 게임 전체 구현 완료로 쓰지 않는다.
