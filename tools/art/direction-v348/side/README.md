# v342 잿곰 누락 보행 — bounded 1차 원화 제안

2026-10-24. **`activationReady:false`**. 변경 범위는 이 staging뿐이며 v334/v339와 메인 src/public/docs/dist는 보존했다. 이번 제안은 누락된 좌·우·뒤 각4개, 총12개 기본 위상을 목표로 생성했고, **좌·우 8개만 부분 등록 제안**, 뒤4개는 보류다. 각 방향4자세를 일반 제작 계약의 **방향당12프레임 밀도나 출시 수락으로 세지 않는다.** runtime CharDef/Creature/스폰은 만들지 않았다.

## 먼저 실제로 읽고 연 원문

캐릭터 동작 스킬, `docs/lore/bestiary.md` §6, draft `Body.CinderBear` 전체와 `Creature.CinderBear`, v334 README 실패 기록을 대조했다. 잿곰은 draft **340kg**, `quadruped`, 앞다리/발 각각2개와 뒷다리/발 각각2개이며 작은 꼬리가 따로 있다. lore는280–400kg, 이동90TU/돌진50TU를 적고 draft Creature의 현재 moveTU는100이다. 이 기존 차이를 원화 배율·재생주기로 해결하거나 Core 변경으로 주장하지 않았다.

v334 **idle/swipe-v2/bite-v3/front-walk 원본4개와 실패한 left/right/up 2×2 원본3개를 전부 다시 직접 열었다**. 기존 실패는 같은 지지/통과 앞발을 A/B에서 반복하거나 뒤 통과 둘 다 같은 뒷발바닥을 보여 주는 문제였다. 좌우 실패 후보의 갈색 미리보기는 이미 alpha=0으로 판명된 것이므로 알파 실패로 재분류하지 않았다.

이번에는 반복되는 contact/passing 문구 대신 **왼뒤 회복 → 왼앞 회복 → 오른뒤 회복 → 오른앞 회복**의 느린4박자를 제안했다. 한 발만 짧게 들고 다른3발이 하중을 받도록 요청했다. 입력은 직접 본 자체 v334 idle과 bite-v3뿐이며, 늑대 확대·타 게임 픽셀·외부 이미지·트레이싱을 쓰지 않았다.

## 의미·지지·가림 검토

새 좌우는 낮고 넓은 곰 몸통, 큰 어깨/엉덩이, 작은 둥근 귀, 짧은 꼬리, 짧고 넓은 주둥이, 목이 어깨선보다 낮은 자세를 유지한다. 몸의 비율은 프레임마다 대략 고정되고 반대쪽 다리의 접지/회복이 구분된다. 새 늑대·개 몸체, 추가 다리, 사람 손·도구·무기, 직립 자세·idle 복제는 등록하지 않았다.

`paw-review.json`은 직접 본 **해부학적 LF/RF/LH/RH**와 원본 시트 안의 대략적인 보이는 발 중심, 접지/회복 상태를 기록한다. 발 중심은 표시 진단용 수동점이며 정확한 히트박스·Core 접촉·발 그립 자료가 아니다. 지지 여부는 점 위치만으로 정하지 않고 발바닥 들림/발목 굽힘/몸 아래 연결과 다른 발의 접지를 함께 봤다. 먼 다리 일부가 털/몸통에 가려지는 것은 그대로 기록했고, 다리의 모든 길이가 모든 프레임에서 독립적으로 보인다고 주장하지 않는다.

뒤는 실제 뒷발 교대가 개선됐지만 **앞발 소유를 확인하지 못했다**. `LF/RF.sourcePoint`는 null, 상태는 `ownership-unconfirmed`이며 보이는 중앙 앞발은 `unknownFore`로만 기록했다. raw1/raw3의 발바닥 좌우 위치가 조금 다르다는 이유로 해부학적 반대발이라고 추정하여 수락하지 않았다. 몸에 가려진 다른 앞발의 지지도 확인하지 못했으므로3발 지지 통과를 주장하지 않는다. 뒤의 앞 얼굴·늑대 꼬리·새 다리 생성은 없지만 그것만으로 실제 사족 보행을 통과시키지 않았다.

## crop·기부·배율·주기 계약

- `sprites.fragment.json`: 새 좌우 PNG2개와 **8개 frame만**. `chars`는 비어 있다. 원문 설치 대상은 `sprites/original/direction-v342/`이며 부모가 수락한 경우만 원문 바이트 그대로 복사한다.
- `cinder-bear.walk.partial.json`: `av331_cinder_bear`를 위한 좌우 clip/변환 제안이며 runtime CharDef가 아니다. 우향 key0/1/2/3은 source raw2/1/0/3이다. 기존 v334 앞4자세/idle/swipe/bite와 깊게 합치는 여부는 부모의 후속이다.
- `candidate-crops.json`: 보류 뒤4개까지 **후보12개**의 실제 원본 직사각형·크롭 SHA·가상기부·표시 변환. 뒤4개는 실제 sprite registry에 넣지 않았다.
- `foot-anchors.json`: 등록 제안8개의 원본 시트·크롭 안 **몸의 지면 투영 기부점**. 개별 발의 실제 접촉 픽셀이나 가려진 발 접촉을 주장하는 점이 아니다.

원본 crop은 `[sheet,x,y,width,height]`이고 실제 연결 영역을 사용했다. 요청한1280/균등 셀 크기를 가정하지 않았다. 표시 오프셋은 `(sourcePixel - cropSize * anchor) * scale`이다. 좌우 원화는 높은 원문 해상도를 기존 idle과 대략 맞추기 위해 **.075**를 제안했고, 보류 뒤는 후보 진단에서만 .085다. 그림 자체의 몸 크기 변경이나 배율로 다리/방향 실패를 숨기는 수정은 하지 않았다. 새 측면은 기존 idle보다 목이 더 낮고 상체/털 모양에 차이가 있으며, 기존 front-walk도 원래 모델 일치 미수락이므로 통일된 최종 몸체라고 주장하지 않는다.

제안4박자 주기는 **1400ms, 자세당350ms**이며 실제 게임에 적용하지 않았다. `playback-contract.json`에서 Core 이동TU/이동 거리와 분리했다. 짧은4자세에 긴 주기를 주는 것만으로 매끄러운12프레임 밀도가 되지 않는다. 이동 거리/발 미끄러짐/힘 전달/실제 속도·상태 전환은 미수락이다.

## 읽기 전용 표시 확인과 남은 최소 다음 단계

새 원본3개, 중립 배경의 발/가림 주석 합성3장, 우·뒤 발 하단 진단2장, 실제 crop/anchor/scale와 이전 idle의 **native×1/표시×4 합성2장**을 직접 열었다. `diagnostics/`는 원화 픽셀을 수정한 배포 자산이 아니라 명시된 표시 진단이다. Pillow/NumPy/SciPy는 원문 읽기·알파/영역/범위/해시와 진단 합성만 만들었다.

등록 제안8/8이 원본 경계 안이고 RGBA crop SHA8개는 전부 다르다. 다른 alpha≥16·면적≥400 실루엣 픽셀 혼입은0, 원문3개의 alpha≥16 캔버스 가장자리 픽셀도0이다. 이 분석은 다리/방향 판단을 대신하지 않는다. 프로젝트나 게임을 열어 수행한 테스트·실제 이동 검증은0회다.

이번에는 추가 생성하지 않는다. 최소 다음 대안은 **뒤 한 방향의 LF/RF 회복을 각각 분리한 자체 해부 구조/포즈 가이드**로 어깨→앞발 경로를 먼저 드러내 검토한 뒤 향후 새 image_gen 요청을 정하는 것이다. 다른 방향 확대나 같은 whole-sheet 무한 재시도로 해결했다고 세지 않는다. 뒤를 반전/역순/idle로 채우지 않고 잿곰은 비활성 상태로 둔다.

남은 범위는 뒤 앞발 소유 확정, 이전 앞walk와 이번 좌우의 동일 모델감, 실제 이동/거리/주기/하중·발 미끄러짐, 방향당 고밀도 동작과 다른 몸 상태/초상/손상 마스크, Core 행동 및 부모의 실제 통합·출시 수락이다. 메인·기존 staging 수정, 빌드/테스트/World/브라우저/commit/push는 하지 않았다.
