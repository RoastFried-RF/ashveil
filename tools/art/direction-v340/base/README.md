# v335 파종기·측량기·구제기 원화 staging

제작·원본·합성 대조: 2026-10-24. **전 종 `activationReady:false`**다. 부모의 AI/실제 행동/피해 부위 연결과 게임 장면 검토 전에는 이 자료로 생물을 활성화하지 않는다. v334 및 그 이전 확정 자료는 변경하지 않았다.

새 픽셀은 모두 `image_gen.imagegen`으로 만들었다. 타 게임 픽셀을 복사/트레이싱하지 않았다. 기존 자체 v322 `drone-locomotion-front-left.png`, `drone-active-front-left.png`는 직접 열어 재질·시점 참고만 했고 생성 입력으로 주거나 다른 종 이름으로 재등록하지 않았다. 이후 이미지 입력은 이 staging에서 만든 자체 원본만 사용했다.

## 실제 Body와 먼저 대조한 구조

`docs/lore/bestiary.md` §11–13, `tools/content-plans/expanded-creatures-v331/art-direction.md`, 캐릭터 동작/게임 개발 스킬, draft Body/Creature 원문을 읽었다. `structure-contract.json`에 조사 시점 원문과 SHA-256을 고정했다.

| 종 | draft Body의 실제 구조 | 원화의 구분 |
| --- | --- | --- |
| 파종기 | DriveLeg1–4, ManipulatorL/R, ToolHead, SensorMast | **4 구동 다리**, 서로 다른 종자/정착균 탱크 2개, 아래 파종구, 짧은 토양 광학부. 작은 접힌 보정 매니퓰레이터를 추가 다리나 무기로 세지 않음 |
| 측량기 | DriveLeg1–3, **별도 Antenna**(detach, signal), SensorMast, 작은 보정 도구 | **3발 tripod**, 앞 렌즈와 별도 긴 얇은 안테나. Creature에 자연 공격이 없으므로 총·칼·근접 공격을 만들지 않음 |
| 구제기 | DriveLeg1–6, ManipulatorL/R, ToolHead(rarm), SensorMast | **6 구동 다리 + 별도 낫팔 2개**. 전방 센서·닫힌 포획망 하우징·정화액 탱크, 후면 냉각 덮개. 낫팔은 소지품 무기가 아닌 고유 도구 |

세 Body의 `Core`, `PowerCell`, `CoolingLoop`는 모두 internal이다. 외부에는 닫힌 서비스 해치·수동 냉각 덮개/배관만 두고, 코어를 영구 발광 노출하는 부품이나 실제 광원을 추가하지 않았다. 그림의 탱크/패널이 독립적으로 조준 가능한 새 Body 부위가 됐다는 뜻은 아니다. 절단/손상에 따라 원화 부품을 제거하는 마스크도 아직 없다.

## 채택한 실제 범위

| 모델 | idle | walk | work | 합계 |
| --- | ---: | ---: | ---: | ---: |
| 측량기 | 4방향×4 =16 | 4방향×4 =16 | 관찰/보고 자세 4방향×4 =16 | **48** |
| 파종기 | 4방향×4 =16 | 앞·뒤만 각4 =8, 좌·우 보류 | 파종구 개폐 자세 4방향×4 =16 | **40** |
| 구제기 | 4방향×4 =16 | 전 방향 보류 | 활성 팔 불일치로 전 방향 절단 보류 | **16** |
| 합계 | **48** | **24** | **32** | **104** |

요청한 3종의 idle은 각각 4방향·4개 원본을 준비했다. 종 구조를 대조한 뒤 후속 walk/work를 만들었고 실패한 보행은 방향별 2×2로 한 번 분리했다. 재시도 뒤에도 반대 지지발/세 발 tripod 위상이 확정되지 않는 후보는 성공으로 세지 않았다.

생성 PNG는 **19개 원문 모두 보존**, 채택 PNG는 **8개**, 실제 등록 크롭은 **104개**다. 후보 셀은 208개지만 실패·대체판을 새 완성 동작으로 더하지 않는다. 미채택 셀도 104개다. 최종 104개 크롭의 원본 픽셀 해시는 모두 서로 다르며, 같은 소스 영역 복사·반전 공유·역순 포즈로 새 프레임 수를 부풀리지 않았다. 표시 반전 보정은 아래의 **5프레임**에만 있다.

일반 제작 계약의 walk12/attack8 또는 모든 상태/초상을 완성한 것은 아니다. 새 초상은 0개다. 측량기의 관찰/보고 `work`는 공격 clip이 아니다. 파종기의 `work`도 실제 재고와 무관한 고정 캡슐·식물·균 구름을 그려 넣지 않고 기계 자세만 포함한다. 유한 8캡슐 재고·배출·월드 객체 생성은 부모 구현이 정해야 한다.

## 등록·지면 기준 계약

- `sprites.fragment.json`: `sheets`, `sheetSizes`, `frames`, `chars` 병합 조각. 준비된 유일한 CharDef는 **`av331_surveyor`**다. idle/walk와 `motions.work`가 있으며 `attack`을 만들지 않았다. CharDef가 존재해도 activationReady는 false다.
- `partial-models.json`: 파종기 40개·구제기 16개의 clip/프레임 변환과 미완성 방향. 두 모델의 runtime CharDef는 만들지 않았다. 누락 방향을 idle·반전 재사용 등으로 채우지 않는다.
- `activation-contract.json`: 전 종 false와 AI/동작/게임 장면 후속. 이 조각은 Creature Def/스폰/전투 정책을 활성화하지 않는다.
- `foot-anchors.json`: 원본 **시트 좌표와 크롭 좌표**로 고른 기계 지면 투영점. 가려진 발의 실제 접촉 픽셀을 알아냈다고 주장하는 자료가 아니다. 특히 들어 올린 발/낫 끝/파종구 끝을 지면 기준으로 오인하지 않는다.
- `occlusion-notes.json`: 먼 다리/작은 도구의 가림 범위. 구제기 뒷면에는 6개 발판이 구분되지만 정면에서는 4개가 뚜렷하고 먼 한 쌍은 몸체에 가린다. 검사한 측면 예에서는 5개와 가려진 먼 발이 구분된다. 모든 프레임에 6발판이 독립적으로 보인다고 주장하지 않으며, 낫날/아래 원통을 빠진 발로 세지 않는다.

등록 frame은 `[sheet,x,y,width,height]`의 **원본 픽셀 직사각형**이다. PNG가 실제로 1254px 또는 그 밖의 크기로 반환됐으므로 요청한 1024px/균등 셀을 가정하지 않았다. `frameTransforms.anchor`는 해당 크롭 내부 지면 투영점을 크롭 너비·높이로 나눈 값이다. 표시 오프셋은 `(pixel - cropSize * anchor) * scale`이며 `flipX` 때 x를 반전한다. 크롭/원본 좌표 자체는 뒤집지 않는다.

측량기 배율 .13, 파종기 idle/work .23, 파종기 별도 고해상도 앞뒤 walk .115, 구제기 idle .16으로 staging에서 대략의 몸 크기를 맞췄다. 배율로 잘림이나 잘못된 다리 위상을 숨기지 않았다. 실제 게임의 상대 크기·시간/이동 거리·지면/가림 검토는 후속이다. 측량기 gait900ms도 표현 제안이며 TU/AI 속도를 바꾸지 않는다.

원본 설치 대상 URL은 `sprites/original/direction-v335/<원문파일명>`으로 준비했다. 부모 통합에서 **채택된 8PNG 원문 바이트만** 실제 public 경로로 복사하고 조각을 병합하면 된다. 이 작업에서는 메인에 복사하지 않았다.

## 실제 방향·반전 보정

| 원본 | 실제 원본 행 순서 | 등록 보정 |
| --- | --- | --- |
| surveyor idle/walk/work, sower idle-v2 | 앞 / 좌 / 우 / 뒤 | 실제 방향 그대로 |
| sower work-v1 | **뒤 / 좌 / 우 / 앞** | 실제 전면 광학부와 후면 벤트를 보고 행을 매핑. **뒤 4개만 flipX**로 탱크 장착 면을 idle과 맞춤. 앞 원본은 이미 일치하므로 반전하지 않음 |
| culler idle-v2 | **뒤 / 좌 / 우 / 앞** | 센서/후면 벤트로 행을 매핑. **뒤3 한 프레임만 flipX**로 탱크 면을 다른 뒤 프레임과 맞춤 |
| sower walk down/up-v2 | 각각 단일 방향 2×2 | 원본 읽는 순서 좌상→우상→좌하→우하 |

이 5개의 표시 반전은 같은 원본을 여러 새 포즈로 재사용한 것이 아니다. 각 원본 영역은 한 프레임에만 쓰며, 원본 PNG는 고치지 않았다. 합성 확인 도중 앞/뒤 work를 모두 뒤집던 초안을 바로잡아 **파종기 앞 work에는 반전이 없다**. 최종 합성에서 탱크 장착 면을 다시 대조했다.

## 읽기 전용 원본 분석과 합성 범위

`originals/`는 도구 출력과 **전부 바이트가 같은 19PNG**다. Pillow/NumPy/SciPy는 알파/연결 영역/크롭 범위/원본 해시와 **명시된 진단 합성**에만 사용했고, 원화 픽셀 수정·배경 제거·리샘플링·재인코딩을 하지 않았다. `analyze-originals.py`의 `/tmp/ashveil-v335-garden-machine-art/` PNG는 읽기 전용 확대/합성 진단이며 새 원화나 배포 자산으로 세지 않는다.

`registration-analysis.json`에서 최종 **104/104 크롭이 원본 내부**이고, alpha≥16·면적≥400의 다른 큰 실루엣이 직사각 크롭에 들어오는 경우는 **0**이다. 낮은 알파의 숨은 RGB와 작은 고립 픽셀은 원문 그대로 남는다. 이 수치만으로 다리수·방향·움직임 통과를 주장하지 않았다.

`index.html`은 실제 원본 crop/anchor/flipX를 사용하는 자체 staging canvas다. 독립 포트 49535에서 메인 게임 없이 열고, 3모델의 프레임0–3을 ×3/×5로 촬영했다. 최종 ×5 합성 12장을 전부 직접 열고 ×3 대표 3장도 열어 발 들림·기계 지면·안테나·탱크 위치·몸 크기와 보류 표시를 대조했다. `diagnostics/`는 **게임 플레이 검증이 아닌 원화 표시 진단**이다. 현재 보행은 제자리 순서 진단이며 실제 이동 거리와 결합한 발 미끄러짐 확인은 하지 않았다.

남은 범위는 파종기 좌우 보행, 구제기 전 보행과 올바른 팔 절단, 세 종의 AI/실제 작업·냉각·포획망·정화/보고·도주 연결, 피격/쓰러짐/수면/기상·손상/안테나 제거 원화와 초상, 실제 게임 장면이다. 프로젝트 빌드/검사·World, 메인 src/public/docs/게임 state/공유dist·preview 수정, commit/push는 하지 않았다.
