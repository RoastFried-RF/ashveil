# v339 측량기 피격·정지·재기동 원화 staging

제작/원본·크롭 표시 대조: 2026-10-24. **`activationReady:false`**. v335 확정 자료와 실패 기록은 변경하지 않았다. 이 폴더는 별도 후속 원화와 병합 제안이며, 출시 수락은 부모의 실제 통합·게임 장면 검토 뒤에만 한다.

## 실제 규칙에서 고른 범위

캐릭터 동작/게임 개발 스킬, 실제 `Body.Surveyor`·`Creature.Surveyor` draft, 기계 Core와 renderer, 확장 동작/정책 계획을 먼저 대조했다. 기존 자체 v335 측량기 **idle/walk/work 원본 3개를 다시 직접 열었다**. 이미지 생성 입력은 그중 자체 idle과 이번 자체 rise뿐이다. 타 게임 픽셀·외부 이미지·트레이싱을 사용하지 않았다. 현재 조사 원문 SHA와 Body/Creature 스냅샷은 `provenance.json`, `scope-contract.json`에 있다.

`src/core/body.ts`의 `mechanicalBodyTick`은 과열/단락의 `shutdownUntil`, 전원, Core 효율로 `unconscious`를 갱신한다. `MapRenderer`는 prone에 fall, 실제 회복에 rise, 서 있는 동안 피해에 hurt를 요청한다. 따라서 **hurt/fall/rise**를 만들었다. `machineCare`는 인접한 실제 정비자·재료·도구가 필요한 activity이며, 파괴된 Core는 수리로 되살리지 못한다. 가짜 손/렌치로 자가수리하는 동작이나 재고 무기·공격을 만들지 않았다.

측량기의 3턴 관찰/보고·별도 Antenna 손상·거리유지/도주·유한 섬광 정책은 여전히 제안 계획이다. 그림이 생겼다고 해당 AI, Creature 스폰, 코어 상태/도구/부위 손상을 활성화하지 않는다.

## 구조·방향·가림의 실제 범위

정체성은 **구동 다리 3개와 별도 긴 얇은 지붕 안테나**다. 앞 중앙 다리 1개와 뒤 양옆 다리 2개가 있는 tripod다. 렌즈 주변 작은 보정 브래킷을 손·추가 다리·무기로 세지 않는다. Core/PowerCell/CoolingLoop는 sealed internal이며, 가짜 영구 발광·노출 동력핵·스파크·신규 장비가 없다.

- hurt는 16개에서 3개 발판/구동 경로와 별도 안테나를 직접 구분했다. 다리를 늘리거나 한 발을 걷듯 이동시키는 새 보행 clip이 아니다.
- fall은 낮아짐에 따라 양옆 다리가 접히고 중심 다리/먼 다리 일부가 머리·섀시 아래로 가려진다. 특히 앞/뒤의 완전 정지 자세와 좌/우 최저 자세에서 **가려진 다리 전체 경로가 독립적으로 보인다고 주장하지 않는다**. 보이는 두 다리를 보고 3개 모두 완전히 확인했다고 세지 않는다. 제거된 다리·떨어진 발·추가 발은 그리지 않았으며, 이 원화에는 실제 다리 파괴/절단 상태 제거 기능이 없다.
- rise의 낮은 단계도 먼 접힌 다리가 섀시에 부분 가려지고, 상승하면서 3개 지지발이 다시 구분된다. 실제 지지 부위 손상과 연결하는 마스크는 미구현이다.
- 4×4 시트는 실제로 앞 / 좌 / 우 / 뒤 순서다. 앞은 전면 렌즈, 뒤는 후면 벤트로 대조했다. 뒤 행에 앞 얼굴이 없다. 교체한 좌/우 fall은 마지막까지 같은 측면 렌즈/패널을 유지한다.
- 반전 `flipX`는 **0개**이고 같은 소스 영역·역순 fall·기존 idle 복제를 신규 프레임으로 등록한 것도 **0개**다. v335 idle 진단 참고 복사본은 신규 원화가 아니다.

## 등록 계약

`sprites.fragment.json`은 `sheets`, `sheetSizes`, `frames`, **부분 `chars.av331_surveyor` 패치**다. 부모가 기존 v335 캐릭터의 **`motions`와 `frameTransforms`에 깊게 병합**해야 한다. 캐릭터 전체를 이 부분 조각으로 대체하면 기존 idle/walk/work가 사라진다. Creature/AI/게임 데이터는 이 폴더에서 수정하지 않았다. 부모가 수락하면 원문 PNG 5개를 `sprites/original/direction-v339/`로 바이트 그대로 복사할 수 있다. 원문 fall-v1은 일부만 쓰더라도 원본 1PNG 그대로 보존한다.

frame은 `[sheet,x,y,width,height]` 원본 픽셀 직사각형이다. 반환 파일은 모두 **1254×1254**이며 요청한 1280/균등 셀 크기를 크롭으로 가정하지 않았다. `source-analysis.json`의 실제 연결 영역과 직접 본 원문으로 크롭을 정했다. 모든 48개 RGBA 크롭 해시는 서로 다르고, 48/48이 원본 내부이며 다른 alpha≥16·면적≥400 실루엣 픽셀 혼입은 **0개**다. 원문 alpha≥16 가장자리 픽셀도 0개다. 이 분석 수치만으로 해부학/동작 통과를 주장하지 않는다.

`foot-anchors.json`은 원본 시트·크롭 좌표의 **기계 지면 투영점**이다. 가장 낮은 지지발판 사이를 기준으로 놓았으며, 가려진 발의 실제 접촉점을 알아낸 자료가 아니다. 정지하며 낮아져도 몸체/렌즈가 지면 기준으로 내려가고 원본 안테나·발이 잘리지 않게 한다. 표시 계산은 `(sourcePixel - cropSize * anchor) * scale`이다.

hurt/앞뒤 fall/rise는 **.13**, 방향별 큰 2×2 fall은 **.06**이다. 배율은 같은 실제 기계 몸 크기를 대략 맞추는 표시 제안이며 잘못된 방향·다리 수를 숨기는 수단으로 사용하지 않았다. 새 시트의 판금·발판 두께와 rise 마지막 직립 높이는 기존 idle과 조금 다르므로 실제 전환의 동일 모델감/상대 크기는 부모 게임 장면에서 수락해야 한다.

## 시간·전환과 표시 진단의 한계

현재 global 기본값은 hurt320ms, fall520ms, rise600ms라 4프레임이면 각80/130/150ms다. **새 CharDef에 기간 override를 추가하지 않았다.** hurt/rise는 `poseDuration(cue)`, fall은 renderer의 global fall 시간을 쓰며, 그림의 자세·표시 주기가 실제 TU/AI 행동/전원·냉각·재료 처리 시간을 뜻하지 않는다. `playback-contract.json`에 구분했다.

rise0은 완전 정지한 fall3보다 이미 첫 구동이 조금 진행된 낮은 자세다. 현재 renderer에는 상태 전환 120ms 표시 blend가 있지만, 실제 fall→rise와 rise→idle에서 자세·높이 변화가 자연스러운지는 게임에서 아직 수락하지 않았다. fall 원본을 거꾸로 돌리거나 정지 끝 프레임을 신규 rise로 세지 않았다. 완전 파괴 시 별도 잔해 원화도 없으며, 현재 fall은 **온전한 몸체의 구동 정지/낮아짐** 표현이다.

`analyze-originals.py`는 Pillow/NumPy/SciPy로 읽기 전용 알파/영역/해시와 명시된 `/tmp/ashveil-v339-surveyor-actions/` 진단 합성만 작성한다. 그 중립 배경 합성 5장을 전부 직접 열어 가림·방향·알파를 봤다. 진단 이미지는 신규 원화/배포 PNG가 아니다.

`index.html`은 새 원문 crop/anchor/scale와 이전 idle을 나란히 표시하는 **자체 staging canvas**다. 별도 localhost49539에서만 열었고 `diagnostics/staging-frame-0..3-x5.png` 4장을 캡처해 **전부 직접 열었다**. 지면 투영·자세별 높이·뒤 얼굴·끝부분 잘림을 대조했다. browser page error는 0이었으나 이는 게임 검증 결과가 아니다. 진단은 보기 쉽게 각220ms로 천천히 돌리므로 실제 default 재생 속도도 검증하지 않았다.

이번 남은 범위는 block 자세, 초상, 실제 손상/안테나 제거와 원화 부위 연결, 보고/도주/섬광 정책 통합 및 실제 장면의 크기/전환/가림 수락이다. 메인 src/public/docs/dist/게임 state/preview 수정, 프로젝트 빌드/테스트/World, commit/push는 하지 않았다. 이 폴더의 원화가 준비돼도 출시 완료로 세지 않는다.
