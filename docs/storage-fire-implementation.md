# 목제 보관함 화재와 원래 내용물

v0.290 통합 검증 중이다. 기존 실제 제작·설치 물품 `Item.StorageChest`가 만드는 `Terrain.Stash`에만 목제 연료600턴을 추가했다. 이미 있는 유한 모닥불/지형 불씨, 실제500ml 소화, 비·젖음과 같은 연소 규칙을 따른다. 일반 돌 궤짝·배 화물함·봉인 금고·제단 전체에 가연성을 상속시키지 않는다.

소진하면 설치 전 바닥으로 돌아가고 보관함 자체는 소모된다. 이미 존재하는 내용물은 같은 물품 객체/UID·수량·물량·수질·소금·정제 효력/변질·닫힌 자루 내부를 보존해 같은 자리 바닥으로 옮긴다. 배치 격자 좌표만 지우며 자동 병합·전리품 재추첨·내용물 복제·닫힌 자루 풀기는 하지 않는다. 이미 열린 같은 보관함 창은 같은 자리 바닥 창으로 바뀌고 다른 용기/시체 창은 유지한다. 이전 거점 창고 접근은 원래 terrain/설치UID 검사로 거절된다.

실제 물500ml로 끄면 같은 보관함과 내용물, 이미 줄어든 연료를 보존한다. 새 보관함을 덧씌워 연료를 채울 수 없다. 각인196→197은 버전만 올리고 과거 화재/보관함 소진/내용물 이동을 추정하지 않는다.

## 원본 표현

원본 침엽수·마른 나무80×96 두 그림과 보관함 닫힘/열림16×16, 별도 소지품32×32를 연결했다. 각 그림은 자체 픽셀 좌표·PNG/SVG·결정적 재현 도구를 포함한다. 보관함 새 키는 Stash와 StorageChest에만 사용하고 일반 상자/화물함/금고/제단/통가죽배 공유 이미지는 보존한다. 나무는 기존 anchor·배율·색조와 해시 좌우 반전을 유지한다. 원래 기본 나무 키의 레거시 혼합 선택도 유지한다. [수목](art-forest-original.md) · [보관함](art-storage-chest-original.md).

## 실행한 검사와 남은 검증

현재 관련5파일58개(새15개·기존 화재/나무문/CLI·로컬 골든10개), 타입과 배포 빌드를 통과했다. 실제5골든 전체 초기/최종/오류 비교는 버전196→197과 두 콘텐츠 해시 경로 외 모두289와 같다. 원래289 벡터는 검토 후 한 번 보관했다. [전체 비교](golden-v290-diff.json). 이 골든은 보관함 화재를 직접 겪지 않으므로 전용 화재 검사와 실제 화면 검사를 별도로 둔다.

처음 전용 검사에서 화상마다 정상적으로 할당됐다가 합쳐지는 상처UID 수를 현재 상처 개수로 잘못 추정했다. 물품만 검사하는 사례는 인물을 열원에서 실제로 떨어뜨리고 모든UID 불변 조건을 유지하도록 고쳤다. 실제 신체·미완료 휴식/복원 검사는 별도로 유지했다. 새 화재의0경과 상태에는 부분연료 기록이 아직 없으므로 소화 사례는 실제5틱 뒤를 검사한다. 창고 소진 사례는 의식 제한이 앞서지 않도록 인물을 열원에서 떨어뜨린다. 제품의 신체·UID·접근 규칙은 완화하지 않았다. 원래 실패 출력도 보존했다.

최종 실제 입력 브라우저 검증은10장/전체197복원6번/20전체상태대조/90700TU/오류0으로 통과했다. 원래 기본0.02불씨 정책에서 실제F2점화100턴/남동2걸음/200턴휴식4회로 소진을 확인하고 북서2+북1걸음 후 원래300ml물병UID만 무료 회수했다. 별도 유한 초기 연소 장면은 실제Node304턴 준비를 명시하며 브라우저에서는500ml소화1턴/무료s열기/남1걸음만 실행했다. 초기 별도 소지품 보관함도 한 개 선언했다. 캐릭터가 바로남쪽에 있을 때 닫힌상자가 몸에 가려지므로 실제로 비킨1411/1418과 소지품1419에서 원본을 확인했다. 브라우저 불러오기 뒤 세계/시간/난수/물품 주입은 없다. 첫검사는 n을남동이동으로잘못사용해주민창을열었다. 실제키Numpad3으로고쳤고 임시제품키변경은되돌렸다. raw첫실패/두번째성공/최종확장출력은모두보존했다. [실제입력근거](storage-fire-v290-native-audit.json). 전체 회귀와 월드30판은 아직 완료로 기록하지 않는다. 집 전체 벽/지붕 붕괴, 모든 지형·물품의 소각, 방화 범죄/평판, 정지 지역 과거 화재 정산과 전체 후속 구현은 남아 있다.
