# 지상 밭의 실제 이탈 날씨 정산 — v0.312

지상 밭을 떠나 다른 층·지역·바깥길에서 시간을 보낸 뒤 돌아오면, 출발 때 남긴 그 셀의 날씨에서 실제 경과를 계산한다. 같은 종자 UID·주인·관수 잔량·증발 나머지·병원체와 재를 보존한다. 익어도 실제 수확 전 음식이나 돈이 생기지 않는다. 사람·주민 노동·수확·교역을 대신 실행하지 않는다.

월드가 있는 고정 지상 지도만 대상이다. 실제 성공한 이탈에서 선택적인 `MapState.surfaceCultivation`에 출발 시각·셀·하늘·6시간 경계·지역 난수 복사본과 원래 밭/지붕/규칙 서명을 남긴다. 재진입은 이 복사본에서 해당 셀의 날씨만 재생하며, 현재 활성 날씨·전역 난수·다른 셀·몸·물품·로그를 덮어쓰지 않는다. 비는 지붕 없는 원래 밭의 빈 관수량만 채우며 같은 오염 전달 규칙을 쓴다. 인접 토양의 물 이동·성장·증발 순서는 기존 활성 재배와 같다.

계단 귀환·저장된 지역 재진입·지역을 거쳐 돌아오는 바깥길과 여행 중 다시 방문한 바깥길을 연결했다. 지역 날씨 기록이 없는 구형 저장, 이동하는 배의 갑판, 월드 없는 옛 지상은 과거 하늘을 추정하지 않는다. 일정한 지하 배양은 기존 정산을 유지한다. 저장206으로 올리며205에는 버전만 올리고 과거 출발 기록/물/성장을 만들지 않는다. 다음 실제 출발부터 새 기록이 생긴다. 규칙/지붕/원래 밭이 바뀌거나 잘못된 기록이면 임의로 정산하지 않는다.

탑 작업 완료는 그 턴의 전역 재배 처리 뒤에 일어난다. 재배의 과거 환경 조회는 이력의 적용 경계만 구분하고 계절·정지 이후 경과 자체는 현재 논리 턴을 쓴다. 따라서 새 탑 출력을 한 턴 일찍 적용하거나 토양의 연속 감소를 계속 한 턴 늦추지 않는다. 이 조회 경계는 임시 `World` 문맥이며 저장이나 UI에 추가하지 않는다. 기존 활성 기후의 기본 조회는 유지한다.

처음 구현은 모든 경과턴을 재생했다. 실제 CPU 프로파일에서 확인한 반복 규칙 문자열 생성과 매턴 날씨 조회를 줄였다. DefDatabase가 깊게 동결한 같은 DB/지형의 문자열만 캐시하고, 날씨 전이는 실제6시간 경계에서 실행한다. 물이 모두0인 비 없는 구간은 다음 날씨 경계까지 건너뛴다. 정지 탑이 없는 일정한 날씨·날짜·일교차 매듭 사이에서는 기온이 선형이므로 양 끝이 모든 작물의 최소 기온과0°C 미만일 때만 건너뛴다. 비가 오면 모든 밭이 이미 가득 찬 경우에만 이 냉각 구간 최적화를 쓴다. 실제 탑 이력·자정·임의 일교차 매듭·다음 하늘 경계를 넘겨 추정하지 않는다. 같은 논리 결과와 처리 시간은 별도로 검사한다.

전용25개가 통과했다. 실제 이탈/귀환·같은 시간 반복·분할/중간 복원·현재 하늘/난수 보존·지붕·두 밭의 물 이동·일교차의 짧은 해빙·사흘·탑 출력/분출 경계·연속 토양 변화·다른 동결 DB의 캐시 분리·구형205를 포함한다. 관련 검사 집계들은 중복되므로 합쳐 고유 검사 수로 쓰지 않는다. 초기 실패는 잘못 쓴 검사용 MapLink 형태, 실제 실행 순서 경계의 성장1턴 차이, 허용되지 않는 테스트 모드의0년 지연을 바로잡았고 규칙 검증을 완화하지 않았다.

유한 Native 장면은 실제 생성한 원래 인물/물품, 흙7×7·연결9×9창고와 물리 계단을 초기 조건으로 선언한다. 원래 종자3·관수용 오염수1000ml·횃불1개에서 실제 장비/점화/심기/관수를 준비한다. 수확 직전 장면의 남은30성장턴과100턴치 물은 유한 초기 조건이며, 이전143970성장턴이나5일 농사를 실행한 근거로 삼지 않는다. 별도205 장면은 출발 기록 없는 형식을 선언한 것이며 과거 사용자 파일이라고 부르지 않는다. 불러온 뒤에는 실제 키/버튼과 독립 Node 전체 상태 비교를 사용한다.

다음은 통합 검사 이전에 남긴 초기 범위 기록이다. 이전311 코어의 한 턴 모델과 독립 대조·두 해상도 실제 입력/PNG 검토·전체 회귀·골든·월드30판·최종 배포를 아직 완료했다고 집계하지 않는다. 고정310의1,000판과 사람 평가도 별도다. X2의 정지 지역 주민 노동·장기 공급·생태 전체를 완료했다는 뜻이 아니다.

## 예비 독립 비교·실제 입력

고정 `v312-surface-preliminary`의7개 장면을 이전311의 실제 재배/날씨/기후 모듈로 한 턴씩 계산했다.1/3/30일·마른 밭·지붕 아래 비·두 토양 밭·탑 변경 경계의 작물 전체와 지역 날씨/난수는 같았다. 이를 포함해 허용한 이탈 기록/시각 외 전체 세계를 독립 기대값으로 대조했으며 현재 전역 하늘/난수·몸·물품·로그는 보존됐다. 같은 초기30일 장면에서 이전 한 턴 모델6766.6ms/새 정산147.6ms였다. 계산 알고리즘의 측정이며 FPS나 다른 계절/대규모 농장 전체의 성능을 뜻하지 않는다.

1366×768 예비에서 실제14개 전체 상태·206복원5회·8PNG·41600TU·콘솔0을 확인하고8장을 모두 열었다. 원래 오염수의 병원체/재가 수확한 귀리5개에 남고, 출발 기록 없는205장면에는 과거 성장을 채우지 않았다. 두 화면 최종 검사나 전체 회귀로 집계하지 않는다. 골든5개의 전체 초기/최종은311과 저장 버전205→206 외에 같았고 명령/오류는 유지했다.311벡터를 보관하고 기대 해시 두 필드만 갱신한 뒤 관련2파일20개가 통과했다.

## 여름 다중 밭 부하 검사와 추가 최적화

유한 합성 초기 여름 밭1/10개·30일을 별도로 측정했다. 첫 후보의10밭은8043ms였으므로 바로 최종 검사로 넘기지 않았다. 성숙한 밭의 정수 증발을 다음 토양 경계 전까지만 묶고, 포화된 같은 수위의 성숙한 빗물 밭은 다음 하늘 경계까지 건너뛴다.29개 전용 검사에는 증발 나머지1199·포화/부분 빗물·다른 지붕/수위의 토양 이동을 추가했다.

정지 지도 정산은 서명 검증 뒤 고정된 밭/규칙을 준비하고 한 턴의 환경을 공유한다. 활성/정지 양쪽의 빗물·오염·증발·성장은 같은 적용 함수를 쓴다. 불변 정의 문자열·준비한 조회는 실행 문맥 캐시이며 각인의 필드나 주민 행동을 추가하지 않는다. 이후 같은 합성 여름10밭30일이 약1224ms였고 전용/토양/기존 농업5파일120개와 타입을 통과했다. 이는 커널 작업중 측정이며 최종 고정본의 독립 비교와 다른 계절·탑 정지·대규모 농장의 성능 검증을 대신하지 않는다. 앞 예비311 대조와 실제8PNG는 이 추가 최적화 전 원본을 가리킨다. 최종 원본으로 다시 대조한다.
