# 소유 스크립트의 실제 구성 변경

v0.257 작업 중, 각인182/API1.4.0. 설계11§8의 모드 제거 시 modState/대기 사건 폐기를 실제 이전 모드 목록·스크립트 소스 기록과 연결했다. 과거 구성 해시가 있고 실제 다른 구성을 명시적으로 승인한 경우에만, 이전 목록에는 있고 현재에는 없는 소유 모드의 해시/지속 데이터·비활성 호출/진단·그 모드가 예약한 사건을 폐기한다. 같은 모드를 계속 사용하는데 소스가 바뀐 경우는 초기화로 우회하지 않고 별도 이행 또는 원래 소스 복원을 요구한다.

계속 사용하는 모듈의 JSON/해시/예약·날짜/계절 시계를 보존한다. 실제 이전 구독자가 모두 제거되면 미완료 사건의 완료 콜백 기록을 폐기하되 이미 출발한 실제 인물/경로·공급원/물품·몸·시각·UID·전체 난수는 바꾸지 않는다. 이전 구독자가 남고 완료 콜백이 진행 중이면 새 스크립트를 과거 구독자로 추가하지 않도록 완료 후 추가를 요구한다. 소유 소스 기록이 없는 데이터/예약과 출처 없는 삭제는 원자적으로 차단한다.

실제 새 모드를 추가할 때 현재 소스 해시만 기록한다. 과거 하루/계절 훅을 소급하지 않고 새 모드의 JSON은 실제 첫 호출부터 시작한다. 보존된 난수 스트림은 삭제/재추첨하지 않는다. 새로 시작하는 모든 스크립트도 기존 QuickJS 검사/격리 실행기를 정상 준비한다. 호출자 검토 목록을 신뢰하지 않고 원문+선택 DB 토큰을 다시 검사한 후보에서만 적용한다.

검토 화면에는 실제 제거/추가할 모드와 버릴 지속 데이터/예약/완료 콜백 수를 표시한다. 취소는 원문·세계·연대기·저장을 보존하고 승인 때 실제 같은 턴 로그 하나/기존 변경 이력과 한 번 저장한다. 스크립트 정리를 물품 rename/상태 제거보다 먼저 검증하므로 없어진 정의를 보관한 제거 모드의 사적 데이터는 현재 세계의 살아 있는 참조로 오인하지 않는다. 남는 모드의 임의 JSON은 고치지 않는다.

전용10개+실제 저장 시작3개와 기존 모드 선택/상태 제거/검토/스크립트 로드·훅·명령/골든의10파일126개를 통과했다. 실제 QuickJS 한 초기 호출의 JSON/난수·정상 순찰 예약을 사용했고 지난 하루를 실행한 이력으로 꾸미지 않았다. 전체 상태 대조·실제 모듈별 격리·원자적 거절·첫 빈 상태/콜백 보호·취소/바뀐 원문·원래 인물/공급원/난수 보존을 확인했다. 골든5개 전체 초기/최종/오류/해시가256과 정확히 같아 기대 벡터/저장 형식은 바꾸지 않는다.

최종 타입·린트·Def/빌드를 통과한 원본257에서 실제 화면1270–1272 세 장 모두 확인·전체182복원2/콘솔0을 첫 실행에 통과했다. 실제 소유 JSON/예약 검토·취소·원문 유지/승인 뒤 전체 물리/시각/난수 보존과 새 실제 스크립트 추가의 빈 데이터·과거 훅 소급 없음을 확인했다.256–258 통합 전체/월드 회귀는 진행 중이다. 같은 모드의 소스 변경 마이그레이션·다른 상태/개체/사건 정의 제거·외부 가져오기/창작마당 및 전체 후속 확장은 남는다.
