# 클라우드 개발 환경과 병렬 실행

2026-10-28 KST. `/workspace/ashveil`의 기존 도구를 재사용하고 Python 표준 라이브러리 실행기를 추가했다. Node 24.19.0, pnpm 9.15.9, Python 3.12.14, Chromium 154를 확인했다. 현재 cgroup 한도는 CPU 4개·메모리 32GiB다. 별도 엔진·패키지·API 키는 필요하지 않다.

## 작업을 나누는 기준

| 작업 | 병렬 실행 | 책임 |
|---|---|---|
| 구현·리소스 제작 | 담당 파일이 겹치지 않을 때 병렬 | 시작 전 파일 소유권과 인터페이스를 합의한다. 다른 담당자의 미완성 파일을 고치지 않는다. |
| 타입·lint·소규모 회귀·읽기 전용 조사 | light 최대 2개 | `cwd`, 명령 인자, 결과 경로를 명시한다. |
| 빌드·Full·World·원정·GPU·Native·freeze | heavy 1개, light도 대기 | Full은 `--maxWorkers=2`; 기존 4작업자 World/원정은 단독 실행한다. |
| 배포 | 검증한 동일 원문의 단일 담당 | 작업 중인 다른 체크아웃을 이름만 보고 게시하지 않는다. |

`tools/cloud-harness/run.py`는 서로 다른 실행기 사본도 `/workspace/.ashveil-tools/cloud-harness/locks`를 공유한다. 실행기를 거치지 않은 명령에는 잠금이 적용되지 않는다. 포트 4317의 기존 Native preview는 단독 소유를 유지한다. 소스 수정은 실행 슬롯과 별개지만 freeze 중에는 모든 작성자가 멈춰야 한다.

```sh
python3 tools/cloud-harness/run.py tools/cloud-harness/example.authoring.json \
  --out test-results/cloud-runs/새이름 --check
python3 tools/cloud-harness/run.py tools/cloud-harness/example.authoring.json \
  --out test-results/cloud-runs/새이름
```

`--check`는 계획만 검사하고 출력이나 프로세스를 만들지 않는다. 실제 실행은 빈 디렉터리를 포함해 기존 출력 경로를 거절한다. light 타입/lint를 마친 뒤 빌드와 두 화면 smoke를 순서대로 실행한다. 파일 소유권이 없는 담당자가 소스를 바꾸면서 같은 작업본의 검사를 성공 기록으로 고정하지 않는다.

실행기는 신뢰된 내부 계획을 위한 협력 도구다. `argv` 배열을 shell 없이 전달하고 실패 코드·명령·작업 경로·시각·표준 출력/오류를 보존한다. 실패한 선행 작업의 후속 작업은 차단하고 독립 작업은 계속한다. 중단할 때 자신이 만든 프로세스 그룹만 정리한다. `kind`와 `effect`를 정확히 적어야 하며 임의 명령의 부작용을 OS 수준에서 제한하는 sandbox는 아니다.

불변본 안에서는 build/freeze/소스 변경을 거절한다. 허용한 검사도 manifest SHA와 등록 파일 원문을 실행 전후 대조한다. 먼저 작업본을 빌드한 뒤 freeze하고, 불변본 검사 결과는 그 밖의 새 출력에 기록한다. 자세한 형식과 제약은 [실행기 설명](../tools/cloud-harness/README.md)을 따른다.

## 복구와 저장

환경을 재연결한 뒤 `git status`, 실제 HEAD, 원격 ref, 보존된 원문을 먼저 대조한다. `/tmp`나 게시하지 않은 변경은 복구 근거로 삼지 않는다. 이번 복원은 깨끗한 v398이었고 원격 main은 v399 `198824a3b9d37663975583c7afb713203206c6d4`였다. 환경 점검 중에는 추적 9,055파일의 SHA-256을 모두 보존하고 상태가 깨끗함을 확인했다. 그 다음 별도 구현 단계에서 v399로 fast-forward했다. 미게시 v400 현지화 작업은 사라져 다시 구현 중이며 복구 완료로 세지 않는다.

`/workspace/ashveil-publish`는 이번 복원 때 v300이었다. 그 경로를 최신 코드로 간주하거나 기존 파일 위에 복사해 게시하지 않는다. 실행기 자체는 Git에 보관하므로 숨김 도구 디렉터리나 임시 메모가 없어도 복원할 수 있다.

설치·시작 설정은 환경 구성 초안에 저장했다. 초안 저장만으로 현재 서비스가 재시작되거나 다음 스냅샷이 게시되지는 않는다. 환경 설정에서 검토·저장·Publish가 필요하며, 현재 연결된 환경의 작업에는 영향을 주지 않는다. 저장소·네트워크·인증 정보는 변경하지 않았다.

## 실제 점검 범위

처음 복원된 v398에서 frozen/offline 의존성 확인과 타입 포함 build가 통과했다. 개발 서버의 `/`는 실제 app HTML, `/src/main.ts`는 JavaScript MIME과 변환된 진입 코드를 반환했다. 입력 검증과 기존 입력 문맥 테스트를 light로 실행하고, 두 화면 smoke를 heavy로 실행했다. 1440×1080·1366×768 각각 실제 타이틀→시작→대기→회전→소지품 11단계가 통과했으며 오류 배열은 비었다. PNG를 직접 열어 월드·소지품·타이틀을 검토했다. 이는 v1.0 전체 출시 검증을 대신하지 않는다.

실행기의 실제 자식 프로세스 검사에서는 교차 실행기 light 최대 2개, heavy 최대 1개와 상호 중첩 0, 실패 7·후속 차단, 기존/빈 출력 거부, 불변본 보호, shell 없는 인자 보존, 실행파일 누락 127, SIGTERM 143·자식 -15와 무관한 프로세스 생존을 확인했다. 같은 코드의 저장소 사본에서도 계약 9개를 다시 통과했다. 잠금 대기 중 30초에 도달한 이전 자체 검사도 실패 자료로 남겨 두었고, 무거운 게임 작업을 마친 뒤 재검한 결과와 구분한다.

외부 HTTPS의 시스템 클라이언트·GitHub 인증·공개 Pages는 정상이다. Chromium은 기존 사용자 NSS 저장소 때문에 외부 인증서를 신뢰하지 못한다. 영구 사용자 신뢰 저장소를 바꾸는 요청은 자동 승인 검토가 거절했으며 적용하지 않았다. HOME 재지정이나 인증서 검증 해제 없이 로컬 게임 브라우저 검사를 수행했다. 공개 사이트 상태는 정상 인증서 검증을 사용하는 시스템 HTTPS 클라이언트로 확인한다.

v399 복구 후에는 새 실행기로 타입·기존 lint·기존 회귀 2파일/9사례·빌드·두 화면 smoke를 통과했다. 최초 예제의 `--max-warnings=0`은 원래 `pnpm lint`보다 엄격해서 과거 원화 도구의 미사용 함수 경고 1개로 빌드/화면 검사가 차단됐다. 원본 해시를 기록한 그 도구는 수정하지 않고 예제를 기존 lint 조건에 맞췄다. 최초 실패와 재검 기록은 별도로 보존한다. v399 원격 원본 CI의 407파일/6,739사례·배포 성공도 원래 GitHub job 로그와 메타데이터에서 다시 확인해 [게시 기록](release-v399-publication.json)을 복구했다. 공개 진입 JavaScript와 이번 v399 로컬 빌드 원문도 동일하다.

## 병렬로 재개한 후속 구현

환경 하네스 담당과 파일 범위를 분리해 [현지화 원문 조사 도구](../tools/localization/README.md)를 재구축했다. TS/Vue/JSON 913입력에서 8,518후보(리터럴 6,183·형식 2,335), 사용처 9,597개를 수집했다. ID·원문 조각·동적 표현식·파일/행/열과 제외 사유를 보존하고 실제 입력 바이트를 전후 확인한다. 개인 이름의 실제 값이나 World를 조회하지 않는다. 영어 번역·런타임 치환은 아직 포함하지 않으며 이전 미게시 코드의 원문 복구로 세지 않는다.

첫 fixture에서 Vue 변환 후 복합 표현식 누락을 발견해 수정했다. 최종 parser/출력 보호/잘못된 UTF-8·소스 symlink 검사 5개, 실제 수집, 신규 파일 lint와 타입 검사가 통과했다. 이 검사들도 공통 light 슬롯으로 실행했다. 앱·Core·Def·이미지·의존성·저장 형식은 v399 그대로다. 전체 검토 결과와 실패/재검 구분은 [구조화된 검증 기록](diagnostics/cloud-recovery-20261028.json)에 남겼다.
