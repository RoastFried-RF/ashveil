# 실제 발효·다섯 회분과 원래 항아리

v0.106. 03 §4.1/4.5의14일 발효·5회분 양배추 절임·비타민 유지와120일 보존을 연결한다. 새 칸/쌓임은13 §4.6에 등록했다. 신선 양배추의6일 보존×20, 씨앗의5일 성장/5회분 수확과20턴 준비는 수정 가능한 콘텐츠 기본값이다.

연합 상점의 실제 유한 씨앗과 빈 도기 항아리를 원래 현금으로 구매한다. 씨앗은 실제 흙에 심고 성장을 기다린 뒤 기존 채집 행동으로 양배추5회분을 얻는다. 발효 준비는 원본 양배추5회분·소금1·항아리1을 실제 배치로 옮긴다. 바람이나 불을 요구하지 않는 발효의 각 연속 턴을14일까지 합산한다. 현재 시각만 바꿔 과거14일을 만들어 넣지 않는다.

배치에는 원래 항아리의 전체 물건 상태/UID를 저장한다. 회수할 때 새 용기를 생성하지 않고 같은 원본을5회분 절임 항아리로 채운다. 원래 용기 품질/내구와 음식 품질을 구별하며 신선도/총 재 오염을 보존한다. 준비한 채소의 오염을 회분별로 나눠 다섯 번 먹어도 총량이 같다. 마지막 회분은 같은 UID·품질·내구·현재 격자의 빈 항아리로 바뀐다. 일반 한 조각 음식은 기존 소비 방식으로 처리한다.

각 회분은 실제 섭취자에게40kcal/단백2g/비타민8/물160ml를 기존 영양·식단·식중독 규칙으로 전달한다. 첫 개봉 뒤 남은 음식의 부패 배율을 적용한다. 빈 회분/먹일 수 없는 거리/손 상태는 원자적으로 거절한다. 부분 항아리는 기존 거래의 남은 양 가격 배율을 사용하고 서로 합치지 않는다. 배낭이 가득 찬 회수는 같은 원래 항아리 하나만 바닥에 둔다. 빈 항아리는 다음 실제 발효에 재사용할 수 있다.

기존 가공 회수가 배치 전체를 음식 상태로 복사하던 부분을 음식의 해동/젖음/남은 음식 필드만 전달하도록 수정했다. 배치 메타데이터로 원래 용기 품질이 덮이거나 결과물 안에 배치가 들어가지 않는다. 기존 프레임 스프라이트를 아이템에서 쓸 때 별도의 없는 파일을 불러오지 않도록 아틀라스 목록도 정리했다.

각인v70은 원래 용기·발효/개봉·남은 회분·몸·난수를 보존한다. 구형69의 일반 음식/배치를 임의의 항아리나 회분으로 만들지 않는다. 기존5재현의 전체 초기/최종/오류를 대조했다. 던전3개는 버전만 다르고, 월드2개는 연합의 유한 씨앗4/항아리3 묶음 추가와 원래 시장 UID 이동/다음 UID만 달라졌다. 원래 재고의 모든 물성과 나머지 전체 상태/오류는 같다. 모든 차이는 [골든 감사](golden-v106-diff.json)에 남겼다.

전용19개·관련8파일238개 검사는 실제14일의 마지막 구간/이른 회수·원래 용기·모든5회분/실제 다른 섭취자·전체 각인/재사용·가득 찬 배낭·실제 유한 상점 구매/부분 가격·실제 씨앗/성장/수확·실패 원자성·구형 보존을 확인했다. 원래 항아리 품질과 음식 품질이 덮이던 실제 오류를 고쳤으며, 원본 채소 묶음의 한 개당 오염과 총량을 구분해 준비했다.

브라우저용 완료 직전 상태는 실제 일반 스케줄러로 만든다. 초기 원본 건빵120회분과 물70L, 실제 보온 코트를 준비하고 게임의 위생 설정을 끈 뒤, 이후에는 실제 줍기·먹기·마시기·버리기·휴식·수면만 사용했다. 1,374행동/식사69회와 원래 물36.2L 소비 후14일 완료 두 턴 전에 살아 도달했다. 몸 상태나 가공 진행을 작업 중 덮어쓰지 않았다. 건빵51회분/물33.8L와 같은 원래 항아리가 남고, 체온37°C·비타민72·실제 식사/피로/수분·수면 부채를 보존했다. 이 증거는 실제 재료의14일 가공과 몸/공급의 동시 경과를 확인하며 사람 플레이 평가는 대체하지 않는다.

v0.106에서는 유한 씨앗/원래 항아리의 실제 구입·심기/수확·원본 채소/소금의14일 발효·같은 용기5회분과 마지막 빈 용기·실제14일 생존/공급·각인v70을 연결했다. 전체108파일1,849개106.99초·전용19개/관련238개·타입/린트/Def101패치/Schema93/빌드·화면458~463/6장·네 차례 전체 복원·콘솔 오류0이다. 같은 검증용 사본의 월드30시드×최대3일339.237976897초·30개 전체 행이 이전과 같다. 전체 검사1849개는 고정 검증 사본에서 통과했다. 초기 그림 검사가 개별 PNG만 확인하던 부분을 실제 시트 파일/PNG 크기/영역까지 검증하도록 고쳤다. 실제 화면에서 남아 있던 인벤토리의 깨진 아이콘은 같은 시트 영역을 표시하도록 수정하고 타입/린트/빌드와6장 전체 화면·전체 복원 검증을 다시 완료했다. 최종 UI 사본의 모든 코어/테스트/도구 파일은 전체 검사를 통과한 사본과 SHA-256이 같다. 최종 사본의 모든 파일 manifest도 확인했다.
