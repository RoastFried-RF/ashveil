# 실제 원본 부분 스키마와 완성 정의 스키마

v0.245 작업 중. 각인177/API1.4.0 유지. 실제 로더가 현재 배포 docs/schema/defs.schema.json을 사용한다. 원본 수집 시 id/defType은 요구하고 나머지 필드는 부분 스키마로 검사한다. 원시 객체의 누락 필드는 이후 실제 패치가 채울 수 있다. 원본의 잘못된 타입은 나중에 패치로 덮어써도 원본 오류로 유지한다. 실제 상속·패치가 끝난 추상 아닌 정의는 완전 필수 필드·중첩 객체·배열 원소/tuple·허용 값으로 검사한다. 기존 참조/수치·의미 검사는 그대로 이어진다.

원본은 배포 스키마의 상속용 nullable/배열 지시·부분 객체 형태를 사용한다. 최종값은 각 Def의 원래 완전 properties/required를 사용한다. 추상 원본은 타입만 검사하며 완성 필드까지 요구하지 않는다. 임의 추가 속성 허용은 기존 스키마 정책을 따른다. 원본과 완성값 오류에는 별도 단계 이름과 실제 JSON Pointer를 표시한다. 스키마 검사 자체는 데이터·난수·스크립트 실행기·GameState·각인·패키지 직렬화·해시를 수정하지 않는다.

현재 배포 스키마에 필요한 형식/참조/객체·배열/합성·조건 키워드의 엔진 독립 검사기를 사용한다. DOM·파일 시스템·동적 코드 생성·외부 실행기를 코어에 넣지 않는다. 지원하지 않는 스키마 키는 오류로 보고한다. 범용 JSON Schema2020-12 전체 구현이라고 주장하지 않는다. 오류 수는100개, 참조 검사 중첩은512단계로 제한한다. 현재 배포 스키마는 독립 Python Draft202012Validator의 검사도 통과한다. 현재 스키마를 TS에서 내보내는 기존 생성 방향을 바꿨다고 주장하지 않는다.

Def 조회의 JSON 검사 범위를 문법/원본 부분/완성값으로 고를 수 있다. 원본 부분은 빠진 필드를 허용하고, 완성값은 실제 필수값을 요구한다. 붙여 넣은 단일 Def/배열을 검사할 뿐 원본 파일·선택 모드·게임에 적용하지 않는다. 참조/의미 검사는 실제 로드 결과와 구분한다. 범위를 바꾸면 이전 결과를 지운다.
