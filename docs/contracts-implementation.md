# 실제 시장 조달 계약 — v0.55

상인의 N창에서 실제로 부족한 붕대/건빵/목재를 납품하는 조달 계약을 맡을 수 있다. GDD §14.2의 조달 계약과 design/10 §9의 보수 구조를 기반으로 한다. 조달 외의 토벌/수색/호송/발굴/순찰·구조/조사/공급원 정리·반전까지 완료한 단계는 아니다.

## 물품과 예치 보수

게시판은 현재 시장의 실제 재고와 `TraderStock` 목표 차이가 요구 수량 이상일 때만 게시한다. 물품·현금이 없는 가상 의뢰는 만들지 않는다. 조회는 원장·난수·UID를 바꾸지 않는다. 같은 전역 게시 기간·템플릿은 완료나 취소 후 다시 맡지 못하고, 한 정착지에서 한 계약씩 진행한다.

수락은 실제 시장 지갑에서 보수를 빼 계약에 예치한다. 개인 상인의 돈과 별개인 기존 시장 계좌를 쓴다. 납품은 실제 배낭의 지정 UID·수량·내구·신선도를 검증한 뒤 같은 물품을 시장으로 옮긴다. 더미 전체는 UID를 보존하고, 일부만 옮기면 새 UID 하나만 쓴다. 남은 더미와 이동한 물품의 품질/내구/신선도는 유지한다. 물품이 부족하거나 오래된 요청이면 물품·돈·원장을 바꾸지 않는다. 완료 후에만 예치 보수를 플레이어 지갑에 지급하고 세력 평판 +1/연대기를 기록한다.

기간 만료·상인 곁에서 취소·플레이어 사망은 남은 예치를 같은 시장으로 한 번 반환한다. 상인이 죽어도 보수를 시체 개인 지갑에 복제하지 않으며, 계약은 남은 기간까지 보존된다. 시장의 기존 현금 재입고 하한은 진행 중 예치를 포함해 계산해 보수만큼 현금을 추가로 만드는 것을 막는다. 기존 경제 전체의 현금 재생산 정책은 이 변경에서 폐지하지 않았다.

각 입력은 실제 1턴이다. 살아 있고 깨어 있으며 조작/시청각이 되는 플레이어만 현재 정착지의 비적대 상인 곁에서 처리한다. 벽·막힌 대각선·인지된 교전 위협·진행 중 활동·거래 거절을 검사한다. 계약 기록은 일지에서 원격으로 읽을 수 있고 납품/취소는 현지 장부에서 한다.

## 데이터와 범위

`SupplyContract.Hearth`는 게시 갱신3일·납품 기한3일·음식 신선도60/내구30 이상·평판+1·기본보수20을 잠정 데이터로 둔다. 현재 의뢰는 같은 시장 납품이고 예상 위협0이므로 design/10의 `(20+거리×8+위협×0.8)×부 배율`에서 거리/위협 항은0, 부 배율1이다. 원거리 임무·이동 보너스를 조달 계약에 붙이지 않는다. 요구 수량은 붕대4/건빵5/목재4다. 감별/잔량이 필요한 물병·정제·도구는 이 템플릿에서 거부한다.

각인v22는 기존 돈/물품/인구를 변환하지 않는다. 수락/완료/취소/만료와 남은 예치를 그대로 저장한다. 다른 계약 템플릿·캐러밴·수요와 공공 생산의 전체 연결은 후속으로 남는다.
