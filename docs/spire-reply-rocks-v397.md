# v397 첨탑의 제한된 자동 회신과 자체 바위 원화

기존 첨탑은 실제 수리/송신에서 끝났으며, 세계관 T7의 실물 인가 코드를 통한 응답 경로가 연결되어 있지 않았다. 새 `receive` 작업은 수리와 송신 후, 온전히 읽은 반쪽 매뉴얼/코드 판과 같은 원래 실물 판 UID를 요구한다.120턴과 저장 전력10을 쓰고, 계약 자산 동결·보존 모드·지상 송신 권한 정지라는 제한된 관리 회선의 자동 상태 회신을 직접 기록한다. 구조 약속·살아 있는 응답자·채권단이 오지 않는 이유를 만들어내지 않는다.

수리/송신/정지 세 작업의 모든 JSON 바이트 의미와 작업 서명은 유지한다. 기존 진행 중 송신의 지침이 바뀌지 않도록 송신 문구도 덮어쓰지 않는다. 새 개인 기록은 앞선 지상 송신 당시에는 회신을 확인하지 못했고 별도의 관리 수신 단계에서 상태 회신을 받았음을 설명한다. 작업 추가는 기존 FieldDevice 규칙을 사용하며 Core/저장219/스키마를 바꾸지 않는다.

본인이 수리/송신/자동 회신을 모두 확인하고 탑이 정지하지 않은 칠번 굴뚝의 지상 출입구에서 네 번째 결말 ‘보존된 하늘의 회신’을 검토할 수 있다. 기존 세 결말을 유지하며 개인 회신 전에는 새 결말과 탐구 단계의 이름/본문을 공개하지 않는다. 결말 자체는0TU이고 실제 정비 시간·실물 판·전력은 원래대로 요구한다. 보고서/연대기·각인 삭제는 기존 종료 경로를 따른다.

## 지형 원화

새 바위는 image_gen1요청/1PNG의6고유 형태다. 원문1717×916·SHA256 `8dca35709f2e46b37ad48a80b1ae42442e42a89a9bbcc3a676f9ed00c88910f4`를 바이트 그대로 보존하고 atlas 셀만 등록한다. 요청한 여백/차지 비율이 완전히 맞지는 않았다. 셀 전체의 저알파 fringe를 유지하고 불투명128 경계로 접지점과 기존21.6단위 폭을 맞춘다. 그림의 높이는 형태에 따라 달라지지만 지형 충돌·시야·채집량·재성장/시간은 바꾸지 않는다. 옛 `rock`와 모든 기존 시트/프레임은 유지하며 모드의 별도 스프라이트 요청도 존중한다.

기존 좌표 해시로 실제 Def의 여섯 변형을 선택한다. 게임 RNG를 추가 소비하지 않는다. 디버그 표현은 현재 보이는 바위만 읽어서 반환하며 숨은 지형을 관찰 API에 추가하지 않는다. 원화/정확한 요청은 [제작 근거](../tools/art/direction-v397/rocks-source.json)에 있다. 참고 위키의 구도/접지·명암 원리를 조사했으나 참고 이미지 픽셀을 생성 입력이나 배포에 넣지 않았다.

## 검증 기록

현재 최종 검사 결과와 게시 영수증은 [검증 상태](release-v397-proof.json)에 확정한다. 실제 장치의 진행/예약 해제·수신·개인 실마리·저장, 네 결말의 실제 검토/취소/종결/보고서 파일/연대기, 낮·밤 바위의 실제 충돌/채집/저장을 독립 Node 전체 세계와 대조한다. 유한 초기 위치/근거의 실제 작업 준비와 정상 장기 여행을 구분한다. 전체 디버그 세계는 로컬 검증 자료로만 보존한다.

다섯 기존 골든의 전체 초기/최종 세계와 모든 명령 오류를 v396과 비교했다. 콘텐츠 식별자인 `loadHash`와 `contentMods[0].hash` 두 필드만 다르며 나머지는 모두 같다. 이를 확인한 뒤 두 fixture의 초기/최종 기대 해시만 갱신했다. 명령·초기 설정·기대 오류를 고치지 않았다. 신규 전력 소비는 선택한 새 작업의 비용이며 기존 전투/기후/생존 밸런스는 그대로다.

수신 작업이7턴 진행된 장면을 직접 열어 보다가 다른 작업인 탑 정지에도113턴이 표시되는 견적 오류를 찾았다. 자기 작업에만 남은 진행을 적용하도록 순수 조회를 고쳤다. 같은 수신은113턴, 별도 정지는120턴으로 표시한다. 실제 두 화면14비교를 재실행했고 수정 전후14세계 바이트도 같다. 이는 표시 견적 수정이며 작업 진행/소비를 바꾸지 않는다.
