# 기존 돌의 실제 투척 공격

## 범위와 근거

기존 `Item.Stone` 한 개를 실제로 던져 공용 전투 판정을 수행하고, 같은 돌을 바닥에서 직접 회수한다. 새 아이템·무기 슬롯·탄약·숙련·화기·투창은 추가하지 않는다. 기존 다른 물품을 좌표에 던져 소리로 유인하는 `throw` 행동은 그대로 유지한다.

- `docs/CANON.md`: D9의 기본1행동100TU, D11/D22의 공간 기반 소지품·무게 규칙 없음, D14의 실제 상태 가시화.
- `docs/design/07-combat.md:339`: 돌은 **타격5·관통0**, 회수 가능한 투척물이다.
- `docs/design/07-combat.md:64`: 유효 사거리 초과1칸당 명중−3, 움직이는 대상−5. 같은 문서 §2.1의 명중5~95·조명·방향·엄폐·팔/머리 상태·고저차를 공유한다.
- `docs/design/07-combat.md:293`: 높은 자리의 원거리 명중+5·최대 사거리+1을 기존 `rangedRange`로 적용한다.
- `docs/design/13-inventory.md:95`와 기존 `src/content/core/defs/crafting.json`: 돌 조각은 **1×1·최대5**이다. 이 크기·쌓임·잡동사니 분류를 유지하므로 새 아이템 선등록은 필요하지 않다.

기본값 중 정본에 수치가 있는 것은 피해5·관통0이다. 최대 사거리6·100TU·소음3은 기존 좌표 투척 행동의 값이다. **유효 사거리3·정확도0·기력3**은 정본이 없는 이번 단위의 수정 가능한 콘텐츠 제안값이다. `src/content/core/patches/stone-throwing.json`에 분리했다. 회수 확률은 새로 만들지 않았다.

## 실물과 전투 경계

새 `throwAttack {uid, target}`은 대상 생물ID와 실제 돌UID를 받는다. `throwQuote`가 먼저 현재 실물·접근 가능한 배낭·정상적인 개수·사용 가능한 실제 팔·시야·살아 있는 대상·정수 좌표·시선·대각 모서리·사거리를 읽기 전용으로 검사한다. 플레이어에게는 현재 `visible`과 실제 `canSee`를 모두 요구해 기억 속 대상이나 사라진 대상을 ID만으로 맞히지 못하게 한다. 닫힌 마대 안의 돌을 꺼낸 것으로 간주하지 않으며 없어진 UID를 다른 더미로 자동 대체하지 않는다.

직선은 기존 `hasLos`를 쓰고 각 대각 구간은 기존 `diagonalBlocked`를 확인한다. 시작/끝이 맵 밖이거나 비정수·비유한 좌표이면 선 계산 전에 거절한다. 최대 사거리는 기존 체비셰프 거리이며 고저차 보정을 공유한다.

검사가 통과한 뒤에만 `removeOne`으로 실제1개를 분리한다. 마지막1개면 같은 UID를 유지하고, 더미면 원래 UID/남은 수량을 두고 던질1개에만 새 UID를 할당한다. 기존 주무기·보조 장비를 임시 교체하지 않는다.

`Wield.throwing`과 선택적 `AttackOpts.wield`는 실제 돌의 공격 문맥을 공용 `previewHit`/`resolveAttack`에 전달한다. 명중·방패·방어구·상처·신체/사기/범죄·공용 스크립트 훅·공격/피격 연출과 로그는 같은 판정을 쓴다. 활의 인접 사격−10은 돌에 적용하지 않는다. 사용 가능한 팔을 고르고 그 팔의 상태 보정을 그대로 읽는다. 02 §3.2의 한손 행동 정본에 따라 사용 손의 `handCapacity`가0.5 이상이어야 한다. 주손/비주손을0.6/0.4로 합친 표시 조작을 요구해 온전한 왼손만 남은 사람을 막지 않는다.

활시위 파손·장전·화살 깃·박힌 화살·확률 회수·맨손 공격·회수 시 새 물품 생성은 호출하지 않는다. 손에 남는 무기의 마모를 투척물에 붙이지 않으므로 원래 돌의 내구·품질·오염·재질·회전을 유지한다. 방어자의 방패/방어구 마모와 신체 피해는 공용 판정대로 일어난다.

명중·빗나감·방패 막기·방어구 튕김 어느 경우든 던진 그 돌1개를 원래 대상 좌표의 바닥에 놓는다. 같은 상태의 여유 있는 더미만 최대 쌓임 안에서 합친다. 기존 `canStack` 검사에 더해 UID·개수·배낭 좌표 이외의 모든 인스턴스 속성이 같은지도 확인하므로 추가 상태가 병합으로 사라지지 않는다. 합치면 기존 바닥 더미의 UID가 대표로 남고 수량만1개 늘어난다. 가득 찼거나 상태가 다르면 던진 돌UID가 별도1개 더미로 남는다. 자동 회수하지 않으며 평소처럼 이동·줍기/루팅한다. 직접 주울 때에는 기존 시간 정산과 자동 격자 배치를 따른다. 특히1×1돌의 배낭 회전은 기존 규칙처럼 기본 방향으로 정규화되며 착지/저장 시의 원래 회전 보존과 구별한다.

## 사용 경로

소지품에서 돌을 더블클릭하거나 메뉴의 **투척 공격 (1개)**을 고르면 실제 UID로 조준한다. 기존 **빠른 슬롯에** 메뉴로 연결한 돌도 같은 `useItem` 경로를 사용한다. 보이는 적 중 현재 실제로 닿는 대상만 고르고 Tab으로 순환·Enter/클릭으로 확정·Esc로 취소한다. 조준 시작/취소에는 시간·돌·기력이 들지 않는다. 확정 순간 Core가 같은 UID/시야/대상/거리를 다시 검사한다.

조준 중 커서의 명중 미리보기는 돌의 `throwQuote.preview`를 읽으며, 손에 쥔 다른 무기의 수치를 표시하지 않는다. 아이템 툴팁에는 피해·관통·정확도·기력·유효/최대 사거리·실제 돌1개 회수 안내를 표시한다.

## 저장과 예상 물리 변화

새 저장 필드는 추가하지 않았다. 원래 돌의 인스턴스·바닥 물품·전투 난수·소지품 빠른 슬롯이 기존 저장 경로로 이어진다. 조준 선택은 기존 UI 임시 상태이며 저장에 돌을 복제하지 않는다. 같은 저장에서 같은 `throwAttack`을 수행하면 같은 전투 결과와 바닥 실물이 남아야 한다.

기존 NPC AI의 무기 선택·활/석궁 동작·아이템 가격·크기·획득량·초기 지급·제작법·일반 물품 유인 행동은 바꾸지 않는다. 새 입력을 실행할 때에만 위 투척 결과가 추가된다. 새 콘텐츠 패치가 추가되어 콘텐츠 해시 자체는 달라지지만, 이를 기존 플레이의 물리 변화와 동일시하지 않는다. 기존 체크포인트·골든·완료 표시는 이 문서에서 변경하지 않는다.

## 확인 상태

`tests/throwing.test.ts`는 실제 Core 경로로 다음을 검증하도록 작성했다.

- 타격5/관통0·기존 칸/쌓임·주무기 보존과 공용 판정 일치.
- 조회 순수성, 실제1개 분리, 마지막 UID, 바닥 병합/최대 쌓임/추가 상태 보존.
- 실제 명중·빗나감·방패·방어구 튕김과 바닥 실물 회수.
- 직선 벽·대각 모서리·체비셰프 거리·높은 자리·현재 시야·어둠·잘못된 좌표.
- 사라진 UID·닫힌 마대·다른 물품·손 기능, 저장 복원 후 결정론.
- 기존 유인 행동 유지와 잘못된 투척 Def 거절.

Root의 전체277/World30 검증 종료 후 허용된 범위에서 검사했다.

- `node --import tsx tools/export-schema.ts`: 배포 Def 스키마 재생성 완료.
- `vitest run tests/throwing.test.ts --maxWorkers=1`: **21/21 통과**, 최종 실행2.46초.
- 변경한 Core/클라이언트/테스트 파일12개의 대상 ESLint: 오류·경고 없이 통과.

첫 검사에서 발견한 한손 조작 경계는 실제 사용 손의 `handCapacity`로 수정했다. 기존 줍기의1×1 기본 회전 배치/시간 정산은 바꾸지 않고 착지·저장 보존과 직접 줍기 후 배치를 구분해 검증했다. 전체 타입 검사·전체 회귀·빌드·브라우저/GPU 검증은 이 격리 작업에서 실행하지 않았다. 통합 뒤 별도 검증 대상이다.

Root 통합 검토에서는278 동결/실제 하네스 검증 뒤 소스 패치를 적용했다. 새 각인/Item은 추가하지 않았고 콘텐츠 패치는286개가 된다. 실제 브라우저 경로는 유한한 초기 돌2개·도끼·오른팔 결손/온전한 왼손을 기록한187각인을 타이틀에서 불러오고, 메뉴 조준/취소·빠른 슬롯·실제 투척·바닥 이동/줍기·전체 저장2회를 독립 Node와 대조하도록 준비했다. 아직 이279 실제 화면/통합 검사를 실행한 결과는 아니다. 원래 도끼의 관찰 시각은 정상 턴마다 갱신되므로 전체 상태 비교에서 실제 시각을 유지하고, 마모 등 나머지 인스턴스 상태의 보존을 별도로 검사한다.

Root 검토에서02§8의 ‘그 팔로 공격1회마다 부목 없는 골절 하중’ 연결이 빠진 것을 확인했다. 성공한 투척이 실제 사용한 팔을 반환하고 기존 worsenFractures를 그 팔에만 적용하도록 연결했다. 무효 입력/쓰지 않은 팔에는 새 판정을 하지 않는다. 금 간 실제 전완의 하중/비사용 팔 경계2개를 추가했으며 통합 검증 전이다. 기존 사격 등 다른 입력의 물리 경로는 이 수정으로 바꾸지 않는다.
