# 표석·탐구 저장 방식

사용자가 후속 확장까지 포함해 v1.0.0을 향한 자율 구현을 지시한 범위에서 GDD §10.2의 C10을 구현한다. 기본 각인은 유지한다. 방식은 새 원정을 만들 때 선택하며 원정 도중 전환하지 않는다. 모드 제작자는 `SaveMode` Def를 추가/패치할 수 있다.

| 방식 | 현재 원정의 자동 기록 | 직접 남기는 복원 지점 | 생애 종료 | 업적 |
|---|---|---|---|---|
| 각인 | 기존 단일 자동 기록 | 없음 | 자동 기록 삭제 | 기존 자격 유지 |
| 표석 | 동일한 현재 원정 기록 | 켜진 실제 모닥불 또는 유효하게 대여한 여관 침대 곁 | 자동 기록 삭제, 마지막 표석은 보존 | 비활성 |
| 탐구 | 동일한 현재 원정 기록 | 장소 제한 없음 | 자동 기록 삭제, 마지막 탐구 지점은 보존 | 비활성 |

F3 설정에서 저장 방식 설명과 저장/복원 버튼을 읽는다. 저장은 턴·몸·물품·UID·돈·난수를 바꾸지 않으며, 기존 같은 방식의 복원 지점을 덮어쓰기 전에 확인한다. 방식마다 수동 슬롯은 하나다. 시작 시 복원 지점을 자동으로 만들거나 이전 지점을 덮어쓰지 않는다. 첫 복원 지점은 직접 남겨야 한다. 탐구의 자유 저장은 장소 제한이 없다는 뜻이며 다중 파일 슬롯 UI는 이번 범위에 포함하지 않는다.

표석의 기본 거리1은 체비셰프 인접이며 실제 시선과 막힌 대각선도 검사한다. 설치한 화로는 원래 물품 UID·실제 남은 연료가 있어야 한다. 기존 정착지 화덕은 실제 모닥불 지형/켜진 광원으로 판정한다. 여관은 원래 침대 지형·플레이어 계약·현재 미만료·근접 조건을 함께 요구한다. 숨겨진 적 여부를 조회해 저장 가능 표시로 누설하지 않는다. 계산 중이거나 끝난 생애에서는 새 지점을 남기지 않는다.

자동 기록과 각 방식의 수동 기록은 별도 IndexedDB 키·localStorage 미러·쓰기 큐/세대 번호를 쓴다. 사망 삭제 표식은 현재 자동 기록에만 쓴다. 수동 기록의 본문은 전체 세계이며 물품이나 난수를 재생성하지 않는다. 복원은 타이틀/설정/종료 보고서에서 가능하며, 시드·인물·턴과 실제 콘텐츠 구성을 먼저 검토한다. 확인 전에는 현재 세계/자동 기록/수동 원문을 바꾸지 않는다. 취소·늦게 도착한 읽기·검토 뒤 슬롯/콘텐츠 변경은 자동 승인하지 않는다. 복원은 확인한 원문으로 현재 원정을 교체하고 자동 기록을 쓴다. 이후 자동 저장 실패는 복원 실패로 위장하지 않고 별도 오류를 표시하며 수동 지점은 남긴다.

표석/탐구는 불러올 때도 업적 차단을 적용한다. 연대기는 생애를 마친 실제 방식 ID/이름을 기록한다. 은퇴 인물의 다음 원정 계승은 같은 시드·같은 저장 방식만 사용하며 과거 미기록 생애는 기존 각인으로 취급한다. 시드 공유는 비기본 방식만 선택 정보에 추가하고 실제 Def 종류/존재를 검증한다. 수신자의 다른 로컬 은퇴 기록은 공유 세계에 끼어들지 않는다.

저장 형식205는204의 버전만 이행한다. 과거 수동 지점·방식·업적 이력을 추정하거나 새 장비를 지급하지 않는다. 형식/정의가 잘못된 원문은 삭제하지 않고 읽기를 거부한다. 고정 입력5개 전체 초기/최종/오류를 v305와 대조한 결과 형식204→205와 새 정의3개/콘텐츠 해시 외의 전체 상태는 같다. [기계 감사](checkpoints-v306-golden-audit.json).

최종 검증은 아래 실제 기록을 따른다. 공개 배포 결과는 게시 후 따로 확인한다. 전용 Native의 치명 장면은 처음부터 HP1·실제 근접 적·combat 난수 배열을 선언한 유한 초기 각인을 실제 타이틀에서 불러온다. 로드 후 세계/몸/시간/난수는 바꾸지 않으며, 실제 대기 입력으로 사망하고 실제 저장/복원 버튼으로 돌아온다. 자연적인 장비 획득·장기 생존·사람 평가 증거와 구분한다.

v1.0.0의 나머지 범위·밸런스·장기 생태·현지화·사람 평가 게이트는 [실행 기준](v1-execution.md)에 남는다. 이번 묶음은 리소스 PNG를 바꾸지 않는다. Eslabong을 포함한 원화 참고 기록은 [v305 조사](art-research-v305.md)에 있으며 실제 숲에서 반복되는 나무 실루엣 변주는 다음 미술 묶음에서 다룬다.

## 최종 통합 검증

전체340파일 6,173개를 한 번의 전체 실행으로 통과했다(875.286초, 작업자2). 두 화면 크기 실제 저장/복원32PNG·독립 전체상태66쌍·복원14회·실제입력합계1,800TU·오류0과 공통8PNG를 확인했다. 최종40PNG를 각각 열어 검토했다. 기본 각인의 물리 상태와5골든 전체초기/최종/오류는 저장 버전·콘텐츠 해시/새 정의3개를 제외하고v305와 같다. 이번 묶음에 새 원화나 수치 밸런스 변경은 없다. 월드30판을 다시 실행하지 않았으며 최신 실측은v305다. [전체 근거](release-v306-proof.json).

전체 검사는 `v306-checkpoints-feature-final`에서 실행했다. 이후 타이틀의 목록 감시 초기화 순서와 복원 창의 선택 변경 시 승인 취소를 두 Vue 화면에서 보완했다. Core·콘텐츠·단위 테스트·도구·모드·원화는 전체 검사본과 바이트가 같으며 최종 UI 빌드에서 타입/린트와 위의 두 해상도 Native/공통 검사를 마쳤다. [범위 대조](checkpoints-v306-post-full-scope.json). 최초 동결 Native의 빈 저장 목록 실패는 `test-results/native-checkpoints-v306-1440`에 보존하고 최종 통과 수량에서 제외했다.
