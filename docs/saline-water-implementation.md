# X4를 위한 실제 염수와 물병 혼합

v0.88 / 각인v52. 정본의 병원체/재를 보존하면서 X4 해안의 용존 소금을 별도로 추가한다. 기존5개 입력의 전체 초기/최종 상태와 오류는 저장51→52 외 동일하며 이전v087 벡터를 보관했다. 관련6파일158개와 타입/린트/Def64패치·빌드를 통과했다. 전체90파일1,503개106.96초·최종 타입/린트/Def/Schema81파일 오류0·빌드를 통과했다. 원본 Def의 패치 전 선언을 고려한 Schema/로더 검증 수정 뒤 Def/염수91개를 재검증했고 최종5전체 상태도 동일하다. 브라우저322~328의 화면7장·두 차례 전체 각인v52 복원·콘솔 오류0을 확인했다. 실제1L 해수/200턴 가열/원래 장작·500ml 붓기/총35g 소금과 음수의 탈수·실제7회 처리한 중간 상태의 계속하기를 검증했다. 자동화의 생성 번호 비교는 기존 장작 묶음 분리 소비를 고려해 붓기 직전 번호로 고쳤으며 같은 앱으로 재검증했다. 같은 월드30시드×최대3일269.347017313초·평균0.4219895833333334일·저체온19/치명상5/과다 출혈6이며30개 전체 최종 행이v0.87과 같다.

바닷물 지형은 실제 수원에35g/L 염도를 가진다. 일반 물과 구형 각인은 선택적 염도 필드가 없어 기존 담수로 남는다. 해안/늪 지역의 배치·배와 소금 생산 자체는 아직 다음 작업이며 이 기반만으로 X4 완료로 집계하지 않는다.

같은 물병을 채우면 실제 주변 수원을 확인한다. 기존 채우기는 내용물을 버리고 새 수원으로 채우는 동작이다. 새로운 붓기는 배낭의 서로 다른 실제 물병 두 개 사이에서만 동작한다. 실제 잔량과 받는 병의 용량을 확인하고 ml 비중으로 염도·병원체·재를 섞는다. 새 물병/UID를 만들지 않는다. 마지막까지 비우면 원래 빈 병이 남고, 소금과 오염은 옮긴 물에 따라 이동한다. 언 물/잘못된 양/원격·동일 병/용량 초과/다룰 손 부재는 변경 전에 실패한다. 우클릭 메뉴는 실제 빈 용량만큼 옮긴다.

끓임·천/숯 여과·정수정·침전은 소금을 제거하지 않는다. 기존 끓이기는 물의 양을 줄이지 않는 추상 처리이므로 염도를 보존한다. 실제 증류·염전에는 물/소금 질량과 연료/시간·받는 용기의 물리적 처리가 별도로 필요하다. 정수 중 염도가 바뀌면 기존 수질/물량 예약과 마찬가지로 중단한다.

수분은 실제 마신 양을 흡수하고 소금 질량당 배출 수분을 더한 뒤 결손0 제한을 적용한다. 기본값50ml/g에서 바닷물200ml는 소금7g/배출350ml여서 순수분150ml를 잃는다. 처음에 갈증이 없어도 적용한다. 병 마시기·직접 물 마시기·다른 인물 돌봄은 같은 경로를 쓴다. 식수 자동 선택은 기본1g/L를 넘는 염수를 피하고, 거점 작업자는 식수 수원으로 바꾸며 소금을 끓여 없애려 반복하지 않는다. 일반 씻기는 실제 염수를 사용할 수 있지만 정밀 설비 청소에는 소금 없는 물이 필요하다. 말라붙은 자 진정에 부적합한 염수를 사용할 수 없다. 기준값은 WaterSafety Def 패치로 분리했다.

설명은 소금물 표시·g/L·실제 남은 소금과 탈수/정수 한계를 보여 준다. 염도·실제 잔량과 진행 중 정수는 전체 각인으로 보존한다. 정식 해안/늪 지역·소금 생산/염장·선박/봉화 신호망과 나머지 전체 후속 구현은 계속 진행한다.
