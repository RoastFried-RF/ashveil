# 격리 스크립트 훅 · v0.224 / 각인161

설계11 §6–7의 단계1 동기 훅을 QuickJS0.32.0/WASM으로 구현한다. 순수 코어는 플랫폼 실행기 인터페이스만 사용한다. 브라우저와 CLI는 같은 격리 실행기를 준비하고 소스 등록을 검사한 뒤 시작한다. 제목 화면의 캐릭터 미리보기는 스크립트 실행을 요구하지 않는다. 실제 새 게임 시작은 준비를 기다리고 실패 시 이전 게임/각인을 덮어쓰지 않는다.

실제 명중 계산/공격 종료/외부 상처/사망/제작 완료/날짜·계절 경계와 현재 지도 순찰·수색 출발 및 원래 인원 귀환을 연결한다. 화면 명중 미리보기는 모드 상태·로그·난수를 바꾸지 않는다. 실제 호출의 전체 명령을 검증한 뒤 모드 상태·하위 난수와 함께 적용한다. 실패한 호출은 해당 훅만 중단한다. 명령은 현재 로그/사고/평판만 지원한다.

VM마다16MiB/스택256KiB/인터럽트5구간을 적용한다. 고정 QuickJS의 인터럽트 카운터는10,000이며 JS문장 개수와 동일하지 않다. 전역 숨은 상태·파일·네트워크·시각·타이머·비결정적 수학을 제공하지 않는다. 복사한 당사자 뷰와 사건은 동결하고 자신의 JSON데이터만 저장한다. 반환 데이터는 UTF-8 64KiB, 소스64KiB, 명령32개, 추적 사건32개로 제한한다. 악성 예외의 getter/toJSON도 실행기 밖에서 읽지 않는다.

각인160에는 버전161만 올리며 과거 호출을 만들지 않는다. 선택하지 않은 기본 게임은 모드 상태/추가 난수/실행기를 만들지 않는다. 선택한 게임은 소스 해시·모드 데이터·하위 난수·중단 훅·진행 사건을 저장한다. 소스가 다르면 같은 원본 구성을 복구할 때까지 이어 하기를 거절한다. 해시는 재현 식별용이며 서명이 아니다.

샘플 모드는 기존 Def·Item·사람·물품을 추가하지 않는다. 실제 명중 가산2와 날짜 로그/개인 카운터만 보여준다. [사용법과 실제 지원 API](modding-guide.md#동기-스크립트-훅--v0224).

단계2 워커·추가 명령(applyWound/spawnItem/queueEvent)·동결 지역 사건 연결·외부 배포/창작마당은 남는다. 전체 검증과 실제 브라우저 결과는 진행 중이며 완료 뒤 기록한다.

최종 정적 검사/빌드와 Schema143개 오류0, 실제 스크립트 패키지 검증이 통과했다. 기본5개 골든의 전체 초기·최종 상태/오류는 v223과 비교해 버전160→161 외 모두 같다. 이전 벡터를 한 번 보관하고 예상 해시만 갱신했다. 샘플 배포 파일의 SHA-256은 `54c63c17a75f005ebb309c84dccedf853ed1f822bc6fa4e18df1f195abbe093b`이다.
