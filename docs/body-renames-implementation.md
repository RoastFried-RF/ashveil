# 실제 몸 상태를 유지하는 Body ID 이행

v0.264 작업 중, 각인182/API1.4.0. 실제 이전 정의 목록과 현재 rename이 같은 Body로 연결될 때 Actor.body.def 식별만 옮긴다. 저장된 maxHp 키 집합이 현재 목적지 Body.parts ID 집합과 같고, 기계 상태 유무가 현재 기계/유기체 분류에 맞고, 현재 Creature 정의가 그 목적지 몸을 사용해야 한다. Creature도 함께 rename한 경우 실제 현재 목적지 Creature의 계약으로 확인한다. 부위나 실제 몸을 다시 만들거나 혈액/HP/상처·절단/의수족·기계 전원/냉각·개체 번호·시각/난수를 채우지 않는다.

다른 해부학/기계 변환·현재 개체 계약 불일치·타입 변경/출처 없음·남는 임의 JSON/현재 값·키는 원자적으로 차단한다. 과거 개인/정신/상처/질병 원인은 보존한다. 현재 도감 표본의 def는 Creature ID이므로 이를 Body ID로 잘못 옮기지 않는다. 같은 부위 ID 집합 검사는 과거 모든 수치나 부위 부모 구조가 현재와 같다고 추정하는 검사가 아니다. 소유 스크립트 정리→물품/상태/사건/몸/개체 rename→없어진 사건/상태→물품 보관의 같은 원문/현재 DB 토큰 승인에 연결한다.

이행을 검사하며 기존 신체 메모 캐시에 현재 콘텐츠 DB/몸 ID가 없어 같은 개체를 다른 정의로 계산할 때 이전 통증이 남는 실제 경로를 확인했다. 실제 현재 Core Body.Quadruped의 해당 부위 pain을 PATCH로3배 바꾸고 같은 개체의 몸 ID를 이행한 회귀에서 캐시가 있는 통증1.2와 전체 저장을 새로 복원한 통증3.5999999999999996의 불일치를 재현했다. 기존 계산식을 바꾸지 않고 캐시 엔트리의 DB 객체와 상태 지문의 몸 ID를 포함해 현재 정의에서 다시 계산하도록 고쳤다. 몸 ID는 JSON 문자열로 구분한다. 첫 회귀 작성의 상속 전 원본 부위 경로 패치 거절과 이후 실제 캐시 불일치 실패를 각각 보존한다.

실제 기본 비활성 sample-body-renames1.0은 Body.Quadruped와 그 몸을 쓰는 같은 Creature/BestiaryEntry를 상속한 비물품 세 정의와 실제 몸 ID맵을 제공한다. 이전0.9 정의를 먼저 실제 로드한 정상 새 게임에서 실제 createCreature의 선언된 초기 배치/현재 시야·관찰만 호출한다. 과거 출생/전투/경과 턴을 실행한 이력으로 꾸미지 않는다. 다른 해부학 시험은 원래 Body 정의의 부모를 실제 인간형으로 바꾼 뒤 생성하며 실제 생성된 몸 상태를 편집하지 않는다. 배포4파일1186바이트·277패치/경고0·SHA256 969362a709c48665d1ecd8826e5af9c8642f031bf6afbd8f4c3571825ae343f3를 확인했다. 새 Item은 없다.

전용8개+실제 저장 시작2개를 포함한 초기10파일60개가 통과했다. 실제 캐시 회귀를 추가해9개 중8개 통과/기존 코드의 실제 계산 불일치 하나를 확인한 뒤, 수정한 관련11파일69개가 통과했다. 최종 몸 ID 지문을 반영한 신체/캐시/골든3파일27개도 모두 통과했고 최종 타입/린트가 통과했다. 전체 상태 독립 대조·현재 지식/표본 Creature ID/혈액·상처·현재 실행 세계/화면·원문 보존·한 번 저장과 올바른 따뜻한/빈 캐시 일치를 확인한다.

캐시 수정 전/후/최종 지문의 골든5개 전체 초기/최종/오류/해시가 모두263과 정확히 같다. 기본 각인182/벡터·Core Def/191물품/277패치를 바꾸지 않는다. 실제 화면/전체182복원·263–264 통합 전체/월드 회귀와 다른 종류/개체 제거/설치·소스 이행 및 나머지 전체 후속 구현은 진행 중이다.
