# 실제 솔잎 채집·원래 물병의 솔잎차

현재 중단 후 진행 보존은 [v0.115 구현 기록](brew-progress-implementation.md)을 따른다. 아래는 v0.108 당시의 구현/검증 기록이다.

v0.108. 03 §4.1의300ml당5kcal/단백0/비타민6/수분300ml/신선6시간과 §10의실제 솔잎·연료/10분 끓이기를 연결한다. 13 §4.8에 솔잎1×1/쌓임10·원래1L 물병의 차1×2/쌓임1을 먼저 등록했다. 재료300ml당1묶음(올림), 살아 있는 소나무8%·4묶음/20턴·하루 재생은 조정 가능한 콘텐츠 기본값이다.

살아 있는 소나무는 실제 기존 나무의 목재·충돌·시야 차단·엄폐를 보존한다. 별도 채집 활동20턴 마지막에4묶음만 얻고 같은 나무의 솔잎 재생 시각을 남긴다. 목재 재생과 구별한다. 말라 죽은 나무에는 솔잎이 없다. 새 지도를 생성한 마지막 단계에서 독립 world.botany 난수로만 배치하며, 구형 지도에 나무를 소급 생성하지 않는다. 현재 실제 나무 그림에 녹색을 적용한 임시 표시이며 정식 신규 에셋 전체 완료는 아니다.

차 견적은 원래 물병 UID/실제300~1000ml/수질/솔잎 UID별 실제 묶음/같은 설치된 유한 장작불을 읽는다. 정적 무료 화덕은 대신하지 못한다. 실제200턴 동안 물·수질·솔잎·불·조리 규칙을 다시 확인한다. 중단/변경에는 재료를 소비하지 않고 진행을 잃는다. 마지막 턴에만 원래 솔잎을 소비하고 같은 물병을 차로 바꾼다. 원래 품질/내구·1L 용량·UID를 유지하며 새 용기를 만들지 않는다. 기존 끓임 수질 규칙으로 병원체는0, 재는×1.1, 염분은 그대로 남긴다. 차를 끓인 것만으로 몸에 영양이나 체온 보너스를 주지 않는다.

실제 마신ml에 비례해 영양을 받는다. 1L는300+300+300+100ml이며 마지막100ml도 비타민2/열량5÷3을 정확히 준다. 총 비타민20/열량50÷3이다. 남은 차가 없어지면 같은 원래 UID 물병이 비고 수질/신선도 기록을 지운다. 씻기에 소모해도 비타민을 받지 않고 같은 빈 물병이 남는다. 차를 일반 물 붓기/정수에 쓰는 경로는 없으며 차의 영양을 새 물에 복제하지 않는다. 실제 다른 섭취자에게 마시게 할 때도 그 몸에만 수분/영양/원래 재·염분이 전달된다.

신선 음료는 기존 시간별 부패·기온/동결/해동·위생/식중독과 거래 신선도 규칙을 사용한다. 기존 일반 물/술의 동작은 유지한다. 제작F2에서 실제 인근 소나무 채집·배낭 솔잎 선택·원래 물병별 실제ml/조리 시간과 거절 이유를 확인한다. 물병 설명에는 실제 남은 양·300ml당 비타민·6시간 신선 기간을 표시한다.

각인v72은 원래 물/솔잎/불의 진행·부분 섭취/마지막100ml·같은 빈 병·나무 재생 시각을 보존한다. 구형71에 과거 차/솔잎/나무를 만들지 않는다. [5재현 전체 상태 감사](golden-v108-diff.json)는 버전과 실제 소나무 지형/독립 난수 외 모든 초기/최종 상태와 오류가 같다.

v0.108에서는 실제 살아 있는 소나무/20턴 채집·원래 물병/실제 솔잎·같은 유한 장작불의200턴 끓이기·300+300+300+100ml 비례 영양/같은 빈 물병·신선6시간·각인v72를 연결했다. 전체110파일1,901개110.81초·전용25개/최종 관련149개·타입/린트/Def104패치/Schema95/빌드·화면470~476/7장 전체 확인과 타이틀483·5전체 복원·콘솔 오류0이다. 같은 검증 코어의 월드30시드×최대3일332.571246477초·30개 전체 행이 이전과 같다. 처음 전체 검사에서 새 차의 고정 용량 검증이 기존600ml 물병 모드를 거절한 부분을 실제 원래 물/결과 용량 상한 확인으로 고쳤다. 최종 관련149검사와 실제로 켠600ml/1200ml 모드는 각각 솔잎2묶음/600ml 조리와 원자적 거절을 확인했다. 브라우저에서 발견한 검증용 품질73(유효 범위0~5)을3으로 고치고, 초기 몸은 실제 대기 행동으로 정산한 뒤 조리를 시작했다. 실제 저장 재개는200턴 경과와 원래4묶음/1L를 한 번만 소비하며 전체 영속 상태가 같다. 음식 화면의 긴 분수 표시도 실제ml로 고쳤다. 최종 코어/도구는 전체 검사를 통과한 사본과 SHA-256이 같고 전체 manifest도 확인했다.
