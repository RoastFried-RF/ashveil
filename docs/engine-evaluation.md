# 엔진 적합성 평가 — 2026-10-17

현재는 **TypeScript 코어 + Vue 3 + PixiJS 8을 유지**한다. 사용자가 허용한 엔진 교체도 검토했지만, 현재 확인한 문제에 대해 전체 이전이 유리하다는 근거는 없다. 이는 장기적으로 이전하지 않겠다는 결정은 아니다.

## 실행 근거

환경: Node 24.19.0, 논리 CPU 5개. `pnpm exec tsx tools/benchmark.ts`로 서로 다른 시드 12개의 실제 지도·생물·봇을 사용했다. CPU 측정은 v0.14의 최종 규칙·봇을 사용한다. 원자료는 performance-latest.json이다. 서로 다른 하드웨어의 결과와 직접 비교하지 않는다.

| 작업 | 표본 | 중앙값 | 95백분위 | 최대 |
|---|---:|---:|---:|---:|
| 새 게임 | 12 | 3.423ms | 11.932ms | 11.932ms |
| 지하 1층 생성·진입 | 12 | 1.642ms | 5.776ms | 5.776ms |
| 봇 판단 + 실제 행동·자동 진행 | 2,559 | 1.873ms | 105.513ms | 1402.270ms |
| 저장 직렬화 | 12 | 3.374ms | 3.753ms | 3.753ms |

최대 저장 크기는 415,249바이트다. 행동 표본에는 대기·이동·전투·다턴 활동이 섞여 있다. 최대치는 한 턴의 비용이 아니라 자동 진행 전체일 수 있다.

브라우저는 Chromium + SwiftShader, 1440×900, 새 게임 직후 안정화 후 115개 프레임 간격을 측정했다. 중앙값 100ms, 95백분위 133.3ms다. **소프트웨어 GPU에서 약 10fps**이므로 이 수치를 일반 PC의 GPU 성능으로 해석하지 않는다. 같은 조건에서 바닥·벽을 텍스처로 캐시해도 중앙값 100ms, 95백분위 133.4ms로 개선되지 않아 해당 실험은 최종 코드에서 제거했다. 최종 브라우저 회귀는 4개 시뮬 워커와 동시에 실행해 중앙값 233.4ms·95백분위 300.1ms였으며, 위 유휴 측정과 직접 비교하지 않는다. 브라우저 검증은 실제 던전 진입·교전과 일지 표시도 확인했고 콘솔 오류는 없었다.

긴 자동 진행에는 화면이 200행동씩 계산하고 제어를 돌려주는 경로를 추가했다. 분할 예산 1·17·일괄 계산의 결과 일치와 진행 중 저장 복원을 검증한다. 입력 대기점에 닿기 전 새 게임 행동은 거부하며 창은 계속 열 수 있다. 이 변경을 최대 CPU 작업 시간 자체가 줄었다는 뜻으로 해석하지 않는다.

## 다시 판단할 조건

1. 실제 GPU에서도 목표 화면 크기의 프레임 예산을 지속적으로 초과하고 Pixi 프로파일러로 원인이 확인될 때.
2. 워커 또는 분할 진행 이후에도 목표 월드 규모의 턴 계산이 예산을 넘을 때.
3. 플랫폼 SDK·입력·접근성·배포 요구가 현재 클라이언트로 충족되지 않을 때.

그때 같은 장면·같은 콘텐츠·같은 장치로 작은 비교 구현을 측정한 뒤 이전한다. 새로운 엔진 이름만으로 이득을 추정하지 않는다.

## v0.64 현재 코드 재측정

동일 환경의 고정 소스/빌드에서 다른 브라우저·시뮬레이션 없이 같은12시드를 재측정했다(`performance-v064.json`). 새 게임 중앙값4.36ms/95백분위24.538ms, 던전 생성 중앙값2.127ms/95백분위7.383ms다. 봇 판단+실제 행동/자동 진행2835표본 중앙값2.666ms/95백분위115.268ms/최대255.298ms이며 최대는 다턴 자동 진행 전체를 포함한다. 직렬화 중앙값2.718ms, 최대 저장440,987바이트다. 동작 거부3회와 사망1판도 원자료에 남겼다. 이 실행은 단일 지역/던전 코어 측정이고 월드 경제·브라우저 GPU 성능의 재측정은 아니다.

현재 변경에서 엔진 교체가 유리하다는 추가 근거는 발견하지 못해 기존 코어/Vue/Pixi 구성을 유지한다. 호송의 문제는 같은 인물·물품/손·다음 차례와 도착 공간 검증으로 해결했고, 기존5개 리플레이의 전체 초기/최종 상태는 저장 버전만 변경됐다.
