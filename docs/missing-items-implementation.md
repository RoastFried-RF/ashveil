# 원래 크기와 상태를 보존하는 없어진 물품

v0.249 통합 검증 완료, 각인180/API1.4.0. 새 게임은 실제191개 Item의 원래 칸 크기·더미 상한·이름 목록을 기록한다.179→180은 버전만 바꾸고 과거 크기를 추정하지 않는다. 기록된 해시가 현재 해시와 같을 때만 검증된 같은 구성의 크기 목록을 보강한다.

원래 ID/종류와 크기가 기록된 Item이 현재 구성에서 사라졌다면, 타이틀 검토에서 보관할 더미 수를 보여 주고 명시 승인 후 같은 실제 인스턴스를 Item.MissingPlaceholder로 보관한다. UID·개수·배치·회전·원래 전체 ItemInst 상태를 보존하며 시간·난수·새 UID를 쓰지 않는다. 원래 물품은 설계13을 전부 읽고 등록한 뒤 새 Def로 추가했다. 현재 콘텐츠의 생성·재고·제작 참조는 이 보관물을 사용할 수 없고 새 보관물을 makeItem으로 만들 수도 없다. 기본 게임에 생성하지 않으며 기존 note 그림을 사용한다.

보관물의 칸은 기록한 원래 크기를 쓰고 회전도 그대로 적용한다. 다른 보관물과 합치거나 나누지 않으며 이동·바닥 놓기·통째 보관함 이전만 제공한다. 사용·장착·거래·수리 등의 행동은 자원/시간을 쓰기 전에 거절한다. 원래 재료·품질·음식·빛·도구 속성을 재적용하지 않는다. 음식·장비 시간 정산도 보관 중 원본을 바꾸지 않는다. 툴팁은 원래 ID·크기·개수와 복원 조건을 보여 준다.

원래 Item 정의가 같은 칸 크기로 돌아오면 재검토 후 같은 UID의 원래 상태를 복원하되 보관 중 실제로 옮긴 위치/회전은 유지한다. 변환과 복원은 먼저 모든 물품을 검사한 뒤 한 번에 반영한다. 한 물품의 기록이 잘못돼도 앞 물품만 부분 변환하지 않는다. 원래 크기/정의 기록 없음, 손상된 원본/개수/UID, 종류 변경, 돌아온 정의의 크기 변경은 거절한다. 빠른 슬롯·제작 참조·진행 중 작업의 같은 UID 등 물품 밖의 참조가 남아도 임의로 고치지 않는다. 설치된 의수족과 선체는 별도 기능 상태를 안전하게 복구하는 작업이 필요해 원래 구성 복원을 요구한다.

실제 바닥·보관함·인물 배낭·지도/장면 등의 물품 인스턴스를 순회한다. 스크립트 상태·지식·이력·사망 보고서와 보관 원본은 물리 물품으로 세지 않는다. CraftBatch.processing.inputs의 uid/def/count는 차감 참조이므로 실제 물품으로 중복 계산하지 않으며 남은 참조로 차단한다.

전용34개(순수20·저장 위치/거래/생성7·실제 승인/저장/재설치7)와 구성/스키마/저장/골든을 포함한11파일119개가 통과했다. 실제 기존 정착지 상인에 접근한 거래/교환은 원문 전체를 보존하며 거절한다. 실제 이전 패키지에서 생성한 Item.Jerky 파생2×3 시험용 물품을 현재 패키지로 보관하고 원래 패키지로 다시 불러와 원본 복원을 확인했다. 시험용 ID는 메모리 fixture에만 있고 실제 등록 물품은 보관물 하나다. 원래 새 게임의 인물과 몸은 유지한다. 초기 물품의 품질·내구도·오염·젖음은 명시한 초기 조건이며 과거 플레이 결과로 주장하지 않는다.

5개 골든의 전체 초기·최종·오류를248과 대조했다. 차이는179→180, 실제 새 보관물 Def에 따른 콘텐츠 해시, 정의 목록의 새 Item 한 개, 실제 해석된191개 Item 크기/상한/이름 목록뿐이다. 물리 상태·시간·UID·난수·명령·오류는 모두 같다.248 원본 벡터는 한 번 보관하고 기대 해시 두 필드만 바꿨다.

브라우저 실제 검토/승인·툴팁/원래 크기·동작 메뉴·실제 배낭 회전 끌기·전체180 저장 복원·원래 크기 없음 차단을 준비했다. 최종 정적 검사/빌드·브라우저·전체 회귀/월드 검증은 진행 중이다. 현재 패키지 목록이 바뀌는 모드 제거 선택 UI, 다른 종류 Def 제거, rename, 설치 의수족/선체/진행 중 참조의 개별 마이그레이션은 계속 남는다. 일반 모드 제거가 전부 완성됐다고 주장하지 않는다.

첫 실제 화면에서 보관물 툴팁에 일반 물품의 사용 안내가 붙는 문제를 확인해 보관/이동/회전 안내로 고쳤다. 실제 드래그/전체 상태 검사는 통과했지만 처음 E2E의 복원 대기는 큰 각인도 localStorage 본문에 들어간다고 가정해 시간 초과했다. 큰 저장은 IndexedDB에 들어가므로 실제 타이틀 저장 완료 후 다시 불러오는 정상 경로로 검사를 수정했다. 원래 실패 증거는 보존한다.

최종249-final의 타입·린트·Vite 빌드를 통과했다. 실제1241–1245 다섯 장 모두 확인했고 검토 전 원문 유지·같은 UID의 원래2×3 크기/개수·통째 이동 메뉴·실제3×2 회전 끌기·전체180복원1·원래 크기 없음 차단과 콘솔0을 확인했다. 전체 회귀/월드30판은 실행 중이다. 앞의 관련119개는 실제11파일이며 별도 world-golden.test.ts 파일 실행을 주장하지 않는다. 기존 golden.test.ts 한 파일이5벡터의 고정 재생/중간 복원10개를 모두 실행한다.
