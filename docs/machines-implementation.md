# 기계형 신체와 실제 정비

구현 v0.80 / 각인 v44. 전체 로드맵은 계속 진행 중이다. 전체82파일1,345개53.48초와 브라우저 실제55턴 정비/전체 각인 복원을 확인했다. 동일 월드 설정30시드×최대3일209.594280383초 검증을 마쳤다. 평균0.4150173611111112일, 저체온18·치명상6·과다 출혈6이며30개 전체 최종 결과 행이v0.79와 동일하다.

설계 우선순위는 `CANON.md` → `design/02-body-and-health.md` §15 → `design/04-psyche.md` §14 → `lore/bestiary.md` §0.3·§4다. 4족 기본 기계형과 6족 수리 드론을 분리했다. 수리 드론은 후속 확장 콘텐츠로 옛 착륙장에 배치하며 잿빛 수도원의 프로토타입 출현 목록을 바꾸지 않는다.

기계는 800ml 냉각액·열·전원과 실제 부위 손상을 각인에 보존한다. 섀시/냉각 루프 천공은 심각도×0.8ml/턴 누출하며 응고·휴식·붕대로 멎지 않는다. 균열은 낮은 심각도, 변형은 자연 회복하지 않는 기능 상한, 화상은 열을 남긴다. 센서·구동 다리·매니퓰레이터·공구·전원셀·코어가 각 기능에 영향을 준다. 기계에 혈액·배고픔·수면 부채·질병·약물·기분·유기체의 체온 사망 규칙을 적용하지 않는다. 기계 사체에서 피·고기·뼈를 만들지 않으며 유기체의 사체 제거 시한으로 잔해를 없애지 않는다.

이동/공격/용접의 열은 1/3/8이다. 냉각은 4×냉각액 비율×냉각 루프 효율−max(0,기온−20)/10이며 70 이상 보호 모드, 90 이상 셧다운 판정, 100에서 코어 2 심각도/턴이다. 손상된 섀시가 물에 잠기면 턴당 1% 단락 판정을 한다. 낮은 경계의 드론은 먼저 공격하지 않고 실제 공격자에게 반격한다. 동료 기계의 남은 현물 잔해가 교전보다 우선하며 같은 UID를 둥지까지 나른다. 전원 30% 미만/체력 40% 이하에서 귀소하며, 둥지의 부품도 실제 바닥에서 인출해야 쓸 수 있다. 물을 피하는 경로를 사용하고 센서 파괴 시 시각을 잃는다. 들은 소리는 기존 경로 비용·문/벽·주변 소음·청각 규칙을 쓴다.

정비 대상·부위·천공·소모품 UID·도구 UID를 채널에 묶는다. 대상 접근/시선·상태와 원래 부품·도구를 매 단계 확인하고 마지막 단계에서 한 개만 소비한다. 같은 종류의 다른 UID로 대신하거나 파괴된 코어를 되살릴 수 없다. 중단하면 소모 없이 채널을 취소한다. 진행 중인 채널의 전체 각인은 남은 시간을 보존한다. 드론의 정상 공구 헤드는 자기 정비 도구로 쓸 수 있지만 교체 부품은 여전히 소비한다. 밀봉 패치는 천2개·밀랍1개·바늘과 실제 노동으로 만든다. 전원셀·구동기는 제작하지 않고 생성 때 기계 안에 배정된 유한한 원본 부품을 회수한다.

드론의 봉인 부품은 생성 때 실제 ItemInst/UID로 정하며 사망 때 같은 물품을 사체 배낭으로 한 번 옮긴다. 기본 고철/구동기/냉각액 각1, 용접 노즐 15%, 전원셀 10%다. 도감 분해의 추가 산출은 비어 있어 반복 분해로 부품을 만들 수 없다. 절단 집게는 접촉한 실제 방어구 부위 내구를 깎으며 용접 모드는 1 화상/대상 기계 열+20을 사용한다.

F2 하단에서 보이는 곁의 기계를 정비할 수 있다. 압력·누출·열·전원·부위 손상과 실제 필요한 소모품을 표시한다. 비활성 상태는 별도 원본 타일로 그린다. RLTiles 원본 public domain 고지/출처/해시는 `CREDITS.md`와 `public/sprites/LICENSE-RLTiles.txt`에 보존했다.

설계에 없는 수치의 현재 기본값은 콘텐츠 설정에 둔다. 전력 소비는 행동 0.1%/턴 대기 0.0001%, 90열 셧다운 확률 20%/2~4턴, 누적 손상 25%부터 20턴 간격 15%의 오류 루프 판정/20턴 반복, 절단의 추가 방어구 손실 5%p다. 정본의 미확정 설정을 확정한 것으로 간주하지 않는다. 다른 지역의 기계/종자 금고·기계 통신 제어·일반 유기체 사체 해체 노동·전역 정원사 보급망은 이후 작업이다.

기존 5개 고정 입력의 전체 초기/최종 상태를 v0.79와 비교했다. 저장 버전 43→44 외 모든 상태와 성공·실패 결과가 동일하다. `golden-v080-diff.json`과 원본 전체 상태 기록을 보존한다.
