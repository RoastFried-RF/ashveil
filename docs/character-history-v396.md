# v396 사용하지 않는 옛 캐릭터 원화의 선택 로딩

메모리 감사에서 과거 캐릭터가 교체된 뒤에도 옛 시트가 공통 지형으로 분류되어 모든 지도에서 디코딩되는 것을 발견했다. 보존된 네 역사적 registry의 실제 캐릭터 프레임/PNG 경로를 대조하고 같은 원문 바이트만 분류 근거로 등록했다.26개였던 역사적 캐릭터 소스 분류는223개가 된다. 새 분류197개 중 현재 캐릭터가 선택해 쓰는 원문도 있으므로197장 전체가 삭제/비활성화되었다고 세지 않는다.

변경한 registry 필드는 `characterSheetHistory` 하나다. 모든 PNG/프레임 사각형/캐릭터 정의는 그대로다. 현재 몸의 실제 모든 단계와 아이콘, 옛 저장/모드가 명시적으로 요청한 프레임은 계속 로딩한다. 원문/역사적 registry SHA와 정확한 캐릭터 참조 증거는 [등록 감사](../tools/art/direction-v396/history-audit.json)에 보존했다. 설치 도구는 원문 SHA/사각형을 다시 검사하며 픽셀을 편집하지 않는다.

- 일반 인간 실제 장면:202→109시트, 디코딩 추정259,764,480→219,439,360바이트.93장/40,325,120바이트(약38.5MiB)를 줄였다.
- 옛 프레임을 명시한 드론과 현재 인간·측량기 장면:210→118시트/310,084,992→269,809,024바이트. 옛 드론 시트 한 장은 실제 선택했으므로 유지한다.
- 계단 아래의 현재 까마귀 장면:212→119시트/322,665,120→282,340,000바이트. 원래 지도로 돌아와 옛 프레임을 재로딩하고 타이틀 이탈 때 소유 시트를 모두 해제했다.
- 두 화면의 변경 전12/변경 후12전체 상태 쌍이 각각 독립 Node와 같고, 대응하는 실제 전체 세계12쌍도 모두 같다. 별도 실제 UI 설치/분리6쌍은109→110→109시트/원래 UID66·수량1/저장 복원을 보존했다. 변경 후 수락18쌍과 이전 기준12쌍을 구분한다.
- 국소9파일77검사, 타입/린트/빌드와401시트/8,469프레임/427고유 PNG 검사를 통과했다. Core/콘텐츠/모드/기대 fixture1,074파일은 v395와 바이트가 같다. 전체 회귀는 최종 게시 CI에서 별도 기록한다.

초기 테스트의 임의 ‘첫 옛 프레임’이 현재 캐릭터 이름과 겹쳤다. 캐릭터 이름은 현재 몸을 우선하는 기존 규칙이므로 테스트를 명시적인 옛 프레임 이름으로 고쳤다. 그 실패도 보존하며 런타임 우선순위를 바꾸지 않았다. 선택한 현재/옛 몸의 지상 화면과 까마귀 지하 화면을 직접 열어 보았다. 낮은 해상도의 옛 드론은 호환 검사 전용 fixture이며 정상 현재 모델로 새로 채택하지 않는다.

수치는 원문 PNG의 폭×높이×4 추정이며 CSS 복사/GPU 오버헤드/실제 RAM·최저사양을 보증하지 않는다. 새 World30/1,000판·사람 평가로 세지 않는다. [검증/게시 상태](release-v396-proof.json). 전체 디버그 세계는 로컬 검증 자료로만 보존한다.

## 로딩 중에도 창 닫기

장소 진입 검사에서 원화를 읽는 동안 Escape까지 무시되어 지도 창이 남는 것을 관찰했다. 세계 행동을 막는 경계와 화면 창/대상 취소를 나눴다. Escape는 상단 창·대상 지정을 즉시 닫고, 로딩 중 대기/이동/세계 행동은 계속 차단한다.

실제 필요한 드론 PNG 요청 하나를 보류한 기준 빌드에서는 창이 닫히지 않았다. 수정 고정본 `v396-history-ui-r2`에서는 세 화면 모두 즉시 닫혔고, Escape/대기/이동 전후의 전체 세계가 그대로였다. 해제 후 실제 한 턴과 타이틀 복원12전체 상태 쌍도 독립 Node와 같았다. 기준4쌍과 수정12쌍을 구분한다. 첫 장소 검사8성공 비교 뒤의 시간 초과는 보존했다. 이후 전수 도구도 새 지도 준비를 확인한 다음 화면을 촬영하도록 고쳤다.

고정17장소와 생성 정착지24곳,41곳×3화면의 진입·한 턴·각인 검사123장면/615독립 전체 상태 비교를 통과했다. 수정 전후 실제 전체 세계615쌍은 바이트까지 같다. 이는 모든 실내 동선·자연 여행·사람 평가를 대신하지 않는다.

## 작은 화면의 주인공 가림 수정

초기123장면 검사에서 로그 창이 좁은 화면의 주인공을 가리는 실제 화면 결함을 찾았다.999px 이하에서는 최근 기록 한 줄과 펼침/접기를 제공하고 측정한 로그 높이를 카메라 여백에 반영한다.680px 이하의 생존 지표는 모든8개 수치를 유지하며 폭을 줄였다. Shift+L로 기록을 읽고 다시 접을 수 있고 큰 글꼴·음성 조작·자동 배율도 유지한다. 시야 범위와 세계 시간은 바꾸지 않는다.

최종 고정본은 `v396-mobile-r4`다.9가지 화면/설정의41전체 비교와 실제 클릭/키/크기 변경을 통과했고, 최종41곳×3화면에서도 좁은 화면의 몸 위치가 지도에 노출되는 것을 검사했다. 직접 연 선택 화면은 지상/지하·1366/390로딩,360기본·390큰 글꼴·681기본,1440관로/낙하구/첫불/갈래길과390갈래길이다. 모든123이미지를 사람이 평가했다고 세지 않는다.

검사 도구의 첫 좁은 화면 시도는 접힌 도구막대 아래에 남은 포인터가 상태 표시의 정상 도움말을 띄워 실패했다. 실제 타이틀 버튼으로 포인터를 옮긴 뒤 재검사했으며 실패 자료도 보존했다. 기존 세 결말18검사와 개인 근거 기반 탐구7검사를 추가해 미완료·타인·미래·부분/오독 기록과 잠듦·구속·위험·저장/중복 종결 경계를 검사했다. 이는 별도 실제 결말 UI 검사의 대체가 아니다.
