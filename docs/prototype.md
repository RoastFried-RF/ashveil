# 프로토타입 v0.1 — 구현 현황과 기획과의 차이

| 항목 | 내용 |
|---|---|
| 작성 | 2026-10-13 16:47 KST |
| 목적 | "Stoneshard의 하드코어 × RimWorld의 랜덤·확장성"이 **재미의 씨앗**을 갖는지 확인 |
| 범위 | 폐허 외곽 로컬 맵 1장, 1인 주인공, 재늑대·약탈자·굴쥐 |
| 엔진 | 순수 TypeScript 코어 + JSON Def + Vue 3/PixiJS 클라이언트 (이전 가능 구조) |

> 기획 문서(design/, lore/)는 **목표 사양**이고, 이 문서는 **지금 코드가 실제로 하는 것**이다. 수치가 다르면 코드가 현재 사실이고, 기획 문서가 지향점이다. 정합 작업은 §5 목록을 따른다.

## 1. 실행

```bash
pnpm install
pnpm dev                # http://localhost:5173 — 브라우저에서 플레이
pnpm test               # 단위·속성·결정론 테스트 (vitest)
pnpm lint               # ESLint Flat (코어는 Math.random·초월함수 금지 규칙 포함)
pnpm validate-defs      # Def 검증 CLI (모드 id 를 인자로 주면 함께 검증)
pnpm sim 30 3           # 헤드리스 봇 30판 × 최대 3일 → 사망 원인 분포
pnpm build && node --import tsx tests/e2e/smoke.ts test-results   # 브라우저 스모크 + 스크린샷
```

`?debug` 쿼리로 열면 `window.__ashveil.botSteps(n)` 로 봇이 대신 플레이한다 (E2E·관찰용).

### 2.2 클라이언트 (src/client)

- Pixi 맵: 타일/피/아이템/생물(시체는 눕혀서 붉게, 방향 점 표시)/어둠·기억 안개/재비 애니메이션.
- 우측 패널: 상태(시계·날씨·기온·체온·단열·젖음·욕구 막대·기분과 사고·능력치·숙련), 신체(혈액 막대와 임계선, 출혈 ml/턴, "쇼크까지 ~N턴", 기능 능력치, 상처별 처치 버튼), 소지품(장착·사용·감별·던지기·물 채우기), 지식(알약·도감).
- 하단 로그: 판정 단계 펼치기(▸), 한국어 조사 자동 교정.
- 호버 정보: 지형·밝기·핏자국·물건, 적의 **관찰 가능한 상태**(절뚝임·출혈·창백함), 명중률 + Shift로 공식 전개.
- 키: 이동 8방향(방향키/hjklyubn/숫자패드), `.` 대기, `r`/`R` 휴식, `z` 수면, `g` 줍기, `s` 수색, `t` 등불, `f` 활(Tab 대상 변경), `L` 탈출, `1~4` 패널, `?` 도움말.
- 타이틀: 시드, 배경 선택, 모드 토글, 각인 이어하기, 연대기(지난 떠돌이 50명).

## 4. 밸런스 현황 (봇 기준, 솔직한 평가)

봇은 전술이 없다(정면 돌격, 문·지형 미활용, 전투 중 후퇴 안 함). 그래서 실제 사람보다 훨씬 빨리 죽는다. 그래도 **어떤 원인이 지배적인지**는 보여준다.

`pnpm sim 30 3` 결과는 [sim-latest.txt](sim-latest.txt) 참고. 요약:

- 2026-10-13 측정(30판 × 최대 3일): **평균 생존 0.52일, 몸통 파괴 53% · 과다 출혈 43% · 탈수 3%, 탈출 0/30**. 최장 생존 1.16일(탈영 경비병, 사건 12회).
- 조정 이력: 굴쥐 회피 과다(명중 5%) → 회피 공식 완화 / 작은 상처 출혈 과다 → 크기계수 도입 / 잔상처 누적으로 다리 절단 → 절단은 단일 큰 베기·물기만 / 재늑대 명중 80% → 숙련 하향 / 사건 과다 → 유예·간격 확대.
- 남은 과제: ① 쓰러진 대상에 대한 무한 공격(짐승은 쓰러진 먹이를 끌고 가거나 먹기 시작해야 자연스러움) ② 몸통 누적 파괴 빈도 ③ 봇에 후퇴·문 닫기·좁은 통로 전술 추가 후 재측정.

## 6. 엔진 이전을 고려한 구조 (D6)

- **그대로 가져갈 것**: `src/content/**/*.json`(모든 콘텐츠), `mods/`, `docs/`, 그리고 `src/core`의 규칙(필요하면 C#/GDScript로 포팅할 레퍼런스 구현 + 테스트 벡터).
- 코어는 DOM·Pixi·Vue를 전혀 import하지 않는다. 렌더러는 `World` 상태를 읽기만 한다.
- 결정론 테스트(`tests/determinism.test.ts`)가 포팅 검증의 기준이 된다: 같은 시드·같은 입력에서 상태가 같아야 한다.
- Steam 출시 경로(웹 유지 시): Electron + steamworks.js. Tauri는 WebView2에서 Steam 오버레이 문제가 보고되어 보류.

## 7. 다음 단계 제안 (우선순위순)

1. **사람이 직접 플레이해 보고** "죽을 때 납득되는가"를 확인 — 가장 중요한 검증.
2. 짐승 AI: 쓰러진 먹이를 끌고 가기/먹기, 배부르면 이탈 → 무한 공격 문제 해결 + "생고기로 시간 벌기" 전술 강화.
3. 02 출혈 모델·07 정수 판정 이식, 05 숙련 척도 확정.
4. 모닥불(체온·조리·연기·빛), 끓인 물, 요리 → 생존 루프 완성.
5. 계절과 날짜 진행, 지역 2~3개 연결(월드맵 압축 시간).
6. 동료 1명(D1 확장 단계) — 관계·명령 최소 구현.
