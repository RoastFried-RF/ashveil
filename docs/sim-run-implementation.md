# 시드/모드/기간 지정 헤드리스 실행 — v0.269

설계11 §9의 ashveil-sim run을 `pnpm sim:run run --seed <시드> --mods id ... --days <일수> --bots N`에 연결했다. 기본은 월드이며 --dungeon/--world, --background, --storyteller, --reroll0/1, --json, --out 파일.json을 지원한다. 기존 sim/sim-batch는 바꾸지 않았다. 실제 모드 로더/선택 순서/버전/원문 해시와 QuickJS 등록 검사를 거친 DB로 실제 newGame/botDecide/playerAct를 실행한다. 한 봇은 원래 시드를 그대로 사용하며 여러 봇은 시드:0, 시드:1 …을 사용한다.

1TU 이상의 지정 기간을 종료 TU로 변환해 코어 행동에 전달한다. 긴 자동 활동도 종료 시각에서 자르며150000개 결정 상한을 넘기면 실패하고 생존으로 집계하지 않는다. 봇1~1000과 실제 양의 기간/유일한 모드/생성 입력을 검사한다. 보고서는 실제 게임/정의 계약·모드별/전체 내용 해시, 초기/최종 상태 해시, 원래 시드/배경/맵/레벨·사인/경과 시간/정확한 종료 TU·결정 횟수, 실행 중 관찰한 Storyteller 사건 기록, 스크립트 오류/비활성 상태를 담는다. 보고서에 실행 벽시계 시간을 넣지 않아 같은 실행 결과 전체를 직접 비교할 수 있다. 파일 출력은 기존 보고서를 덮지 않는다.

최종 전용2파일16개가 통과했다. 실제 초기 엔진 해시·288TU 중간 종료·반복 결과 전체 일치·여러 봇과 같은 개별 시드 결과 전체 일치·실제 모드 내용·직접 CLI JSON/파일/사람용/실패 종료·기존 파일 보존을 검사했다. 첫 스크립트 오류 시험은 짧은 기간에 일일 훅이 호출되지 않아15/16이었고 실제 새 게임에서 호출하는 지도 워커로 고쳤다. 이어 기존 VM의 진단이 게스트의 원래 메시지를 그대로 내보내지 않는 정책을 확인해 실제 한국어 진단/정확한 워커 호출 ID/비활성 ID 보존으로 검증했다. 제품의 VM 동작은 바꾸지 않았다. 첫 린트의 Error cause 누락은 실제 원인을 보존하도록 수정했다. 초기 bad-args 테이블도 각 배열 전체를 전달하도록 고친 뒤 전 입력을 실제 검증했다.
