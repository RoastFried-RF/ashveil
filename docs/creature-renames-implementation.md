# 같은 실제 개체와 현재 종별 기록의 ID 이행

v0.263 작업 중, 각인182/API1.4.0. 실제 이전 정의 목록과 현재 rename이 같은 Creature로 연결될 때 현재 개체의 식별을 같은 실제 몸/번호로 옮긴다. 목적지 Creature의 body가 원래 BodyState.def와 같고 현재 몸 정의의 부위 ID 집합이 저장된 maxHp 키 집합과 같아야 한다. 다른 몸/부위를 재생성하거나 없는 부위를 채우지 않고 별도 해부학 이행을 요구한다. 같은 몸 ID의 수치/부모 구조 전체가 과거와 같다고 추정하는 검사는 아니다.

활성/다른 층/정지 지역의 실제 개체와 공급원 species/needsAlive·저장된 방 residents 참조를 옮기되 원래 몸/HP/혈액/상처·번호/소지품/이름/관계/진행·인구 수/명단/미래 슬롯·시각/UID/난수는 보존한다. 현재 공포 대상/극복 대상·수확 나머지 키와 플레이어/NPC의 종별 지식 키/실제 표본 Creature ID도 같은 식별로 옮긴다. 표본의 관찰된 혈액/부위 HP나 지식 수치를 현재 Def 값으로 다시 쓰지 않는다. 원래 표본 def는 Body ID가 아닌 Creature ID임을 실제 bestiary 소스에서 확인했다.

현재 지식/수확 나머지 키와 공포 대상/극복이 겹치면 임의 병합하지 않고 전체 승인을 막는다. 과거 개인/정신 기록·공격자/사망 원인·상처/흉터/질병의 원인과 다른 역사적 지식은 보존한다. 남는 임의 JSON/기타 살아 있는 값·키는 의미를 추정해 고치지 않는다. 타입 변경/출처 없는 이행도 기존 원문/현재 DB 토큰의 원자적 검사로 보호한다. 개체 제거는 이 기능과 별개다.

실제 기본 비활성 sample-creature-renames1.0은 코어 Creature.BurrowRat와 BestiaryEntry.Rat를 상속한 비물품 두 정의와 ID맵을 제공한다. 이전0.9는 원래 Creature ID/도감 연결을 실제 로드한 정상 새 게임에 실제 createCreature로 선언된 초기 개체 한 마리를 빈 현재 관찰 칸에 배치하고 정상 시야/observeBestiary(false) 현재 관찰만 호출한다. 과거 출생/전투/경과 턴을 실행한 이력으로 꾸미지 않는다. 몸 불일치 시험은 원래 Def의 몸을 실제 인간형 Body로 바꾼 뒤 생성하며 생성된 몸 상태를 직접 편집하지 않는다. 배포4파일1177바이트·277패치/경고0·SHA256 8a97881f16bd44d4f4b0a978937a879e489d9d5095634b126bba03e3ca17f2fe를 확인했다. 새 Item은 없다.
