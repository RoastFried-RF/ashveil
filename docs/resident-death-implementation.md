# 주민 사망·시체 개인 소지금 — v0.54

실제 주민이 죽은 뒤 정착지의 생존 인구와 소비가 그대로였고, 개인 지갑에 받은 진료비/숙박비/수업료는 시체 소지품 창에서 회수할 수 없었다. 사망 훅·인구 한도·개인 동전 이동을 연결한다. 정본은 design/09 §8의 `S+I+R+사망=N`, design/13 §8의 실제 소지품 수색·전투 중 이동 시간이다.

## 사망과 인구

`killCreature`의 실제 사망 뒤 현재 정착지·같은 세력 주민만 처리한다. 임상 회색열/면역에 따라 가능한 I/R, 그렇지 않으면 S에서 한 명을 사망자로 옮긴다. 구획이 임상 상태와 맞지 않으면 남아 있는 구획에서 옮겨 음수를 막는다. 조사 인구 `total`은 사망자를 포함하므로 줄이지 않는다. 개체 ID 원장은 반복 사망 호출·각인 복원 뒤 재호출을 한 번으로 제한한다. 이미 생존 인구가 0이면 추가 사망으로 세지 않는다.

당일 그 주민의 실제 식사/끓이기 때문에 기록했던 공공 소비 공제만 거둔다. 자정 요약 소비가 사망자를 제외하는데 그 사람의 공제까지 살아 있는 다른 주민에게 적용하던 중복 차감을 막는다. 개인의 실제 사용 이력과 지난 날 정산은 보존한다. 봉쇄 변화는 기존 06:00/지역 진입 반영 규칙을 사용한다.

첫 방문의 실물 주민과 구형 지역에 추가하는 의사는 남은 `S+I+R` 범위에서 생성한다. 죽은 의사가 남은 구형 지도는 초기화 표식이 없어도 시체에 무료 진료 물품을 다시 공급하지 않는다.

이 단계는 요약 구획과 모든 임상 개체의 완전한 일대일 대응, 모든 역병·출생·이주·비활성 지역의 개별 생애를 구현하지 않는다. 고정 생산량의 노동 인구 비례화도 이 변경의 범위가 아니다.

## 개인 동전

실제로 죽고 수색한 인접 시체의 개인 `money`만 플레이어 지갑으로 옮긴다. 살아 있는 상대·미수색/다른 시체·시야 차단·막힌 대각선·부족한 손/의식·바뀐 금액·비정상 정수/합계 초과는 거부한다. 견적은 읽기 전용이며 미수색/원거리 상대의 금액을 노출하지 않는다. 가방이 꽉 차도 지갑은 별도라 동전을 가져갈 수 있고, ‘모두 가져가기’와 봇도 돈만 남은 시체를 처리한다. 적이 플레이어를 인식한 동안은 기존 1턴, 그 외는 0턴이다.

I창은 현재 지갑과 수색한 시체의 남은 동전/회수 버튼을 표시한다. 시장 공금과 NPC 개인 지갑은 별개다. 동전 이동은 아이템·UID·난수·시장 돈을 생성하거나 변경하지 않는다. 상속·도난/범죄 체계·화폐 무게는 별도 후속이다.

## 저장·검증

각인 v21은 v20의 실제 개체/인구/지갑을 그대로 보존한다. 로드 시 과거 사망을 새로 추론하거나 돈을 만들지 않는다. 기존 골든 5개 명령·오류는 보존했고 전체 초기/최종 상태 차이는 저장 버전 20→21뿐이다. `golden-v054-diff.json`에 비교를 기록했다.

`resident-death.test.ts` 12개와 `corpse-money.test.ts` 13개는 구획·당일 소비/자정 정산·생존 한도·시체 물품·수색·전투 시간·동전 보존·중복/오래된 요청·각인 복원을 검증한다. 동전만 있는 시체의 수색 테스트는 실제 조명을 설치한 상태에서 기본 2턴을 검증한다. 어둠에서 3턴이 되는 기존 행동 시간 배율은 유지했다.

전체 54파일 835개 테스트가 30.00초에 통과했고 lint·vue-tsc·배포 빌드·Def·JSON Schema 50파일 검증 오류는 0개다. 병렬 브라우저/시뮬 실행 중 기존 긴 생활 테스트가 5초 제한에 걸려, 다른 실행과 분리한 고정 소스 전체 검사로 확인했다.

브라우저 mortality 구간과 설정 회귀의 콘솔 오류는 0개다. 실제 진찰로 지급한 6표가 의사의 개인 지갑→실제 사망/인구 원장→수색→지갑 94→100표/시체 0표로 이어지고, TU·UID·난수·시장 공금 보존 및 전체 각인 복원을 확인했다. 화면116~118을 저장했고116을 시각 확인했다. 수색이 I창을 자동으로 여는 기존 동작에 맞춰 중복 I입력을 제거했다.
