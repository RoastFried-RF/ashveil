# 실제 필드별 출처와 resolve 조회

v0.242 작업 중. 각인177/API1.4.0 유지. 241의 원본 정의/성공 패치 목록에 더해 최종 필드가 온 원본 모드·파일·JSON 배열 항목·정의ID·원본 JSON Pointer 또는 패치 연산을 표시한다. Def 뷰어의 ‘필드별 출처’와 `pnpm --silent defs resolve <Def.Id> [modId ...] --json`에서 같은 실제 로더 결과를 사용한다. 사람용은 `pnpm defs resolve Terrain.KtFloor`로 확인한다. 스크립트 VM/게임 행동/파일 쓰기를 실행하지 않는다.

출처는 실제 deepMerge/applyPatch 연산과 함께 움직인다. 부모의 상속값은 부모 원본을, 자식 자신의 값은 자식을 가리킨다. 부모 패치가 자식 값에 가려졌으면 최종 출처로 선택하지 않는다. 같은 값을 다시 쓴 성공 패치는 마지막 지정 출처다. 배열 전체 교체·선택자 앞뒤 삽입/삭제·배열 병합의 prepend/remove/append 이후 실제 요소의 원래 위치를 보존한다. 값이 사라지면 최종 필드 목록에서도 사라진다. 패치 실패는 값과 출처 모두 원자적으로 버린다.

각 행의 path는 최종 해석값의 JSON Pointer, sourcePath는 원본 Def 또는 패치 객체 안의 JSON Pointer다. 패치 값은 /value 아래, 상속 배열 지시는 /extra/$append/... 같은 원래 경로를 보존한다. 항목은 파일의 JSON 배열을1부터 센 위치이며 소스 줄 번호가 아니다. 빈 객체/배열의 출처는 마지막 구성 연산을 가리킨다. 삭제된 값의 전체 연대기는 제공하지 않으며 성공 패치 목록과 구분한다. 기존 루트 merge의 Object.assign 보존 동작을 그대로 추적하고 규칙을 변경하지 않는다.

추적은 요청한 snapshot에만 붙으며 DB·실제 Def·패키지 직렬화·스크립트 설정 해시·GameState에는 넣지 않는다. 기존 기본 로더는 추적 트리를 만들지 않는다. CLI는 누락 정의/선택 모드/해석 오류/잘못된 옵션에 종료1을 반환한다. --json은 실제 CLI 출력 JSON이며 pnpm 배너 없는 파이프 사용에는 --silent를 쓴다. VM 실행 검증은 기존 validate-defs와 별도다.

전용 출처21개·실제 CLI5개와 조회/기존 병합·선택자·순서·Def까지7파일217개가 통과했다. 코어/선택 모드의 모든 최종 스칼라를 표시한 실제 원본 JSON 경로에서 다시 읽어 값까지 대조했다. 최초3실패는 테스트 준비 문제였다: 원시 부모에 없는 필드의 replace를 add로 수정, override가 의존하는 선택 모드도 명시, 실제 스크립트 게임 대조 전에 양쪽 격리 실행기를 준비했다. 초기 타입의 선택 결과 union과 병합 추적 임시 타입도 고쳤다. 생산 콘텐츠 수치·신체·시간 규칙은 바꾸지 않았다.
