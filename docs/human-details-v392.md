# v392 인체 세부 결손·변형 인간과 물품 경계 수정

개발 미리보기 `0.392-dev`. Core 게임 버전0.1.0·각인219·콘텐츠/모드 정의는 유지한다. 이 묶음의 완료를 전체 프로토타입/X1–X4 또는 v1.0.0 출시 완료로 세지 않는다.

## 수정한 동작

- 거절된 일반 투척이 장비를 가방으로 옮기거나, 묶음을 나누고 UID를 소비하던 결함을 재현했다. 좌표·범위·시야를 원래 물품 이동 전에 검사한다. 입은 의복은 기존 탈의 작업을 거쳐야 하며, 성공한 용기 전체 투척만 그 용기의 열린 소지품 문맥을 닫는다.
- 손 장비의 버리기/일반 투척이 기존 onUnequip 물품 작업자를 빠뜨리던 경계를 연결한다. 거절 때 작업자를 실행하지 않으며 성공 때 원래 UID의 장비 해제를 한 번 전달한다. 기존 의복 버리기는 기존 unequip/dropAfter 경로를 그대로 따른다.
- 빠른 사용이 접근 가능한 벨트 물품을 소비했지만 관찰자는 배낭/장비만 찾아 소품이 사라지던 결함을 수정한다. 선택적 관찰에서 기존 supplyItems를 사용하며, 반착용/파손 벨트의 내용물을 새로 공개하지 않는다.
- 도감의 큰 그림을 처음 확대하면 중앙에서 시작하며, 배율/화면 변경에도 이전에 보던 상대 위치를 보존한다. 실제 휠·방향키 스크롤을 유지한다. 인체 카드에는 현재 머리 원문과 해당 몸/얼굴이 선택된 실제 조립 작업대 링크를 제공한다.

## 실제 몸과 원화

일반 인간의20개 손가락/발가락 부위 및 보이는 눈·코·턱·귀 결손을 실제 body 상태에 연결한다. 부모 사지 결손과 실제 의수족이 우선하며, 정상 착용 장갑/신발 아래 피부 표시는 숨긴다. 겹친 결손은 마스크의 합집합을 뺀다. 절단으로 분리되는 원문 피부 조각을 알파 연결성으로 조사하고, 원래 원문 픽셀을 편집하지 않고 해당 표시 마스크에서 제외한다. 다섯 손가락 동시 결손은 실제 손바닥 부착 경계로 마감한다.

서로 다른 좌우/방향 발8개와 결손 표시12개를 새 원문으로 등록했다. 원문의 실제 alpha128 지지선과 각32개 발가락 결손 조합의 남는 지지선에 발을 핀한다. 균일 배율을 유지하며 발목도 같은 원문점에 연결한다. 뒤쪽에 가려진 발가락을 새로 그리지 않는다. 앞쪽 원문의 좌우 열 라벨은 실제 큰발가락 방향과 달라 등록 단계에서 정규화했다.

그늘 사람5종, 말라붙은 자/사제2종, 감염 순례자2종을 기존의 동일 환자/감염자 결합 그림에서 분리했다. 실제 장비와 사지 소유를 사용하는3개 전용 몸·9개 전면 얼굴이다. 그늘 사람은 작은 체격, 말기 환자는 수척한 살아 있는 몸, 포자 감염자는 어깨 균사판으로 구분한다. 언데드·발광 눈·마법 효과를 추가하지 않는다. 부품 원문의 반대 방향 몸통 행을 정규화하고, 프로필 다리의 실제 방향이 맞는 원문만 두 해부학적 측면에 명시적으로 공유한다. 실제 발은 별도의8개 원문이다. 몸 크기에 맞춘 접지 간격/걸음 거리와 원문별 관절 배율, 팔꿈치·무릎의 피부 겹침을 사용한다.

새 활성 원본 PNG7장, 새 등록 frame key120개, 등록 고유 원문 영역114개다. 이 중4개는 현재9종이 선택하지 않는 포자 몸 기본 머리이며, 현재 캐릭터가 조건부로 선택하는 신규 원문은110영역이다. 변형 인간 등록100키 중6키는 프로필 다리 원문의 명시적 공유다. 생성 요청8회/원본8장을 보존하며, 첫 결손 표시 원문은 외부 검은 테두리·뜬 부착점 때문에 교체했다. 첫 혼합 머리 시트의 감염자8영역은 프로필 방향이 달라 사용하지 않고 전용8영역으로 대체했다. 첫 환자 후보의 건강한 몸은 말기 환자로 수락하지 않고 그늘 사람 몸으로 별도 검토했다. 요청 수·보존 파일 수·활성 원문 영역 수·동작 프레임 수를 혼동하지 않는다.

이는 원문 부품을 같은 HumanView로 조립하는2D 표현이다. 새로 그린 완전 보행 프레임이나 실제3D 균형/해부학 인증이 아니다. 기존 의복25종·의수족6종의 실제 실물 UID를 유지하고, 의수족의 반대 면 원문을 새로 만들었다고 세지 않는다.

## 착용 치수와 실제 부착점 수정

추가 확대 검토에서 소매가 팔보다 넓고, 장갑 끝을 실제 손끝이 아닌 무기 grip에 맞춰 손이 짧아지는 문제가 드러났다. 같은 원문 알파128의 팔·손바닥·허리 폭과 보이는 손끝을 측정해 착용 폭을 맞춘다. 장갑의 손끝과 물건을 쥐는 grip은 서로 다른 점으로 유지한다. 원문 픽셀은 바꾸지 않는다.

기본 원문의 허리띠 점은 버클/옆 띠였으나 v389의 fit에서 전체 너비 span으로 이미 보정되어 있었다. 이번 남은 문제는 작은 체형에도 같은6world-pixel 너비를 쓰는 것과 몸 뒤쪽 띠의 가림이었다. 실제 허리 폭과 착용 중심에 맞추고 뒤쪽 띠는 몸통 뒤에 그린다. 투구도 기존 목/정수리 보정을 유지하며 실제 머리 폭과 얼굴 가림을 맞춘다. 원문 임시 기준점을 이미 보정된 값에 다시 적용해 투구를 기울인 개발 후보는 시각적으로 거절하고 복원했다. 작은 체형의 안경/마스크는 실제 머리 배율을 따른다.

열린 소매·장갑·신발 원문의 어두운 안쪽 면에는 실제 부모 몸 표면을 해당 입구 안에서만 겹쳐 그린다. 없는 팔/손/다리의 피부를 새로 만들지 않으며 이 표시는3D 착용·개별 손가락 굴곡을 인증하지 않는다. 재현 가능한 수치 등록은 `tools/art/measure-human-wear-v392.py`, 선택 의존성은 `tools/art/requirements-source-analysis.txt`에 있다.

## 재현과 검증

- `throw-transaction`, `action-observations`, `script-item-lifecycle`: 실패 전후 전체 상태·UID·열린 용기 문맥, 실제 공급원, 장비 작업자 호출을 검증한다.
- `human-details`, `human-mutants`, `human-gait`, `human-paperdoll`, `atlas-plan`: 원문/부위 소유·겹친 결손 면적·측면·접지·몸 크기·필요한 모델만 읽는 로딩 경계를 검증한다.
- 실제 Native 입력 도구: `inspect-pocket-props-v392`, `inspect-human-loss-native-v392`, `inspect-mutant-native-v392`. 유한 초기 조건을 Title에서 불러온 뒤 실제 키 입력과 별도의 Node 전체 상태를 비교하며, 불러온 뒤 세계 상태를 주입하지 않는다. 전체 세계 JSON은 로컬에만 보존한다.
- 합성 작업대 도구 `inspect-human-details-v392`와 `inspect-mutant-gallery-v392`는 화면 기하/원화 검토 자료이며 Core나 전체 상태 검증으로 세지 않는다.

첫 구현의 자동63조합 검사는 통과했지만 확대 화면에서 귀/손발 표시의 떨어짐을 찾아 시각적으로 거절했다. 원문과 실패 기록을 유지하고 부착점·소스 연결성·실제 피부 겹침을 수정했다. 첫 변형 인간 조립의 큰 머리·짧은 다리, 이후 관절 틈도 확대 검토에서 발견해 수정했다. 최종 통과 범위와 게시 여부는 [검증 기록](release-v392-proof.json)에 별도로 기록한다.

원문 SHA·프롬프트·크롭·방향 정규화는 [세부 원화](../tools/art/direction-v392/source-audit.json), [변형 인간](../tools/art/direction-v392/mutants/source-audit.json), 재현 가능한 원문 등록은 `tools/art/install-human-details-v392.py`, `tools/art/install-mutant-humans-v392.py`를 따른다. `human_source_masks_v392.py`는 원문을 읽는 알파/기하 분석만 수행한다.
