# v0.327 제작법 ID 이행과 착수 규칙 보존

모드의 `migrations/rename.json`에 제작법의 이전/현재ID를 명시하면 기존 콘텐츠 구성 검토에서 제작법 이행을 표시한다. 배운 제작법, 착수한 `workJob`, 현재/보관 지도·지역의 가공 배치, 거점 활성 지시와 대기열의 실제 제작법 참조를 함께 옮긴다. 조회/취소에는 원래 세계와 각인을 바꾸지 않는다. 승인은 기존 구성 변경의 정확한 검토 토큰과 후보 사본 경로를 사용한다.

착수한 노동/가공 배치는 기록된 원래 제작 규칙이 목적지와 같아야 한다. 새 각인은 실제 DB의 제작법 규칙 해시를 `contentRecipeContracts`에 기록한다. 정의의ID·표시 이름·설명·상속 이름을 제외한 해석 완료 필드 전체를 정렬해 SHA-256으로 기록한다. 재료·출력 개수·소요 시간·가공·정수·재질·도구·작업장·능력 조건 중 하나가 달라지면 이름만 바꿔 이어 가지 않는다. 원래 기록이 없는 진행도 새 규칙으로 추정하지 않는다.

이행은 원래 물품UID/개수·품질·재질·진행·고정 입력·완료 시각·인물·난수·과거 로그를 보존한다. 없는 새 재료나 완성품, 추가 진행을 만들지 않는다. 다른ID들이 같은 배운 제작법으로 겹치거나, 플러그인 지속 데이터/알 수 없는 필드에 이전ID가 남으면 별도 이행이 필요하다고 표시한다. 미착수 지시/배운 제작법만 있는 구형 각인은 원래 노동 규칙 기록이 없어도 현재 제작법으로 옮길 수 있다.

저장212를 추가했다.211→212는 헤더만 바꾸며 과거 제작 규칙을 생성하지 않는다. 확인한 현재 구성으로 새 기록을 시작하거나, 기록된 해시와 실제 DB가 같은 각인을 정상 불러올 때부터 현재 규칙을 기록한다. 다른 구성으로 바뀐 각인은 원래 기록을 검증한 뒤에만 현재 메타데이터로 갱신한다. 기존 물품·몸·상태·사건/개체 이행은 유지한다.

실행 가능한 예제는 [sample-recipe-renames](../mods/sample-recipe-renames/manifest.json)다.0.9의 `SampleMigration.Recipe.OldBandage`를1.0의 `SampleMigration.Recipe.RenamedBandage`로 옮긴다. 기본 게임에 약이나 제작법을 새로 지급하지 않는다. 코어 콘텐츠와 PNG는 바꾸지 않았다.

현재 범위는 같은 기계적 규칙의ID 이행이다. 같은ID의 일반 수치 변경은 기존 구성 변경 정책을 따른다. 제작법ID 변경과 동시에 재료ID/규칙까지 바꿔 원래 해시가 달라지는 경우, 다른 가공 방식으로 변경하는 경우, 지식을 병합하는 경우와 플러그인 지속 데이터는 별도 이행이 필요하다. 자동 추정하지 않는다.

대상47개·타입/린트·Def/Schema·빌드를 확인했다. 실제 UI에서는 선언한 이전 구성/1회 착수 진행·천4개·거점 활성/대기 지시를 불러와 두 해상도로 검토→취소→승인→기존 진행 재개를 수행했다. 승인 직후 전체 상태를 Node에서 독립적으로 작성한 기대 상태와 비교했고, 실제 제작 후 천2개/붕대1개를 확인했다. 노동 시간이 달라진 이전 구성은 승인 없이 그대로 유지했다. 초기 진단에서 잘못 선언한 보관함 지형/불완전한 스크립트 검증 자료와 적대 경비의 공격으로 중단된 제작을 발견해 유효한 초기 자료/실제 동료 계약을 사용했다. [검증 범위와 실패 기록](release-v327-proof.json).

모든 수동 가공 배치/정수·재질/여러 이행의 조합, 전체 회귀·World/1,000판·출시 각인과 사람 평가는 후속이다. 이 변경만으로 모드/메타 또는 v1.0.0 전체를 완료 처리하지 않는다.
