# v0.325 거점 의료 보급과 제작 협업

동료의 응급 처치와 거점 창고/최소 재고를 연결했다. 창고 사용은 상호 응급 처치와 별도로 곁에서 허락해야 한다. 여러 제작자는 이미 착수한 실제 작업과 운반 중인 완성품을 함께 고려해 같은 최소 재고의 중복 생산을 줄인다. 저장210을 추가하고209에는 창고 사용 동의나 과거 보급 임무를 추정하지 않는다.

## 창고에서 환자에게

주민·세력 → 동료 → 동행·급료 → 응급 처치 부탁의 ‘거점 창고 의료 보급’에서 허락/중지를1턴에 지시한다. 같은 현장의 본인 소유 실물 창고가 필요하다. 지침을 바꾸거나 끄면 진행 중인 보급 지시는 해제하며, 이미 들고 있는 원래 물품은 동료에게 남는다.

동료는 직접 관찰한 외부 상처에서 필요한 처치 종류를 판단한다. 자기 가방/주머니에 쓸 수 있는 도구가 없고, 확인한 열린 창고에 깨끗한 원본이 있을 때만 보급을 계획한다. 실제 도구·몸으로 그 처치를 시작할 수 있는지도 사본에서 확인한다. 환자ID/상처/마지막 관찰 위치·시각·지도/지역, 원래 창고UID와 의료 물품UID/종류를 기록한다. 조회만으로 물품·시간·난수·몸을 바꾸지 않는다.

실제로 창고까지 걸어간 뒤 같은 물품을 한 개 꺼낸다. 중간에 원본이 없어지거나 오염됐거나 공간이 없으면 다른 물품으로 몰래 대체하지 않는다. 기존 창고 이전의 전체/부분 묶음·새 조각UID·실제 공간 검사를 사용한다. 필요한 한 단위가 생겼을 뿐 상처는 아직 치료되지 않는다.

환자가 계속 보이면 위치를 갱신하고, 보이지 않으면 마지막으로 확인한 곳으로 돌아간다. 숨은 현재 좌표로 따라가지 않는다. 마지막 관찰 뒤 기본240턴이 지나거나 원래 현장/창고/지침이 달라지면 임무를 해제한다. 돌아와 실제 환자를 확인한 뒤 기존 처치와 기다림·물품 예약·중단/완료 규칙으로 넘어간다. 환자가 이미 치료됐거나 다른 시술자의 작업을 받으면 같은 처치를 덧붙이지 않는다.

돌봄을 맡긴 사람이 휴식/수면 중이면 정상적인 중단·기상 경로를 거쳐 처치를 받을 수 있다. 깨어서 다른 독서/제작을 하는 사람의 작업을 임의로 빼앗지 않는다. 그러한 작업 중 실신한 경우의 기존 구조 경로는 유지한다. 동료의 자기 허기·갈증·피로·체온과 위협 대응은 보급보다 앞선다. 물품이 없거나 환자를 찾지 못했다고 치료 효과나 대체 재료를 지급하지 않는다.

최소 재고 제작자가 같은 동료일 수도 있다. 실제 의료 보급이 창고 재고를 줄이고, 처치로 들고 있던 물품을 사용하면 부족한 재고를 원래 재료와 노동으로 보충한다. 처음부터 무한 의료품/원격 치료를 만드는 경로가 아니다.

## 여러 제작자의 최소 재고

최소 재고 조회는 창고의 실제 완성품, 자신의 운반 중 완성품, 다른 현지 유급 작업자의 운반 중 완성품/재료가 묶인 착수 배치를 나누어 계산한다. ‘다른 작업자 운반·착수’는 아직 창고에 들어온 재고와 구분해 UI에 표시한다. 대기열에만 있는 계획이나 아직 재료를 인출하는 단계는 생산 약속으로 세지 않는다.

다른 작업자가 실제 같은 거점의 같은 완성품을 만들고 있어야 한다. 원래 작업ID·제작법·물품UID/수량과 재질 예약이 유효해야 착수 물량으로 센다. 사망·포로·급료 만료·다른 지시/지역·재료 소실이면 더 이상 그 완료를 기대하지 않는다. 자체 제작이 이미 시작됐으면 원래 배치는 마친다. 묶음 출력 단위나 복직/나중에 회수한 기존 물품 때문에 목표를 넘을 가능성까지 없애지는 않는다.

이 계산은 파생 정보이며 새 완성품·재료·미래 재고를 저장/지급하지 않는다. 여러 작업자의 모든 원재료를 미리 전역 예약하는 시스템과는 범위가 다르다. 같은 최소1개를 맡긴 두 작업자는 먼저 실제 착수한 한 배치를 고려하며, 다른 작업자의 미사용 천은 그대로 남는다.

## 구성 변경 뒤의 대기 지시

활성/대기 작업의 제작법·완성품·재료/운반 종류가 현재 구성에서 없어졌으면 이유를 표시하고 대기한다. 없는 제작법의 조회로 게임을 중단시키지 않는다. 유효한 다른 대기 지시가 있으면 기존 배치/재료를 보존한 채 수행하고, 없어진 지시는 목록에 남겨 사용자가 구성을 복원하거나 삭제할 수 있게 한다. 임의의 다른 제작법이나 물품으로 추정 교체하지 않는다.

## 구현·확인 범위

설정은 기존 `Companion.Hearth.aid.supplyMemoryTurns` 패치로 분리했다. 타입·대상 린트·Def/생성 Schema·관련 검사와 선언한 초기 창고/동료/상처를 불러온 실제 UI·휴식 입력의 결과는 [검증 기록](release-v325-proof.json)에 기록한다. 기본 붕대와 두 작업자 시나리오가 모든 도구/시야·기기·노동 조합의 자연 발생 빈도를 검증하지는 않는다.

수술·투약 계획, 들것/지도 경계, 원격 노동·작업장 전체 연료/소유권, 나머지 X1–X4와 영어 전환 등의 [자율 구현 항목](autonomous-implementation.md)은 계속 남는다. 전체 회귀·World·1,000판·출시 저장/사람 평가도 후속이다.
