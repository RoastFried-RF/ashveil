# v0.390 손 부착과 빈 화면 안내

v389 공개판에서 오른팔이 없고 왼손은 정상인 유한 초기 각인을 불러온 뒤 실제 빠른 슬롯으로 물을 마셨다. 물은 소비됐지만 물병은 사라졌다. 원인은 물품 사용 연출이 오른손을 기본으로 정하고, 실제 손의 조작 가능 여부와 별도로 부착 위치를 선택한 것이다. 초기 각인과 독립 Node의 전체 저장 비교, 실제 PNG는 `test-results/autonomy-v390/hand-baseline-r1`, `hand-baseline-r2`에 보존한다.

일반 장비의 grip과 양손 무기 보조는 다르다. 갈고리의 기존 `grip:false`와 `twoHandSupport:.5`를 구분한다. 전원이 없는 의수, 손가락 결손, 고삐에 묶인 손도 같은 읽기 전용 기능 조회를 사용한다. 실제 물품·장착 슬롯·처치 가능 여부·소모·판정은 Core가 결정하며 렌더러가 바꾸지 않는다.

`tools/inspect-hand-props-v390.ts`는 정상/상완·전완·손·손가락 결손, 갈고리, 무전원·유전원 의수, 양손 결손과 즉시 연출 및 같은 그림의 다른 물병 UID 전환을 포함한15개 초기 상태에서 실제 빠른 슬롯 사용과 타이틀/이어하기를 확인한다. 소비가 끝난 마지막 음식도 성공 당시의 UID를 잠깐 표현하며 가방에서 다른 물건을 찾지 않는다. 원래 세계가 달라졌는지는 독립 Node 전체 JSON과 비교한다. `tools/inspect-hand-fx-v390.ts`는 원래 유한 탱크의 실제 분무 FX·원래 UID·오른팔 결손의 손 부착을 확인한다. `tools/inspect-empty-ui-v390.ts`는390/1440px의 실제 Tab/방향키 스크롤·빈 기록/정비·이어하기를 확인한다.

입 위치가 원문에 관찰된 정면/측면에서만 섭취 접촉을 맞춘다. 뒤쪽은 보이지 않는 입 좌표를 만들어 넣지 않고 기존 가림과 준비/회복 동작을 유지한다. 기존 육포 그림은 여러 조각을 묶은 보존식 도상이다. 작은 실제 소품으로 재사용하며 새 한입 전용 원화를 그렸다고 세지 않는다.

개발 중 첫 회귀의 잘못된 fixture ID(`Item.DriedMeat`→`Item.Jerky`, `Item.BeltPouch`→`Item.LeatherBelt`), 빠른 슬롯 관측 사이에 오래 걸리는 PNG 저장을 끼운 촬영 도구, 새 스크롤 영역의 방향키가 게임 입력에 막힌 실패를 원문으로 보존한다. PNG 저장은 연출을 정지하지 않으므로 원래 RAF 관측과 별도로 다룬다. 개발 서버의 HMR 실행은 최종 불변 빌드 검사와 구분한다. UI 개발 검사에서1440px의 연속 창 전환이 실패한 기록도 삭제하지 않는다.

이번 묶음은 새 원화·새 authored 동작 프레임을 생성하지 않는다. 기존 PNG와 신체 모델을 그대로 사용한다. 저장219·Core 버전0.1.0을 유지하며 프리뷰 표기만0.390-dev다. 최종 검사와 게시 근거는 `release-v390-proof.json`, 게시 후 영수증은 `release-v390-publication.json`에 남긴다.

후속: 변형 인간의 고유 몸, 미세 결손/복합 결손 자세, 모든 임상/공격/투척 소유의 추가 경계 감사, 도감 확대의 첫 초점, X1–X4와 장기 생태·사람 출시 평가. 일반 소모 동작의 손 선택은 표현상의 선택이다. Core가 개별 팔을 기록하는 투척의 모든 경우까지 수락했다고 확대하지 않는다. 기존 Core에서 양손 결손 중 물 마시기가 허용되는 경계는 바꾸지 않았으며 이번 검사는 가상 손/물병을 그리지 않는지만 확인한다.

빠른 슬롯의 빈 병 재현은 첫 병의 마지막1회분과 두 번째 원래 물병으로 선언했다. 첫 병은 기존 Core에서 같은 Def/UID·uses0으로 남는다. 빈 병을 다른 물품 ID로 바꾼다고 추정한 초기 검사도 실제 uses0 보존 검사로 바로잡았다. Core의 일반 quickItem/quickCount 및 물품·소비 규칙은 변경하지 않고 UI 편의 선택만 수정한다. 고정된 컵/약/보급품 사용 제한의 최종 판단은 기존 Core가 유지한다.
