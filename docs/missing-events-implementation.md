# 사라진 장소 사건의 실제 예약 폐기

v0.259 작업 중, 각인182/API1.4.0. 설계11§8에 따라 이전 정의 목록에 있던 PlaceEvent가 현재 구성에서 없어졌을 때, 명시적인 구성 변경 승인 뒤 그 사건의 미실행 장소 예약/스크립트 대기/완료 콜백만 폐기한다. 활성 지역과 실제 저장된 정지 지역의 예약을 함께 집계하고 예산·지난 사건 시각·과거 사건 기록은 보존한다. 같은 ID의 종류 변경과 출처 없는 삭제는 허용하지 않는다.

이미 출발한 인물/경로·원래 공급원·몸·물품·시각·UID·난수는 바꾸지 않는다. 사라진 사건을 계속 사용하는 현재 활동/다른 살아 있는 값·사전 키/남는 모드의 임의 JSON이 있으면 예약을 일부 지우지 않고 전체 승인을 차단한다. 과거 사건 일지·로그·실제 진단은 보존하며, 실제 Journal의 과거 사건 표시는 기존 ID fallback을 사용한다. 실제 제거할 예약이 있을 때만 같은 턴의 집계 로그를 하나 남기고 반복 실행은 새 로그를 만들지 않는다.

검토는 소유 사본으로 검사하고 현재 원문+선택 구성 토큰을 다시 확인한 승인 후보에서만 적용한다. 앞서 소유 스크립트 제거로 폐기한 예약을 중복 집계하지 않는다. 다른 사건 예약/남아 있는 완료 콜백은 보존한다. 원래 없어진 정의만 제외하고 나머지 종류 제거/이행 검사도 모두 통과해야 진입할 수 있다.

검토 단계가 늘면서 같은 전체 저장 사본을 다시 만들던 작업을 줄였다. 상태 rename/사건/상태 제거 계획의 소유 사본을 다음 읽기 전용 검토 단계에 넘기고 승인 때는 실제 새 후보에서 다시 검증한다. 원본을 공유하거나 참조 검사를 생략하지 않는다. 관련85개 첫 실행에서 새 예약 검사11개는 통과했고 기존 실제 상태 rename 승인 한 개가5000ms 제한을 넘겼다. 당시 전체 회귀/타입 검사도 실행 중이었다. 실패를 보존하고 사본 반복을 줄인 뒤 관련10파일85개를 작업자1로 다시 실행해 모두 통과했다. 최종 타입·린트도 통과했다. 최종 골든5개 전체 초기/최종/오류/해시가258 및 사본 최적화 전259와 정확히 같다.

실제 이전 Core 사건 정의를 로드한 정상 새 게임과 선언된 미실행 미래 예약으로 화면 검증을 준비했다. 이전 사건 실행/인물 출발/과거 턴을 실행한 이력으로 꾸미지 않는다. 별도 단위 검사에서는 명시된 예약/콜백 초기 데이터를 사용해 원래 실제 인물/공급원을 보존하는지 검사하며, 이를 스크립트가 실제 과거에 예약한 실행 기록이라고 주장하지 않는다.

최종 타입/린트·Def277패치/191물품·빌드2.38초를 통과한 원본259에서 실제 화면1276–1278 세 장을 모두 확인했다. 검토/취소 원문 유지·예약 하나/집계 로그/현재 메타데이터 외 전체 일치·전체182복원1·현재 활동 참조의 승인 차단/원문 보존·콘솔0을 첫 실행에 통과했다. 전체/월드 회귀는256–260 통합 진행 중이다. 현재 사용 중인 사건 참조/다른 상태·개체/설치·소스 이행 및 나머지 전체 후속 확장은 계속 남는다.
