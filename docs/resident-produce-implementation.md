# X2 실제 주민 수확물의 상점 공급

v0.236 / 각인173. 기존 주민·종자·뿌리188종 물품을 재사용한다. 기존 `ResidentCultivation.Hearth`의 선택적 `surplus` 설정은 PATCH로 남길 식량600kcal/재시도1200턴/한 번 최대2개를 둔다. 기존 Def 파일의 수치는 직접 바꾸지 않는다.

원래 주민이 자기 원래 종자로 실제 심은 밭을 같은 수확 작업으로 마칠 때만 출력에 원래 주인·종자·밭·지역·지도·수확 시각을 기록한다. 주인 미상/야생/플레이어 수확물이나 기존 음식의 과거 출처를 추정하지 않는다. 배낭에 넣기 전에 정보를 붙여 같은 상태의 출처 없는 음식과 쌓이지 않게 한다. 원래 쌓음 분할/거래/소비는 출처를 그대로 보존하고, 재사용 빈 그릇에는 이전 음식의 기록을 지운다.

몸과 생존·돌봄·위협 대응에 여유가 있는 주민은 자기 실제 새 수확물 중 신선한 잉여만 판다. 먹을 수 있는 신선/오래된 개인 식량을600kcal 이상 남기며, 상한 옛 음식으로 비축량을 채운 것으로 계산하지 않는다. 실제 기른 음식이 없는 주민은 이 행동을 하지 않는다. 수확물의 원래 냉동 상태/영양/관수 오염은 거래로 사라지거나 안전한 것으로 바뀌지 않는다.

먼 상점에는 주민이 아는 공개 상인 위치로 걸어간다. 재고/금고는 곁에서 실제 거래가 가능할 때만 확인한다. 실제 상인이 서 있는 칸을 목적지로 삼지 않고 걸어갈 수 있는 곁의 빈 칸을 찾는다. 남은 원래 식량이 충분한 잉여 판매는 추가 밭 점검보다 먼저 진행하고, 생존·돌봄·위협 대응의 우선순위는 유지한다. 판매를 마치면 기존 귀가 이동으로 집에 돌아가 밭을 계속 돌본다.

다른 상인에게 파는 물건은 기존 공통 `exchange`로 원래 주민 배낭→상점과 실제 상점 돈→개인 지갑을 함께 반영한다. 개인 지갑이 처음 없던 주민은 실제 첫 수입을 받은 때만 지갑이 생긴다. 조회에서0으로 채우지 않는다. 상점 주인이 자기 수확물을 재고로 옮길 때는 자기 돈/상점 돈을 바꾸지 않고 원래 물품만 이관한다. 현장에서 돈이 없거나 상점이 닫힌 것을 확인하면 물품·돈·UID를 보존하고 실제 재시도 시각만 유예한다. 먼 실패 입력은 현장 확인 기록도 바꾸지 않는다.

원래 수확물2개 전체가 팔리면 UID111은 그대로 상점으로 가고 주민에게4/상점1000→996을 지급한다. 남은 기존 개인 식량이 충분하므로 기본 시나리오는 두 개 모두 팔 수 있다. 한 개 한도 검사에서는 원래 더미 한 개를 남기고 실제 새 분할UID만 부여한다. 플레이어가 그중 하나를 사면 원래 상점 더미는 한 개 남고 같은 출처의 새 분할 한 개만 배낭으로 간다. 구매7이면 개인100→93/상점996→1003/주민4로 총돈과 두 음식이 보존된다.

상점의 실제 거래 물품도 기존 소지품과 같은 읽기 전용 상세 정보로 살펴볼 수 있다. 접근이 유효할 때 실제 공개 물품의 신선도/영양/냉동·수질 정보를 보여 주며, 원래 주민의 비공개 배낭이나 내부 출처ID를 새로 노출하지 않는다. 구형172 각인은 버전173만 올리고 기존 주민 음식에 농사 출처를 채우지 않는다.

초기3파일103개 중 냉동 음식을 팔 수 없어야 한다는 검사 하나가 실패했다. 원래 규칙은 냉동 음식도 먹고 거래할 수 있으므로 게임 규칙을 바꾸지 않고 실제 냉동 상태를 보존한 거래 검사로 고쳤다. 이동 준비 중 두 번의 실제100턴 조사에서는 상인 점유 칸을 목표로 한 경로 실패와, 밭 점검이 다시 집으로 돌려보내던 왕복을 확인했다. 실제 곁 접근 칸과 잉여 판매의 작업 우선순위만 고쳤고 NPC를 옮기거나 현금/물품을 맞추지 않았다. 이후 실제14턴 이동·판매에서 두 수확물/4의 대금과 원래 UID가 보존됐다.
