# 사건 예약/완료 기록의 실제 ID 이행

v0.262 작업 중, 각인182/API1.4.0. 실제 이전 정의 목록과 현재 rename이 같은 PlaceEvent로 연결될 때 장소 예약·스크립트 대기 실행/완료 콜백의 사건 ID만 옮긴다. 활성/정지 지역의 원래 시각·좌표·배우/귀환·실행 번호·예산·전체 인물/공급원·몸/물품·UID/난수/과거 로그는 보존한다. 새 사건을 즉시 실행하지 않고 향후 실제 출발지/경로/공급원 검사를 그대로 따른다.

현재 인물의 사건 표시 ai.placeEvent와 다른 살아 있는 값·키/남는 모드의 임의 JSON은 의미를 추정해 고치지 않고 별도 이행을 요구한다. 다른 종류의 목적지와 출처 없는 이행도 승인하지 않는다. 과거 사건/개인/정신/진단 기록을 현재 실행 참조와 구분해 보존하며 반복 실행은 로그/보상을 만들지 않는다. 소유 스크립트 정리→물품/상태/사건 rename→없어진 사건/상태→물품 보관의 같은 원문/현재 DB 토큰 승인에 연결한다.

사건 현재 참조 스캔을 재사용 가능한 읽기 전용 함수로 묶었다. 이전259의 거절 장면은 임의 현재 Activity의 추가 필드 참조를 보존하는 검사였다. 실제 등록된 사건 참조 필드는 AiState.placeEvent임을 원본/실제 AI 호출에서 확인했고, 이번 단위/화면 검사는 실제 ai.placeEvent를 사용한다. 두 경로 모두 기존 일반 참조 검사가 차단하며 구현의 보호 범위를 줄이지 않는다.

실제 기본 비활성 sample-event-renames1.0은 코어 순찰을 상속한 비물품 PlaceEvent 하나와 실제 ID맵을 제공한다. 이전0.9는 원래 정의를 먼저 실제 로드한 정상 새 게임과 선언된 미실행 미래 예약을 사용한다. 과거 사건 실행이나 인물 출발을 실행한 이력으로 꾸미지 않는다. 배포4파일/1020바이트·277패치/경고0·SHA256 328ac152d20e54f47ab701eab5b6676dc82b6ae8bb9115b09bfc82b03b921254를 확인했다. 새 Item은 없다.

전용6개+실제 저장 시작2개와 기존 사건/정신/상태/물품/모드 시작/골든의10파일66개 검증을 준비했다. 첫 실행65개 통과/새 시작 보호 한 개5000ms 제한 초과는 월드4작업자·타입 검사 동시 실행 중 발생했다. 기존 실제 실행 세계는 같은 정상 원본의 전체 직렬화/복원 사본과 같은 불변 DB로 준비하도록 바꿔 동일한 새 게임/DB를 두 번 생성하던 시험 비용을 줄였다. 화면/세계 포인터·원문·전체 상태·저장 불변 검사는 유지하고 시간 제한을 늘리지 않는다. 실제 필드의 타입 검사도 보강했다. 월드/GPU 작업 종료 뒤 최종10파일66개를 작업자1로 다시 실행해 모두 통과했다. 최종 타입/린트·Def/빌드도 통과했다. 기존 원문/실행 세계/화면/포인터·전체 상태·저장 불변 검사는 그대로 유지했다.

골든5개 전체 초기/최종/오류/해시가261과 정확히 같다. 최종 정적·실제 화면/전체182복원·전체/월드 회귀와 다른 상태/개체/설치/소스 이행·나머지 전체 후속 구현은 진행 중이다.
