# 실제 포로 호송과 손 점유 — v0.64

`PrisonerEscort.Hearth`에 호송 준비2턴/발목 재포박2턴/밧줄 거리2칸을 분리했다. 수치는 확장 조정값이며 실제 작업 시간은 기존 몸·조명·피로 등 공통 다턴 배율을 적용한다. 회유·구출 후 영입과 자연 발생 구출 사건 전체는 다음 작업이다.

N창에서 같은 편이 포박한, 깨어 직접 걸을 수 있는 인물의 발목을 풀고 빈손 하나로 실제 밧줄을 잡는다. 준비 작업의 시작/각 틱/완료에 같은 인물·밧줄UID와 거리/손을 검사한다. 실제 밧줄은 계속 그 인물의 손목에 있고 손목 조작0을 유지한다. 포로를 동료 계약으로 바꾸거나 새 인물·물품·지갑을 만들지 않는다. 발목이 묶인 기존 포로는 기존 이동0이다.

호송자의 온전한 빈손(.2 이상, 실제 의수 쥐기 조건)을 점유한다. 왼손이 가능하면 왼손부터 선택하며 점유한 손의 기능/장비 슬롯은 사용할 수 없고 양손 장비도 장착할 수 없다. 일반 조작은 남은 손의 기존 오른손.6/왼손.4 가중치를 쓴다. 주먹/갈고리 공격도 점유한 손을 쓰지 않는다. 한 손만 남은 호송자가 손을 되찾도록1턴의 ‘호송 밧줄 놓기’를 제공한다. 밧줄을 놓아도 손목은 묶여 있고 발목이 저절로 다시 묶이지 않는다. 다시 걸음을 묶으려면 실제 발목 재포박 작업을 해야 한다.

포로는 실제로 보인 포박자의 마지막 위치를 기억하고 기존 경로/이동 행동으로 한 칸씩 따라온다. 거리/시선/손이 끊기거나 호송자가 잠들거나 실신·기절/넘어짐 상태가 되면 연결이 끊어진다. 손목 밧줄/풀린 발목은 그대로 남고 기존 포로 탈출·도주 판단을 쓴다. 포로가 잠들어도 깨어 잡은 손은 유지되며 직접 걸어야 하는 여행은 멈춘다. 호송자/포로의 사망·해방도 손 점유를 해제한다.

포로가 출입구를 막으면 그 칸으로 움직이려는 입력은1턴의 비키기 요청이 된다. 밧줄 거리/시선/모서리·빈 바닥을 검사하고, 포로 자신의 다음 차례에 기존 이동 행동으로 비킨다. 즉시 밀어 옮기거나 공격하지 않는다. 실제 수면/실신/이동 불가인 사람은 비키지 못한다. 비키기 요청도 각인에 보존한다.

이동 명단은 실제로 따라오는 고용 동료와, 플레이어나 그 동료가 직접 이끄는 포로다. 계단/지역/길목의 원본 명단에서 같은 인물들을 제외해 도착지로 옮기며 복제본을 남기지 않는다. 각 여행 틱에 계약/각성·이동/출혈과 실제 호송 연결을 확인한다. 몸/허기·갈증/수면도 실제 시간이 진행된다. 도착 바닥은 실제 빈 칸을 고르고 포로와 해당 호송자 사이2칸/LOS를 만족한다. 최대20,000단계의 결정론 탐색으로 출입구를 검증하며, 이미 아는 도착지에 자리가 없으면 지도/인물/시간을 바꾸기 전에 거절한다. 호송 중 적이 계단을 따라오는 경우도 같은 도착 공간 검사에 포함한다. 포로 없는 기존 도착 순서는 유지한다.

각인v30은29의 몸/밧줄·돌봄 기록을 바꾸지 않는 순수 이관이다. 새 호송/손 점유·발목 상태와 마지막 실제 위치를 저장한다. 기존5골든의 전체 초기/최종 상태는 버전29→30 외 동일하며 원래 명령/오류를 유지했다(`golden-v064-diff.json`).

돌봄/깨우기 로그도 이미 아는 이름·실루엣을 써서 아직 모르는 이름을 드러내지 않는다.
