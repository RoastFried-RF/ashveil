# ASHVEIL 얼굴 천 약탈자 원본 — 적용 전 제작본

2026-10-20, 사용자 요청에 따라 두 번째 약탈자 `reaver1` 교체용 아트를 직접 작성했다. 이 폴더는 실제 게임 저장소와 분리된 산출물이다. 아직 게임에 적용하지 않았고 Core/Def·기존 문서·실제 manifest·Git을 수정하지 않았다.

## 디자인과 출처

얼굴 아래를 가리는 재 묻은 천, 짧게 드러난 머리, 해진 짙은 적갈색 어깨천, 가죽 대각 끈과 작은 철제 고리, 회색 정강이 감개를 그렸다. 철모를 쓴 첫 약탈자와 달리 머리 위가 낮고 둥글며 피부가 드러난다. 떠돌이의 뾰족한 청록 후드와 긴 망토·측량 가방도 사용하지 않았다. 비대칭 어깨천은 인물의 왼쪽에서 더 길게 늘어진다. 정면에서는 화면 오른쪽, 뒤에서는 왼쪽에 긴 천이 보이고, 옆모습 두 개의 천 길이와 회색 속옷 노출도 다르게 그렸다.

아래 얼굴을 덮은 밝은 재색 천은 눈과 짧은 머리가 있는 윗부분과 분리된다. 머리 뒤의 묶은 천 끝은 옆·등 방향에서 보인다. 어깨의 적갈색과 바랜 재색 천, 대각 가죽 끈의 대비로 방향과 몸통을 읽게 했다. 완성된 검·활·방패는 그리지 않아 실제 무기를 잘못 표시하지 않는다. 외형의 가죽·천·철제 고리는 장비 수치나 실제 착용 상태를 대신하는 기능이 아니다.

상위 `docs/CANON.md`의 고유 IP·낡은 재질·인간형 약탈자 기조를 따랐다. 얼굴에 재를 바르는 관습과 제각각인 장비는 `docs/lore/factions.md` §3.1·3.5와 `docs/lore/bestiary.md` §3을 참고했다. 새 설정·세력·직업·능력·아이템을 추가하지 않는다.

`tools/art/draw-reaver1.mjs`에 모든 픽셀 좌표·폴리곤·재질 덩어리·28개 포즈를 직접 작성했다. 이전에 직접 만든 약탈자 도구의 캔버스·PNG 인코더·SVG 내보내기·검토 시트·무결성 검사 구조를 재사용했다. 인물의 머리·얼굴 천·몸통·어깨천·가죽 끈·다리 감개·팔 동작 좌표는 새로 작성했다. 외부 팩 또는 이전 PNG의 픽셀을 입력으로 읽거나 추출·트레이싱·재색칠하지 않는다. 이미지 생성 도구를 호출하거나 생성 이미지를 편집하지 않은 정확한 픽셀 원본이다.

## 기존 애니메이션 계약과 새 프레임

실제 `src/client/sprites.json`을 읽고 `reaver1`의 28개 이름과 방향별 순서를 유지했다. 행은 **down·left·right·up**, 걷기는 **0·1·2**, 공격은 **0·1·2·3**, 대기는 각 방향의 **걷기 1번**이다.

| 동작 | 이름 | 사각형 |
| --- | --- | --- |
| 걷기·대기 | `reaver1_w_{방향}{0..2}` | `['reaver1', 열×24, 행×32, 24, 32]` |
| 공격 | `reaver1_a_{방향}{0..3}` | `['reaver1_atk', 열×32, 행×40, 32, 40]` |

걷기의 세 포즈는 왼발·대기·오른발, 공격의 네 포즈는 준비·들기·뻗기·회복이다. 서로 다른 포즈가 총 28개다. 공격에서는 움직이는 팔의 대기 그림을 생략하고 포즈별 팔을 새로 그려 손이 중복되지 않게 했다. 들린 팔과 얼굴 천의 위치도 직접 검토했다.

| 캐릭터 설정 | 값 | 지면·표시 근거 |
| --- | --- | --- |
| `anchor` | `[0.5, 31/32]` = `[0.5, 0.96875]` | 보행 셀 중심 x=12, 지면 경계 y=31 |
| `attackAnchor` | `[0.5, 39/40]` = `[0.5, 0.975]` | 공격 중심 x=16, 지면 경계 y=39 |
| 공격 몸 오프셋 | `[4, 8]` | `16−4=12`, `39−8=31`로 보행과 같은 몸·발 기준 |
| `renderScale` | `1` | 먼저 만든 떠돌이·약탈자 원본과 같은 네이티브 픽셀 밀도 |
| `headOffset` | `28` | 보행 지면 y=31에서 드러난 머리 상단 y=3까지의 높이 |

모든 보행 포즈는 y=30의 신발 픽셀이 있고 y=31은 비어 있다. 공격은 같은 몸을 8px 내렸으므로 신발 픽셀이 y=38, 비어 있는 지면 경계가 y=39다. 팔·천 동작 중에도 몸의 루트 좌표는 유지된다.

현재 기존 `reaver1`은 걷기 24×32, 공격 **47×63**, 걷기 앵커 `[0.5,0.92]`, 공격 앵커 `[0.5,0.78]`, 기본 배율 0.72를 사용한다. 새 파일의 URL만 바꾸면 잘못된 영역을 자른다. 추후 통합할 때 제공 JSON의 **`sheets` 두 항목·`frames` 28개·`chars.reaver1` 전체**를 함께 반영한다. `hero`·`reaver0`·Core Def와 현재 렌더러의 걷기/공격 시간은 이 조각에 포함하지 않았다. 카메라·지형·시야·조명을 바꾸지 않는다.

## 재현 및 검사

격리 폴더 루트에서 실행한다.

```sh
node tools/art/draw-reaver1.mjs
node tools/art/draw-reaver1.mjs --check
```

첫 명령은 이 폴더의 아트 파일 8개만 쓴다. `--check`는 예상 바이트를 메모리에 생성해 제공 파일과 비교하며 파일을 쓰지 않는다. `--install` 등 다른 인자는 거부한다. 외부 패키지·네트워크·브라우저·GPU가 필요 없다.

검사는 프레임 경계·방향별 포즈 수·대기 연결, 서로 다른 28포즈, 모든 포즈의 발 기준선, 걷기/공격 앵커 일치, 팔레트 색, 0/255 알파, PNG CRC·압축 데이터·스캔라인과 생성 바이트 일치를 확인한다. 투명한 원본 시트와 불투명한 검토 시트를 구분해 기록한다. 각 포즈와 제공 파일의 해시는 무결성 JSON에 남긴다.

실제로 실행한 범위는 다음과 같다.

- `node tools/art/draw-reaver1.mjs --check` 통과. 보행 12개·공격 16개와 28개의 서로 다른 포즈 확인.
- 보행·공격 원본 PNG와 전체 검토 PNG를 `view_image`로 직접 열어 얼굴 천·드러난 머리·비대칭 어깨천·발 기준·팔 동작을 확인.
- 현재 실제 manifest와 읽기 전용 대조: 기존 `reaver1_*` 28개 이름, walk/idle/attack 방향별 배열 동일. 제공 조각에는 `reaver1`과 `reaver1_atk` 시트만 존재.
- 문서의 8개 SHA-256이 실제 파일과 일치함을 검사.

게임에 아직 연결하지 않았으므로 실제 이동·공격·피격·사망·조명 화면을 검증했다고 주장하지 않는다. 브라우저·GPU·게임 빌드·전체 회귀·전체 타입 검사는 실행하지 않았다. 실제 게임 검토는 통합 담당자가 수행한다.
