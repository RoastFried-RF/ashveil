# ASHVEIL 잿빛 약탈자 원본 아트 — 적용 전 제작본

2026-10-20, 사용자 요청에 따라 다음 캐릭터 교체용으로 직접 그렸다. 이 폴더는 게임 저장소와 분리된 제작 산출물이다. 실제 `sprites.json`, Core/Def, 기존 문서, Git 상태를 수정하는 설치 기능은 제공하지 않는다. 새로운 세력·직업·능력치·장비 아이템을 추가하는 작업이 아니다.

## 디자인과 직접 작성한 원본

낮고 둥근 짧은 철모, 재를 바른 얼굴, 꿰맨 무두질 가죽 조끼, 해진 회색 어깨 천과 짧은 튜닉, 묶은 밧줄 허리띠를 그렸다. 떠돌이의 뾰족한 청록 후드·긴 천·측량 가방·구리 브로치와 구별되도록 머리와 어깨의 실루엣을 새로 설계했다. 피부, 철모 테두리, 밧줄에 작은 밝은 면을 배치해 어두운 바닥에서도 머리·몸통·손을 읽을 수 있게 했다. 형광 윤곽선이나 지형/조명 변경은 사용하지 않았다.

재 묻은 얼굴과 제각각인 장비의 근거는 `docs/lore/factions.md` §3.1·3.5와 `docs/lore/bestiary.md` §3이다. 상위 `docs/CANON.md`의 고유 IP·인간형 신체·낡은 재질 기조를 따른다. 이 인물은 일반 약탈자의 시각 자산이며 두목 전용 이빨 목걸이를 두르지 않았다. 철모와 가죽의 표현은 외형의 기본 디자인이고, 실제 장비 상태나 방어 수치를 표시하는 기능은 아니다.

모든 실루엣·재질 덩어리·보행·팔 동작은 `tools/art/draw-reaver.mjs`의 좌표와 팔레트에서 직접 작성했다. 자체 제작 떠돌이 도구의 작은 캔버스·PNG 인코딩·SVG 내보내기 접근만 재사용했다. 기존 팩 이미지, 이전 캐릭터 PNG, 생성 초상 등은 입력으로 읽지 않으며, 외부 팩의 픽셀 추출·트레이싱·재색칠은 하지 않았다. 이번 팩은 이미지 생성 도구 호출 없이 작성한 정확한 픽셀 원본이다.

팔레트는 윤곽/머리카락, 회색 철, 잿빛 천, 갈색 가죽, 피부/재, 밧줄, 바지/신발의 램프로 나뉜다. 마지막 네 색은 검토 시트의 배경·글자에도 쓴다. 밧줄 매듭은 인물의 오른쪽 허리에 유지한다. 정면에서는 화면 왼쪽, 등에서는 오른쪽에 나타나고, 옆모습 두 개에는 보이는 매듭의 양을 다르게 그렸다. 고정 검·활·방패를 그리지 않아 다른 실제 장비를 들었을 때 잘못된 무기가 겹치지 않는다.

## 프레임 이름과 지면 기준

현재 게임의 `hero`·`reaver0`에는 아래·왼쪽·오른쪽·위 방향별 걷기 3개와 공격 4개가 있다. 대기는 각 방향 걷기 1번이다. 기존 이름과 방향별 순서를 읽어 그대로 보존한 적용용 조각을 제공한다.

| 동작 | 기존 이름 형식 | 셀 | 열 순서 | 행 순서 |
| --- | --- | --- | --- | --- |
| 보행·대기 | `reaver0_w_{방향}{0..2}` | 24 × 32 px | 왼발·대기·오른발 | down·left·right·up |
| 공격 | `reaver0_a_{방향}{0..3}` | 32 × 40 px | 준비·들기·뻗기·회복 | down·left·right·up |

걷기 사각형은 `['reaver0', 열×24, 행×32, 24, 32]`, 공격은 `['reaver0_atk', 열×32, 행×40, 32, 40]`이다. JSON에 28개 전체를 기록했다. 걷기·공격의 발이 닿는 픽셀은 각각 y=30·38이고 지면 경계는 y=31·39이다. 공격 몸통은 보행 몸을 `(4, 8)`에 놓는다.

| 항목 | 적용 시 사용할 값 | 이유 |
| --- | --- | --- |
| `anchor` | `[0.5, 31/32]` = `[0.5, 0.96875]` | 보행 셀의 중심 x=12, 지면 y=31 |
| `attackAnchor` | `[0.5, 39/40]` = `[0.5, 0.975]` | 공격 셀 x=16·y=39에서 몸 오프셋을 빼면 보행의 x=12·y=31 |
| `renderScale` | `1` | 기존 원본 떠돌이와 같은 네이티브 픽셀 밀도와 인간형 크기 |
| `headOffset` | `29` | 지면 31에서 철모 상단 2까지 29px; 상단 상태 표시의 기준 |

위 값은 제공 JSON에만 들어 있다. 실제 게임에 적용하지 않았다. 기존 `reaver0` 공격은 **47 × 63 px**, 앵커는 `[0.5, 0.78]`이고 기본 렌더 배율은 0.72다. 새 시트 URL만 바꾸면 잘못된 영역을 자르므로, 추후 통합 담당자는 `sheets` 두 항목·28개 `frames`·`chars.reaver0`를 함께 반영해야 한다. 기존 `reaver0_*` 이름, `idle.* = walk.*[1]` 규약은 동일하다. `hero`·`reaver1`·NPC Core Def를 변경할 필요가 없다. 현재 렌더러의 걷기/공격 시간은 그대로 사용하며 별도 FPS 변경을 제안하지 않는다.

## 재현과 읽기 전용 검사

격리 폴더 루트에서 실행한다.

```sh
node tools/art/draw-reaver.mjs
node tools/art/draw-reaver.mjs --check
```

첫 명령은 이 폴더의 아트 파일 8개만 생성한다. 두 번째는 예상 파일을 메모리에서 재생성한 뒤 기존 바이트와 비교하고, 어떤 파일도 쓰지 않는다. `--install`을 포함한 다른 인자는 거부한다. 외부 패키지·네트워크·브라우저·GPU가 필요 없다.

`--check`는 프레임 28개의 경계·방향별 수·대기 연결·서로 다른 포즈, 전 프레임의 발 기준선, 걷기/공격 앵커 일치, 팔레트 안의 색, RGBA의 0/255 알파, PNG CRC·압축 데이터·스캔라인, 제작 파일의 바이트 일치를 검사한다. 원본 셀은 투명하고, 배경과 이름이 있는 검토 PNG만 불투명하다. SHA-256과 개별 포즈의 해시는 `ashveil-reaver-integrity.json`에 저장한다.

## 실제 확인한 범위

- `node tools/art/draw-reaver.mjs --check` 통과. 걷기 12개·공격 16개, 서로 다른 포즈 28개.
- 원본 보행 PNG·공격 PNG와 4배 검토 PNG를 `view_image`로 직접 열었다. 옆 팔의 외곽을 다듬고 등 방향 공격의 손이 머리 위로 드러나게 수정한 뒤 최종 검토 시트를 다시 확인했다.
- 현재 실제 `src/client/sprites.json`을 읽기 전용으로 대조해, 기존 `reaver0`의 28개 프레임 이름과 walk/idle/attack의 방향별 순서가 제공 조각과 같음을 검사했다.
- 맵·카메라·밝기·시야·Core/Def·기존 문서·실제 manifest는 수정하지 않았다. 브라우저·GPU·게임 빌드·전체 회귀 검사를 실행하지 않았다.
- 이 문서의 시각 확인은 독립 아트 시트를 대상으로 한다. 실제 전투·이동·사망·조명 속 게임 화면 확인은 이후 통합 담당자의 검증 범위다.
