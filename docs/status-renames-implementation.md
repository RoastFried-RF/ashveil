# 상처·상태의 실제 ID 이행

v0.258 작업 중, 각인182/API1.4.0. 설계11§8의 rename 우선 처리를 기존 물품에 더해 Wound/Disease/Thought/Trait로 확장했다. 실제 이전 정의 목록과 현재 migrations/rename.json이 같은 종류로 연결된 경우에만 명시 승인한 후보에서 옮긴다. 상처 번호·병 진행/잠복·생각의 남은 시간/묶음·특성 상태와 실제 몸/물품·시각·UID·난수는 보존한다. 현재 상처의 위험/물림 대기/보균·면역·노출 시계는 같은 질병 식별로 옮기며, 과거 흉터/질병 원인·로그·지식은 다시 쓰지 않는다.

원래 상처 번호를 그대로 쓰므로 압박/뇌 회복/현재 치료의 숫자 참조는 유지한다. 현재 필드의 기록된 종류가 다르거나 목적지가 다른 종류이면 원자적으로 거절한다. 여러 원본이 같은 특성/생각/질병/면역 또는 노출 시계 키로 겹치면 진행/수치를 임의로 버리거나 합치지 않고 원래 정의 복원/개별 병합을 요구한다. 남는 모드의 임의 JSON/기타 살아 있는 값·키 참조도 추정해서 고치지 않는다. 과거 구성 없는 저장이나 같은 전체 해시와 모순된 이행은 허용하지 않는다.

실제 검토에 타입·원래/현재 ID·현재 이행할 기록 수를 표시하고, 취소와 검토 뒤 상태 변경을 기존 원문/선택 DB 토큰으로 보호한다. 스크립트 소유 상태 정리→물품 rename→상태 rename→없어진 상태 제거→물품 보관 순서로 같은 승인에 연결한다. rename한 상태는 제거하지 않으며 기존 구성 변경 이력/업적 비활성·한 번 저장에 연결한다.

실제 sample-status-renames1.0.0은 네 비물품 정의와 rename 파일을 제공한다. 원래 코어는 패치하지 않고 시작 특성 추첨 가중치는0이며 기본 비활성이다. 이전0.9 시험 구성은 실제 같은 모듈에서 원래 네 ID를 먼저 로드한 뒤 정상 새 게임과 명시적인 초기 상처/질병/생각/특성을 만든다. 이전 플레이 이력을 실행했다고 주장하지 않는다. 실제 배포 검사277패치/경고0·1269바이트·SHA256 c9425c16b8df4a2eceb072dc5ccb36d1eaa6d212508a11ae7ea11b3f90533348·예제 네 파일만 포함을 확인했다. 새 Item은 없어13등록 대상은 없다.
