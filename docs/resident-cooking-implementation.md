# 주민의 실제 곡물 조리와 개인 조달 — v0.301 통합 완료

주민의 개인 귀리·돈·물병·그릇·장작불을 기존 실제 행동으로 연결했다. 새 원본은 추가하지 않고 기존 빈 그릇/덜 익은 귀리죽/익은 귀리죽 원본을 재사용한다. 최종 실제28PNG, 각인204 전체복원10회, 전체상태38쌍과 두 화면 크기 공통 입력 검사를 통과했다. 전체 회귀와 월드30판도 통과했다.

## 조달과 실제 조리

깨어 있고 손·시각·이동을 쓸 수 있는 해당 정착지의 주민/경비가 대상이다. 위협·출혈·심한 갈증·추위/더위·피로·기존 활동을 우선한다. 먹을 개인 음식이 없고500kcal 준비 문턱 아래이며 실제 조리용 곡물을 가지고 있어야 한다.

부족한 그릇/키트/장작은 공개 상인 위치까지 실제로 걸어가 곁에서 확인한다. 먼 상점 재고나 잔액으로 계획하지 않는다. 개인 생활비5를 남기고 한 물품 최대25까지만 지불한다. 자기 상점에서는 실제 재고만 옮기고 돈을 만들지 않는다. 현장에서 품절·공간·지불 불가를 확인하면 원래 물품/돈/UID를 보존하고1200턴 뒤 재시도한다. 돈이나 실제 공급이 없는 주민에게 도구를 무료로 지급하지 않는다.

집 반경3 안의 보이는 빈 땅에 원래 키트를 설치하고 실제 목재 한 개로 기존100턴 점화를 마친다. 물이 부족하면 기존 용기를 실제 우물에서 채우며, 조리 뒤에도 물300ml를 남길 수 있어야 한다. 귀리1개·물220ml·같은 그릇을 불 위에 올려400가열턴을 보낸다. 가열 전에는 병원체가 남고, 실제 끓여도 재는 사라지지 않는다. 첫 식사 뒤에도 준비 문턱 아래면 같은 빈 그릇으로 다음 한 회분을 준비할 수 있다.

기본 정책은 `ResidentProvision.Hearth.cooking`의 `Recipe.Oatmeal`이다. 정책 수치는 제안 기본값이며 CANON 미결정 항목을 확정하지 않는다. 옛 세계의 상점에 새 키트를 소급 보충하지 않는다. 다른 세력의 도구 조달·모든 음식·연료 상실 이후 자동 재점화/재조리·장기 기근·전역 농업 전체의 완성은 아니다. 연료가 끊기면 원래 덜 익은 그릇과 진행을 회수하며 기존 생식 선택과 오염 규칙이 적용될 수 있다.

## 실제 소비와 공개 범위

한 회분의 실제 열량/2500만 Food 장부에 기록한다. 귀리죽300kcal는0.12Food, 탄210kcal는0.084Food이며 개인 일일 한도를 넘기지 않는다. 준비·급수·미완료 가열·조회는 식사로 세지 않는다. 점화 완료에 소비한 실제 목재만 Fuel 장부에 기록한다. 그릇 음식을 요약 Food 재고로 등록하지 않아 마을 요약 소비가 그릇까지 삭제하지 않는다. 환산 필드를 없앤 모드는 이전 물품별 환산을 유지한다.

본인이 설치한 불의 위치/UID를 기억하고 현장에서 사라진 것을 확인했을 때만 잊는다. 다른 사람의 불과 음식은 조작하지 않는다. 바로 곁의 조리창에는 보이는 그릇 원본과 익음/덜 익음 상태만 표시한다. 정확한 타인 조리 진행·연료와 회수·불 관리 조작을 공개하지 않는다. 자기 음식과 모닥불의 기존 조작은 유지한다.

각인203→204는 버전만 올린다. 기존 주민에게 도구·돈·불 기억·과거 조리·소비량을 추정해 채우지 않는다.

## 실제 검증 범위

전용32개가 구매/부분 스택·생활비/품절/자기 상점·같은 그릇/두 번째 끼니·400가열·오염·원래 물/연료·중단·건강 경계·소비 한도·미완료 전체복원/구형각인을 검사한다. 최종 Native는 주민8장/4복원/15전체쌍, 기존 플레이어 귀리 조리12장/6복원/23전체쌍이다. 실제 키/마우스95,900TU와 별도 미완료30,300TU 재개, 합계126,200TU를 확인했다. 공통 두 크기는 각각4장/11입력/200TU를 확인했다. [전체 상태 근거](resident-cooking-v301-guard-native-audit.json) · [공통 검증](game-harness-v301-guard-audit.json) · [직접28장 시각 검토](ui-v301-guard-cooking-art-review.json).

주민 초기 곡물3/개인 돈100·허기/일정과 선택적 도구는 명시한 유한 초기 조건이다. 정상 플레이로 얻었다고 주장하지 않는다. 첫 실제 구매/점화/가열/섭취는 NPC 스케줄러가 수행하며 타이틀에서 불러온 뒤 세계·시간·난수·물품을 주입하지 않는다. 주민8장만으로 익은 음식/배낭의 빈 그릇/식사 성공을 판정하지 않고 전체 세계·식사 이력·장부와 교차 확인한다. 플레이어 귀리 장면은 이전 성장을 초기 조건으로 명시하므로5일 전체 정상 재배의 검증이 아니다. 구형203 검사는 현재 유한 장면의 구형 헤더이며 과거 사용자 파일 자체의 재현은 아니다.

## 구현 중 검증 이력


첫 전용26개 중25개가 통과했고, 빈 병으로 우물에 가던 주민이 집 반경 밖에서 귀가로 되돌아가던1개가 실패했다. 실제 우물/상점 조달이 끝난 뒤 귀가하도록 순서를 고쳤고 같은 검사도 원래 제한에서 통과했다. 관련5파일111개가 통과했다. 이후 건강 경계3개와 관수 오염곡물1개를 더했다. 전용30개/골든10개 검사를 빌드·린트·Schema와 동시에 돌렸을 때 구매→식사 한 검사가 기존5초를 초과했다(39통과/1시간제한). 제품/제한시간을 바꾸지 않고 무거운 검사를 분리해 재검사한다.

원래5골든의 전체 초기/최종/오류를 비교했다. 3개 일반 벡터는203→204·콘텐츠해시2곳 외 완전히 같다. 2개월드 벡터에는 촌락 상점별 실제 키트2개와 그 스택 할당에 따른 순차 시장UID/nextItemId 이동만 더해지며 나머지 세계/난수는 같다. 옛300 기대값을 한 번 보관했다. [전체 골든 차이](golden-v301-diff.json).

연료가 중간에 끊기면 조리한 것으로 위장하지 않고 원래 덜 익은 그릇·진행을 회수한다. 기존 주민의 생식 선택이 적용될 수 있어 미완성 음식의 병원체/재가 남는다. 이번 범위가 연료 상실 이후의 자동 재점화/재조리·모든 음식·장기 기근·전역 농업의 완성은 아니다. 실제 근처 조리창에는 다른 사람의 그릇과 익음/덜 익음만 보이고 정확한 진행/조작은 공개하지 않는다.

첫 실제 Native는 타이틀/구매/실제 가열과 첫 복원을 전체 상태로 통과한 뒤,600턴 후 그릇이 비어 있어야 한다는 시험의 가정에서 실패했다. 실제로 첫 그릇을 먹은 뒤에도500kcal 준비 문턱 아래라 같은 그릇으로 다음 끼니를 이미 준비하고 있었다. 첫 실패4PNG와 원본 전체 상태를 보존했다. 제품 행동을 고치지 않고 다음 준비의 수량/UID/식사 원장 경계를 전용 검사에 추가했으며, 실제 Native도 첫 섭취 직후까지의 원래 대기 입력으로 구분했다. 같은 유한 초기 장면은 직렬화한 템플릿으로 재사용해 매 검사마다 초기 접근 경로를 재연하던 비용만 줄였다. 전용31개가 원래5초 제한에서 통과했고, 무거운 검사 중복은 피한다.

수정된 두 번째 실제 Native는8PNG/4전체204복원/15전체쌍/실제52,700TU와 미완료30,300TU 재개/오류0을 통과했다. 첫 그릇 섭취는 실제 마지막125대기로 구분했고, 별도 다음 끼니 검사에서 같은 그릇 재사용을 확인했다. 다만 직접1512화면을 열어보니 기존 모닥불 UI가 타인 불에도 끄기 버튼과 정확한 연료 잔여를 표시했다. 코어의 기존 관리 권한 검사를 그대로 공개한 읽기전용 함수로 UI를 연결해 타인 불의 버튼/연료 수치를 숨겼다. 원래 core 권한 판정은 바꾸지 않았다. 이 수정 전8장은 이력으로 보존하고 최종 화면 근거에는 새 빌드 재검사를 쓴다. 자기 모닥불 조리도 기존 실제 귀리 Native로 다시 확인한다.

## 다시 검증하기

새 출력 폴더를 지정하고 다음 검사를 순서대로 실행한다. 전체 검사·월드 시뮬·브라우저를 동시에 돌리지 않는다.

```sh
pnpm exec vitest run tests/resident-cooking.test.ts --maxWorkers=2
pnpm build
pnpm exec tsx tests/e2e/resident-cooking.ts test-results/resident-cooking-new-run
pnpm exec tsx tests/e2e/oat-cultivation.ts test-results/player-oat-new-run
pnpm game:preview-check test-results/common-new-run
pnpm exec vitest run --maxWorkers=2
pnpm sim:batch 30 3 test-results/world-new-run --world
```

마지막 각인 경계 검토에서 월드와 주민 지역이 모두 없는 NPC의 설치에도 `undefined === undefined` 비교로 불필요한 주민 불 기억이 생길 수 있음을 확인했다. 실제 주민 지역이 있을 때만 기억하도록 조건을 명시하고 비주민 설치 검사를 추가했다. 진행 중인 월드는 수정 전 불변본의 별도 기록으로 보존하고 최종 수정본을 다시 통합 검증한다.

최종 비주민 조건 수정은 실제 설치 입력으로 구본/수정본을 비교했다. 구본의 지역 없는 불 기억만 사라졌고 나머지 전체 상태는 정확히 같았다. 수정 전후 5개 기준 시나리오의 전체 초기·최종·오류도 정확히 같았다. 월드30판은 수정 전 `v301-permissions`에서 577.385초에 완료한 별도 실측이며, 결과30행·평균·사인은 마지막 실측299와 같았다. 주민 지역이 필요한 기본 설치 AI와 밸런스는 이 조건 수정의 영향을 받지 않는다. 최종 수정본의 실제 화면·저장 복원·전체 회귀 검사는 별도로 실행한다.

전체333파일 6,105개 통과(920.743초, 작업자2). 실제28화면·각인204 전체복원10회·전체상태38쌍·실제키/마우스95,900TU 및 미완료30,300TU 재개·오류0. 월드30판/최대3일 577.385초(작업자4) 검증. 월드30개 전체 결과 행·평균·사인은 마지막 실측299와 같다. [최종 근거](release-v301-proof.json). 앞선 작업중 문장은 당시 이력이다. 공개사이트 배포와 별개다.
